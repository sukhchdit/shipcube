## 3. Why — notes for conformance reviews

1. **The claim was never a digest.** `head().sha256` is `x-amz-meta-sha256`, written by whoever can `PutObject` on the key. With a pre-seeded object whose metadata names the writer's digest, the old rule would have reported "written", stopped retrying and left the attacker's bytes in the sink until the hourly verifier's byte-exact comparison noticed. The new rule uses the one value the store computes itself (`ChecksumSHA256`, which the store verified on receipt: a wrong digest is a 400 `BadDigest` and nothing is stored) and, when that is absent, the bytes. Making the wrapper expose `isWritten` and nothing else turns the rule into a type rather than a convention: nobody can read the claim by accident later.
2. **`get()` failing with `INTEGRITY_MISMATCH` is a verdict, not an outage.** It means the object's own claim contradicts its own bytes, i.e. somebody else wrote it. The writer must not loop on it and must not downgrade it to "unavailable"; PR #30's `failure()` already keeps typed port errors out of that downgrade.
3. **`nosniff` cannot come from the adapter.** Pre-signed means the browser talks to the store. Writing the promise into an ADR that no code can keep is how SEC-P3-21 item 5 reached PR #30 half-built. Amendment 3 ranks the controls honestly and names the only two places a header can appear. The same-host caveat in Compose (cookies ignore ports) is stated rather than hidden; it is accepted for synthetic data and is why `allowInline` is closed outright.
4. **An allow-list beats a deny-list for inline types.** The reviews offered a deny-list of active types; a new active type (or a `+xml` vendor type) would pass it. There is no M1 caller, so the cheapest safe design is "no inline at all" with one reviewed way to add it.
5. **The `.gitmodules` hole is wider than the line the record cites, and it has a root cause.** Every `git diff`/`git status` call in `tools/quality` and `tools/ci` honours `ignore = all` (the owned-path check, the migration-immutability check and the porcelain gate included), so the flag goes on all of them with a repo test. The real fix is the tree invariant: `git ls-tree` plumbing cannot be filtered, and with no gitlink, symlink or stray executable in the tree the hole has nothing to hide. Both are scheduled; neither relies on the other.
6. **M2 had a second half.** Narrowing only the pending entries would have left gate rule 5 (every `gate`-profile suite `active` or deferred) failing at the tag for every suite whose task has not merged. The `--checkpoint` flag narrows both from one input, with `required_from` defaulting to `G3` so that forgetting to set it is the strict outcome. The G3 command carries no flag, so the flag cannot weaken G3; the checklist pins that.
7. **The verifier-side scan cannot false-positive on an honest run** because it reuses the belt's own shapes: anything the belt would have rewritten is, by construction, absent from a scrubbed run. A route text such as `/home/settings` (cosmetically rewritten by the belt, code review N2) is therefore also absent.
8. **PR24-SEC-10 is availability, and the fix is operational.** The build phases of a CIC commit before any event trigger runs; no guard can undo them. The record's recovery for one leftover (rename away) is probed; the two-leftover case needs the superuser. Writing the correction of the R2-n1 break-glass here matters: the fold-3 text said the end-of-command trigger "needs no suspension" and that is true only for the last squat.
9. **Rule 11 (c) refuses; it does not track.** After PR #11, files are applied statement by statement outside a transaction block, so a `BEGIN` is the only way to make a `RESET` undoable. Teaching the tracker `BEGIN … ROLLBACK`, `SAVEPOINT` and `ROLLBACK TO` is re-implementing a transaction manager over text. No migration needs them.
10. **No override switch for static storage credentials in staging/production.** Security's text allowed "unless a documented switch allows static keys". There is no current need (IAM task role at M5, staging blank), a switch is a standing weakening, and an ADR amendment is the right cost to pay if a non-IAM store ever appears. Reversible.
11. **`STORAGE_PUBLIC_ENDPOINT` is required whenever `STORAGE_ENDPOINT` is set, everywhere.** A missing public endpoint puts the in-network host (`rustfs:9000`) into a URL the browser cannot use and discloses an internal name; failing at start-up costs one line in `compose.env`.
12. **`.dockerignore` and the api image's contract file conflict if applied literally.** Security's suggested `docs` entry would exclude `docs/03-architecture/api/openapi.yaml`, which the api image must ship (D-TASK017-01 (7), TASK-014 line); the sheet now carries the single `!` exception and a matcher test that proves the file is not ignored while every other `docs/` path is.
13. **TASK-014 edits `packages/config` without the `pkg-config` lock** exactly as its existing lines (TLS helpers, exit-78 handling) already do; TASK-116 edits it the same way for its two keys. A lock on either would collide with batch 0.5's `rls` task or serialise nothing useful; the sheets say to coordinate.
