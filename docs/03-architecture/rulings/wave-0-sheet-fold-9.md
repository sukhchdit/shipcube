## 3. Why — notes for conformance reviews

1. **A plan is not a diff.** The old DoD line turned a planned file into a promise of a hosted run. TASK-288 planned to touch `prisma/tests/harness`, did not, and its PR body still said the job runs. The fix is two things together: the list is read from the classifier (so the card can never be ahead of what lane A does), and the line states a condition with both outcomes. Matching planned paths more exactly is a side benefit, not the control.
2. **The trigger list is about what the suites exercise.** `jest.config.ts`, the lock and process layer, the oracle helpers and the dependency tooling all run inside the job, so they belong on the list for the same reason `prisma/**` does. Paths that only gate (`tools/ci`, `tools/quality`, `.github`) stay off it: they have the workflow policy and the record check, and adding them would select nearly every Wave-0 PR. The list cannot catch a deliberate weakening of the suites through `jest.config.ts`, because the job runs the head's configuration; that stays with the record.
3. **PR59-SEC-01 needs an order inside TASK-287.** The finding is due before any other workflow PR merges, and the incremental lane is itself a workflow PR. Policy first is not a preference: the tested base's policy judges the PR, so a pin that arrives with the workflow change it pins does not bind that change.
4. **Honour-system due points became edges or locks where that was free.** TASK-049 ← TASK-028 costs nothing (batch 0.8 before 1.4) and makes D-SEC-PR56-01 condition 1 a generator fact. PR54-SEC-02 (b)(c) rides TASK-030, which TASK-073 already depends on. Where an edge was impossible (TASK-028 and TASK-029 share batch 0.8), the card carries a precondition line and says why.
5. **`listCountries` is not the first audited route.** D-SEC-PR56-01 named TASK-026 as the likely first; its only route is public with audit `none`, which the capture mounts without a tokeniser. The first route that needs one is TASK-049's. The mount refusal remains the backstop for route tasks that do not descend from TASK-049.
6. **The aggregated denial entry is written at the crossing.** The security record asks for an entry that closes the window with a count. Nothing runs at the end of a window, and a job would need the worker audit port, which lands two batches later. Writing the summary when the budget is crossed keeps the bound (N+1 audit transactions a minute per actor) and tells an auditor that suppression began; the count follows in the first entry of a later window and in a metric. Security-analyst confirms the shape before dispatch.
7. **`source_app` is verified where it can be.** The access token carries `app` and `sid`, so for any principal with a session neither value needs a client header. `admin` additionally requires operator scope, so a tenant token can never label an entry as coming from the admin console. Session-less traffic keeps the client-asserted `web`, and the viewer says which is which.
8. **TASK-060 owns the two orphaned capture items.** It owns operator scope and the 401/403 outcomes, it precedes the only M1 consumer (the audit viewer) by an existing edge, and it is a platform task. A module task must not add platform seams, and TASK-033 is a test task.
9. **PR56-SEC-13 is pinned, not skipped.** A security suite with a skipped case fails the manifest rule, and a comment would be forgotten. A test that asserts the current behaviour under an `OPEN` title fails the day the capture is fixed, which forces the flip in the same PR.
10. **PR54-SEC-02 (b)(c) rides an existing PR.** The change is a list of names in two files and a corpus. With the CI-minutes forecast over the allowance, a dedicated late task would spend a review cycle on it; TASK-030 moves raw statements anyway, holds the two locks without a batch conflict and is already upstream of TASK-073.
11. **One transport plus a ratchet, not a sweep.** The pooled-fetch flake returned in three suites because each fix was local. The transport helper exists; what was missing is a tripwire. A shrink-only allow-list gives one without making W0-FLAKE-3 hold every platform lock, which D-ORCH-118 shows would collide with whatever is in flight.
12. **The prerender timeout is not a setting.** React Router 8.5.1 exposes only `prerender.concurrency`. A wrapper around `react-router build` would also wrap the Docker and hosted builds and hide a real prerender regression there; the flake belongs to the loaded developer host, so the only place a retry is allowed is the lane B runner, and only on the named signature.
13. **Locks name shared files, not only folders.** PLAN.md §5 rule 1 defines locks as folders and assumes a task stays in its folder. The audit capture, the admission bulkhead, the idempotency slot and the lexer guard all meet in four files. Naming those files and making the generator refuse a card that plans to edit one without the lock is the smallest change that makes the overlap visible at dispatch instead of at merge. The check reads planned files only; a PR that discovers it needs a hot file stops and asks for the lock.
