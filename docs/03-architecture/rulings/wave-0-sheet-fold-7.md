## 3. Why — notes for conformance reviews

1. **Reserves, not partitions, for the anonymous classes.** Fixed shares (2/2/1 of 5) starve whichever class is idle; a per-class cap without a ceiling lets the anonymous world grow past one tenant's share and reopens the SPK-04 pool-exhaustion argument. The formula `inflight(k) < C − Σ_{j≠k} max(inflight(j), reserve(j))` is the R-15 "bulkhead reserve" pattern made exact: each class is guaranteed its reserve and nothing more is wasted. The ceiling equals the tenant cap on purpose — every sentence of ADR-0007 am. 10 item 3 about pool share stays true.
2. **`auth` is derived from the rate-limit class, not declared twice.** The descriptor already carries `rateLimit` (`auth`, `email-send`, `public`, `public-quote`, …) with a contract drift test; deriving the admission class from it means a new auth route cannot forget to declare it, and the route-metadata test proves the derivation for every mounted route.
3. **Bounds are "always", not "production".** A guard that applies only when `APP_ENV` says production is a guard nobody tests until G4. The half-pool rule and the statement-timeout rule hold in every environment; only `DB_POOL_MAX ≥ 4` is environment-conditional because a two-connection local pool is legitimate.
4. **`writeAll` over a guard.** The code review offered both; the design already requires several entries in one transaction in at least three places, so a guard would have been a latent 500 in the checkout path. Sorted lock order is the textbook deadlock-freedom argument and costs nothing in the one-stream case, which is every flow this run ships.
5. **The store CTE lands in TASK-029, not TASK-030.** Batch order is 0.8 then 0.9; a `record`/`flush` API whose flush still appended entries one by one would violate the budget between the two merges. TASK-030's job was always to move and prove (D-TASK025-04 accepted by the code review), and that is now written on its card.
6. **A new bootstrap file, not an edit, not a migration.** Rule 12 keeps audit DDL out of `prisma/migrations/**`; immutability keeps edits out of `10-audit.sql`; the file's own header already prescribes "a new `NN-audit-*.sql` with its own marker". One statement, so a partial run cannot leave the table unchecked; the owner exemption of the DDL guard is exactly for this file.
7. **The invitation is the pending state.** `user_id NOT NULL` already made the stories' "INVITED membership" impossible for an address without an account; the security finding only made the consequence visible. Option A removes two things at once (the pre-consent read and the invite-time account oracle) with zero schema change. `INVITED` stays in the CHECK as reserved because removing a value is a schema change for nothing, and a reserved value with a written rule ("a writer needs an ADR amendment") is safer than a silent re-introduction later.
8. **Due points became DAG edges.** "Due before TASK-052 merges" with no dependency is the honour system PR43-SEC-01 just criticised. TASK-052, TASK-059 and TASK-061 gained one dependency each; the generator verifies the batch order and the orchestrator's dispatch honours it.
9. **Late-task numbering changed to array order (gen.mjs, one line).** The former rule — late tasks numbered by (wave, batch) after the planned ones — made the position of a late task determine its ID, so the first late task placed before TASK-279's batch would have renumbered TASK-279..282 (observed in the first regeneration and reverted). Array order is append-only: the seven existing late tasks are listed in the order of their IDs, so nothing moved (column-level CSV diff: no `task`, `wave`, `batch`, `title`, `branch` change in TASK-001..282), and any future late task takes the next number wherever it is scheduled.
10. **The raw-SQL check lives with the manifest, not with the SQL lint.** `db-raw-sql` decides whether a statement is parameterised; `system-model-owner` already knows which module owns which SYSTEM table and already reads the manifests.
