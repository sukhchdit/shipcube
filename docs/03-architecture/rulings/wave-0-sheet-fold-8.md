## 3. Why — notes for conformance reviews

1. **`createRequire` was never dynamic.** The 2026-11-14 wording let a reviewer believe the shape was unreachable by lint and covered elsewhere; PR44-SEC-01 proved the opposite on `main` (five lint-clean loader forms, one of them building a second Prisma client). The amendment states the control as configuration (resolve, then refuse) and leaves exactly one review item, which is CODEOWNED. Writing "a fixture each" for a loader shape is not a control and is withdrawn as a reading rule.
2. **A lint claim is corrected, not the ruling.** D-ARCH-124's result (identifier completeness over a tagged template) holds because interpolations are bound values; what was wrong is the reason given for it. The fragment refusal lives in the TenantDb guard at run time, and that is where PR #54's twins put it.
3. **`devOptional` is production.** The lockfile flag marks a package that production code can load optionally; the Prisma CLI, engines and config are exactly what the RLS and migration suites exercise. A rule that treats them as dev would skip the hosted security run on the one bump most likely to change transaction behaviour. The D-TASK015-59 refinement is held until the fix lands because it would have exposed the gap.
4. **Proofs are PR-bound and base-bound.** A run of another PR into another base executes that base's workflow and tooling; accepting it as a proof lets a writer forge every step name. Binding to the same PR into `main` closes it, and the no-retarget rule keeps the binding honest until branch protection exists. The remaining gap — a proof older than `main`'s last tooling change — is procedural (P1) today and becomes mechanical in TASK-286 together with `TOOLS_REF`.
5. **The audit backstop sentence was false.** am. L item 6 relied on lane C and nightly audits that do not exist. Rather than weaken the inheritance model, the audit and signature steps become unconditional: they cost seconds, not a billed minute, and they are the only time-dependent gates in the lane.
6. **Seam retirement needs owners, not a note.** The matrix's synthetic credentials resolve ahead of the production authenticator; without a line on each authenticator task the seam would outlive the authenticator and the oracle would keep proving the stub.
