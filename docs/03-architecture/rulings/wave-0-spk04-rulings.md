## 3. Design notes the implementers should not re-derive

1. **Why the row lock is safe where the advisory lock was.** Both are released at COMMIT; both serialise exactly the writers of one stream (the row lock exactly, the advisory lock modulo `hashtext` collisions). Deadlock freedom is unchanged because the head lock is the last lock any transaction takes and nothing but the CTE and COMMIT follow it. `platform_app` holds `UPDATE` on `audit_stream_heads` (§4.4), which `FOR UPDATE` requires. No table may reference `audit_stream_heads` by FK (a `FOR UPDATE` lock would block referencing inserts).
2. **Why `lock_timeout` is set inside the lock statement.** A separate `SET LOCAL` costs a round trip outside the lock (acceptable but avoidable). A `MATERIALIZED` CTE is evaluated when the join first pulls from it, which happens before the `LockRows` node locks the head row; `set_config(…, true)` takes effect immediately for the session. TASK-030's held-row test is the proof; if it does not bound the wait, the `SET LOCAL` form is the fallback and the PR says so.
3. **Why two vault statements, not one.** `ON CONFLICT DO UPDATE … RETURNING token` would return existing tokens in one statement, but the vault's `BEFORE UPDATE` guard (`AUDIT_VAULT_IMMUTABLE`) raises on the no-op update. `DO NOTHING` returns nothing for existing rows, and the second statement needs a new snapshot to see a concurrent writer's winner — hence two statements, both before the lock.
4. **Why "round trips under the lock" and not a latency number.** Hold time ≈ round trips × RTT; RTT is 1.1–1.7 ms p50 on Docker Desktop and a fraction of that on native Linux. A statement count is host-independent and asserted by a query spy; the latency budget is then measured once, on a clean host (TASK-280).
5. **Why not sub-streams now.** They change `stream_id ≠ org_id`, the verifier, `audit_checkpoint_heads` and the viewer; and with 2 round trips under the lock the hot stream's utilisation at 60 writes/s is ≈ 60 × 2 × 1.5 ms ≈ 0.18 on this host (≈ 0.02 on Linux) — far from saturation. The trigger in am. 10 item 4 keeps the option open with evidence, not a guess.
