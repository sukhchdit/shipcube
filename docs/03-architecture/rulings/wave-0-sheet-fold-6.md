## 3. Why — notes for conformance reviews

1. **The contract is one rule in one ADR, repeated per task.** Five tasks across waves 1, 2, 6 and 8 implement the same slot interface. If each carried only its own wording, a reviewer of TASK-261 in wave 8 would have no normative text to compare with; ADR-0008 am. 6 item 2 is that text, and the sheet lines point at it. The PR #38 code review (R2.4) already ruled D-TASK020-41 sound; this fold does not re-decide it, it records it as architecture.
2. **`markCredentialsRead` is kept and "together with the decision" is the whole rule.** Forgetting it makes errors more private, never less (the mark only disables the generic any-credential arm, and the declared arm reads the descriptor). So the contract needs no ordering discipline, and the five tasks get a spy test instead of a code-review convention.
3. **The companion carve-out is not a weakening.** A `[session]` route that checks a quote token is checking possession of a quote, not identity: the caller is already authenticated, the token dies at claim, and the contract declares it as a header parameter there. Refusing it everywhere would have forced the token into the body or a slot that knows nothing about quotes; allowing it only on exactly `[session]` keeps the P3 probe closed (`[anonymous]`, `[anonymous, session]`, `[session, quote-token]`, `[refresh-cookie]`, `[signature]` all refuse it) and binds the exception to the contract through parity.
4. **Header names belong to the contract, so the list is pinned to `securitySchemes`.** The security analyst proposed a hard-coded list; a hard-coded list drifts when a provider is added (the carrier push scheme already exists in the contract before TASK-261). The parity test turns a new scheme into a lane A failure until the shared list names it, which is where the authenticator and the `defineRoute` rule both read it.
5. **Narrowing the value allowance is a correction, not a new policy.** The ADR said one file; the lint said one category. When the rule and its encoding disagree the encoding moves, and here it moves at zero code cost because nothing else imports the client as a value. The dynamic-import residual is named rather than hidden: CODEOWNERS already covers it, and a lint rule for template-literal `import()` of a specific specifier is not worth its false positives.
6. **In-flight tasks get merge checks, not scope.** TASK-014, TASK-015 (PR #40) and TASK-025 are running. Their new lines say "review requirement" and "satisfied as is if the head already does it", so a developer reading the sheet mid-task does not reopen finished work; the reviewer reads the same line as a checklist.
7. **A docs owner was missing and is now a task.** Three folds have routed developer-doc items to "the P7 docs pass" without a sheet task to carry them, and CLAUDE.md §2 is the orchestrator's file. TASK-282 follows the TASK-276..281 precedent (late task, numbered last, free slot in an existing batch) so that every later doc item has an owner and a drift guard. It is not a P7 task: it must merge before G3 so the writer verifies commands against the stack the gate judges.
8. **Coverage-gate activation lines go to the task that lands the source.** The `coverage gate:` names are inactive until a scope has measured files (D-TASK015-24/26), so the earliest correct moment to require them is the activation checkpoint after the first source merges, and the task that merges that source is the one whose PR body must quote the merged numbers. The ledger has no such task this run; the rule is recorded for qa-lead only.
