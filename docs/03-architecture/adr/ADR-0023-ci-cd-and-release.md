# ADR-0023: CI/CD on GitHub Actions, release artefacts (tag + GitHub Release + GHCR) and progressive delivery design

- **Status:** Accepted
- **Date:** 2026-11-12
- **Deciders:** principal-architect, platform-architect (devops-engineer implements in P5 Wave 0)
- **Related:** brief §10 (pipeline stages), §11; CLAUDE.md §3 (CI_PLATFORM, CANARY_STEPS, ROLLBACK_TRIGGERS), §5; REQ-PLAT-006/007, REQ-SEC-013; D-004, D-005, D-006; **D-ORCH-001, D-ORCH-002, D-ARCH-010 (amendment below)**; NFR-OPS-002/003/004, NFR-SEC-002, NFR-QUAL-*; platform.md §7; ADR-0024 amendment (where each test layer runs)

## Decision

1. **Workflows** in `.github/workflows/`:
   - `ci.yml` (pull requests and `main`): `setup` (checkout, Node from `.node-version`, `npm ci --ignore-scripts` with cache — *amended 2026-11-12, amendment F*) → parallel `lint` (eslint, stylelint, prettier check, commitlint, actionlint), `typecheck`, `unit` (Jest unit + coverage gate 85/75, 95 on pricing/audit/authz), `contract` (Redocly lint, OpenAPI drift, generated types freshness, `.env.example` parity, repository structure test) → `integration` (Jest integration/api projects with Testcontainers on the runner's Docker; RLS, audit, migrations up→down→up, RBAC matrix, audit generator) → `build` (workspaces build, size-limit) → `security` (Semgrep, Gitleaks, `npm audit --omit=dev --audit-level=high`, licence check against LICENSE_ALLOWLIST + 18-month age script) → `images` (buildx multi-stage for api/worker/web/admin, Trivy image + config scan, hadolint, CycloneDX SBOM via `npm sbom`/syft, push to GHCR only on `main`/tags) → `iac` (`terraform fmt -check`, `validate -backend=false` per module/overlay, Checkov) → `e2e` (compose up from built images, Playwright 3 engines × 2 viewports with axe, k6 smoke, Lighthouse CI on public routes, security header tests, ZAP baseline on release candidates). Target ≤ 20 min wall-clock via job parallelism and caches (NFR-OPS-003).
   - `nightly.yml`: k6 soak (100 rps × 60 min), Stryker mutation on `packages/pricing`, ZAP baseline, live-sandbox carrier contract tests and Stripe test-live **only when the secrets exist** (`CARRIER_LIVE_SANDBOX=1`, `STRIPE_TEST_LIVE=1`; otherwise reported as skipped), restore rehearsal (NFR-REC-003), dependency freshness report.
   - `release.yml` (on tag `v*`, incl. `v0.1.0-m0` pre-release per D-006): rebuild or promote images by digest, tag `ghcr.io/sukhchdit/shipcube-{api,worker,web,admin}:<semver>` + `sha-<gitsha>`, attach SBOMs (*amended 2026-11-12, SEC-P3-25 d / SEC-P3-33 item 8:* provenance attestations are **deferred to M5** — GitHub artifact attestations need Enterprise Cloud on a private repository, platform.md OI-10; the M5 choice is cosign keyless, cosign with a KMS key, or a public repository), generate changelog from Conventional Commits, create the GitHub Release (pre-release flag for `-m0`) with notes + SBOM + OpenAPI document (D-005).
   - `cd.yml`: `deploy-staging` and `deploy-production` jobs with environments and required reviewers **present but no-op** (log "no deploy target configured", D-002) until `DEPLOY_TARGET_STAGING`/`_PRODUCTION` variables and the OIDC role exist; when enabled: assume role via GitHub OIDC (no long-lived keys), `terraform plan` → Checkov/OPA on plan → `apply` (staging), ECS deploy via CodeDeploy with CANARY_STEPS and alarm-based automatic rollback (ROLLBACK_TRIGGERS), smoke + e2e against staging, production promotion by digest only.
2. **Policies**: pinned action SHAs; `permissions:` least privilege per job (`contents: read`, `packages: write` only for publish, `id-token: write` only for OIDC jobs); concurrency groups per ref; required checks on `main`: lint, typecheck, unit, contract, integration, build, security, images(scan), iac; merges only after code-reviewer APPROVED + security-analyst no Critical/High (D-004); no force pushes.
3. **Artefacts**: images (digest-pinned bases, non-root, `HEALTHCHECK`, labels `org.opencontainers.image.*`), SBOM per image, coverage report, Playwright traces, k6 summaries, Lighthouse reports, Terraform plan output (when enabled) — retained 30 days.
4. **Secrets in CI**: only `GITHUB_TOKEN` for GHCR; optional sandbox/Stripe test secrets as repository secrets consumed only by the nightly job; never echoed; Gitleaks on every PR diff and full history. *Superseded 2026-11-12 by amendment H: sandbox/Stripe secrets are environment secrets of `carrier-sandbox`, never repository secrets.*
5. **Progressive delivery design** (exercised at M5): CodeDeploy ECS blue/green canary 5 % → 25 % → 50 % → 100 % with 10-minute bakes; rollback alarms = ROLLBACK_TRIGGERS; database migrations run as a pre-deploy ECS task using the migrator role, expand-only (contract steps ship in a later release per CLAUDE.md §5), preceded by an automated snapshot + restore check job.

## Alternatives considered

- **Self-hosted runners / other CI.** GitHub Actions is fixed (CLAUDE.md §3).
- **Publishing to ECR now.** Needs an AWS account; GHCR is free with the repo (D-005); ECR mirror at M5.
- **Monolithic single job.** Exceeds the 20-minute budget; parallel jobs with caches are required.

## Consequences

- Positive: every guardrail is a pipeline stage; releases are reproducible (digests, SBOM; signed provenance attestations from M5, OI-10); deploy stages are ready to switch on.
- Negative: Docker-in-runner integration tests and Playwright across 3 engines are the long poles — mitigated by job parallelism and selective e2e on PRs (full matrix on `main`/nightly).

## Reversibility

High.

## Amendment (2026-11-12, D-ORCH-001): hosted PR fast lane, local heavy lane, dispatch-only full lane

**Supersedes** the self-hosted `heavy` runner default of D-ARCH-009 and platform.md PD-10 (options C + D). The human decided (Q-007 → D-ORCH-001): no self-hosted runner, no paid minutes, the repository stays private, and the heavy suites run locally with committed evidence. §1 (`ci.yml`, `nightly.yml`) is redefined below; §2–§5 stand. Local commands in this amendment run with the per-command PATH prefix from CLAUDE.md §2 (`export PATH="$APPDATA/fnm/aliases/default:$PATH";`, D-ORCH-002); containers and hosted jobs use `node:24` / `.node-version`.

### A. Lane model

| Lane | Trigger | Runs on | Content | Budget |
|---|---|---|---|---|
| **A — PR fast lane** | `pull_request` (`opened`, `synchronize`, `reopened`, `ready_for_review`) on **non-draft** PRs; concurrency group per PR with `cancel-in-progress: true` | GitHub-hosted `ubuntu-latest` (2 vCPU / 8 GB on a private repository) | One job `fast-lane` (single checkout, one `npm ci --ignore-scripts` with the `node_modules` cache — *amended 2026-11-12, amendment F*): ESLint (incl. boundaries) + Stylelint, Prettier check, commitlint, actionlint, hadolint, `tsc -b` type-check (incremental, `.tsbuildinfo` cached), Jest **unit** + coverage gate, `npm run build` (all workspaces) + `size-limit`, Gitleaks on the PR diff (container), `npm audit --omit=dev --audit-level=high` + `osv-scanner` (container), Semgrep (container), licence + 18-month age check, `.env.example` parity, i18n key check, repository-structure test, OpenAPI lint + route drift + generated-types freshness, migration linter, `quality:check-evidence` (section C). `iac` steps (`terraform fmt -check`, `validate -backend=false`, Checkov, Trivy config) run **only when `infra/**` changed**. `ci-gate` aggregates and is the one required status check. | ≈ 8 job-min typical (incremental), ≤ 15 when a full-trigger path changed; wall-clock ≤ 15 min (NFR-OPS-003 ≤ 20) |
| **B — local heavy lane** | On demand by `test-runner` (dispatched by senior-developer or qa-lead) before a PR is marked ready, at every wave end and before each gate: `npm run quality:heavy -- --profile <pr\|wave\|gate>` | Developer host (Windows 11, Node 24 via fnm, Docker Desktop) | Integration (Jest + Testcontainers: PostgreSQL 18, Valkey, RustFS), API + generated suites (RBAC matrix, audit, RLS cross-tenant, abuse, saga fault matrix), compose-up timing (NFR-OPS-001), Playwright e2e (Chromium for `pr`; Chromium + Firefox + WebKit × mobile/desktop for `wave`/`gate`) with axe and CSP listeners, header tests, Lighthouse CI on pre-rendered routes, k6 smoke (`pr`) / ramp-steady-spike + scale-test (`wave`) / soak (`gate`), ZAP baseline (`wave`/`gate`), Trivy image + config scan (`wave`/`gate`, and whenever a Dockerfile or the lockfile changed), Stryker on `packages/pricing`, restore rehearsal and `valkey-compat` (`gate`). Writes evidence under `docs/05-quality/` (section B). | $0. Wall-clock: `pr` ≈ 15–25 min, `wave` ≈ 60 min, `gate` ≈ 2–3 h |
| **C — hosted full lane** | `workflow_dispatch` only (inputs `ref`, default `main`; `profile` = `wave-end` \| `release-candidate`), dispatched by the orchestrator or devops-engineer **at every wave end, before G3, before G4** and for each release candidate (the `release.yml` guard requires a green lane C run on the tagged SHA) | GitHub-hosted; heavy jobs use `runs-on: ${{ fromJSON(vars.HEAVY_RUNNER_LABELS \|\| '["ubuntu-latest"]') }}` | Everything in lane A (non-incremental, whole-repository coverage thresholds) **plus** `integration` (Testcontainers), `images` (buildx ×5, size budget, Trivy, layer-secret scan, Syft SBOM, push `sha-<sha>` to GHCR), `e2e-stack` sharded per browser (3 jobs: compose up from the built images, smoke, Playwright + axe, Lighthouse, k6 smoke, log-schema check), `iac`. | ≈ 85 job-min per run; wall-clock ≈ 20–25 min with sharding; ≤ 8 runs/month |
| **`push` to `main`** | `push`, path-filtered to code (`apps/**`, `packages/**`, `prisma/**`, `infra/**`, `compose*.yaml`, `**/Dockerfile*`, `package*.json`, `.github/**`) | GitHub-hosted | Lane A, incremental against the push's `before` SHA (+ `iac` for `infra/**`). **Enabled by repository variable `CI_MAIN_FAST_LANE`**, default `false` while the monthly estimate exceeds 80 % of the allowance (section D); the orchestrator sets it to `true` when headroom exists. | ≈ 4–5 job-min per merge when enabled |

Reading of D-ORCH-001 "push to main, path-filtered": on `main` the hosted workflow re-runs the **fast lane** for code merges (toggle above). The heavy jobs run on hosted runners only through `workflow_dispatch`, because merge-triggered full runs (≈ 85 min × ≈ 100 merges) would exceed the free allowance on their own.

`nightly.yml` keeps its job definitions (they are the self-hosted alternative and the lane C `release-candidate` extras) but has **no `schedule`**; it is `workflow_dispatch`-only. Its scheduled content is lane B's `wave`/`gate` profiles, run locally.

**Incremental mode** (lane A on PRs and on `main`): `jest --changedSince=<base>` for the `unit` project, ESLint `--cache` with a restored cache, incremental `tsc -b`. **Full-trigger paths** force a non-incremental run: `package-lock.json`, `jest.config.*`, `tsconfig*.json`, ~~`.swcrc`~~ *(withdrawn 2026-11-13, PR #17 code review R2-n2 / PR17-SEC-01, D-TASK007-04: no `.swcrc` exists — the `@swc/jest` options are inline in `jest.config.ts` with `swcrc: false`, and any `.swcrc` is a workflow-policy finding)*, `eslint.config.*`, `packages/shared/**`, `packages/config/**`, `docs/03-architecture/api/openapi.yaml`, `.github/**`. Coverage on PRs is a **diff gate**: changed and new source files must reach 85 % line / 75 % branch (95/95 under `packages/pricing`, `packages/audit`, `packages/authz`); the whole-repository thresholds are enforced by lane C and by lane B `wave`/`gate` profiles, whose `coverage-summary.json` is part of the evidence. SPK-07 (risks.md) validates the incremental mode in Wave 0; until it passes, lane A runs non-incrementally (≈ 14 min).

**Self-hosted runner — documented alternative, not the default.** Setting the repository variable `HEAVY_RUNNER_LABELS='["self-hosted","heavy"]'` moves lane C's heavy jobs and `nightly.yml` to a self-hosted runner with no other workflow change (the reversibility D-ORCH-001 names). Prerequisites if ever chosen: ephemeral runner, private repository only, no `pull_request_target`, Docker Desktop/WSL2 (platform.md §7.8 option C).

### B. Evidence layout for the local heavy lane (`docs/05-quality/`)

The directories `reviews/`, `tests/`, `security/` and `performance/` already exist. The heavy-lane script writes machine-generated files only; no agent hand-edits them.

```
docs/05-quality/

  tests/
    schema/heavy-run.schema.json   JSON Schema for summary.json   (WITHDRAWN 2026-11-13, amendment K item 2: the schema lives at
                                   tools/quality/summary.schema.json, code-owned next to the checker — D-ARCH-082)
    runs/<stamp>_<sha7>/           one directory per run, e.g. runs/20261120T1432Z_a1b2c3d/

      coverage-summary.json        merged Jest coverage summary (never the raw lcov)

    LATEST.md                      generated pointer: latest run per branch and per profile
  security/
    runs/<stamp>_<sha7>/           zap-baseline.json, trivy-<image>.json, trivy-config.json, gitleaks-full.json (when run),
                                   osv.json, npm-audit.json, semgrep.json (optional locally), summary.json
  performance/
    runs/<stamp>_<sha7>/           k6-<profile>.summary.json, host-spec.json, lighthouse/<route>-<locale>.json
                                   (LHCI assertion results), stryker-summary.json (gate), summary.json
  reviews/                         code-reviewer and security-analyst verdicts (unchanged owners)
```

Naming: `<stamp>` = UTC `YYYYMMDDTHHMMZ`; `<sha7>` = first 7 hex digits of the commit the suites ran against; `verdict` ∈ `PASS | FAIL | INVALID`. Content rules: JUnit XML and JSON summaries only; **no HTML reports, traces, videos, screenshots, raw lcov or image tarballs** (failure traces stay in the git-ignored `tests/e2e/output/`). A repository test caps a run directory at 5 MB and rejects file names outside the allow-list. Retention: run directories for the current and previous wave plus every gate run are kept; `npm run quality:prune` removes older ones in a dedicated commit (history keeps them).

**Integrity (risks.md R-ARCH-16).** `summary.json` is written only when `git status --porcelain` is empty for tracked code paths (`git_dirty: false`; a dirty tree yields `verdict: INVALID`, which lane A rejects); it records the SHA, timestamp, host spec and the SHA-256 of every attached report. Lane A's `quality:check-evidence` validates the schema, that `git_sha` is an ancestor of the PR head, that every attachment hash matches, and that the diff between `git_sha` and the PR head touches only `docs/**` (otherwise the evidence is stale). Evidence is committed as `test(evidence): heavy lane <profile> <sha7> <verdict>` by senior-developer or devops-engineer after test-runner's run (test-runner does not modify the repository). Lane C re-runs the integration and e2e subsets on Linux at wave ends, which cross-checks the local results.

### C. What "passing CI" means for the merge DoD (CLAUDE.md §2, §8; D-004)

A PR merges to `main` only when **all** of the following hold:

1. **Lane A green** on the PR's current head (`ci-gate`; path-filter skips count as success).
2. **Lane B evidence present with `verdict: PASS`** for the change, selected by changed paths (the same table lives in `docs/05-quality/README.md` and is what `quality:check-evidence` enforces):

   | Changed paths | Required local suites (profile `pr` minimum) |
   |---|---|
   | `apps/api/**`, `apps/worker/**`, `packages/**` (except `packages/ui`), `prisma/**` | integration + api (incl. generated RBAC / audit / RLS / abuse suites) |
   | `prisma/migrations/**` | + migrations up → down → up and the migration linter; a data-changing migration also needs the restore-rehearsal report (CLAUDE.md §5) |
   | `apps/web/**`, `apps/admin/**`, `packages/ui/**` | e2e `@critical` on Chromium (mobile + desktop) with axe and CSP listeners; Lighthouse on pre-rendered routes when public routes of `apps/web` changed |
   | `**/Dockerfile*`, `compose*.yaml`, `package-lock.json` | compose-up timing + Trivy image and config scan |
   | `packages/pricing/**`, `packages/audit/**`, `packages/authz/**`, or a task tagged `perf` | + k6 smoke with the NFR-PERF thresholds |
   | `docs/**` only, `.github/**` only | none (lane A suffices; actionlint is in lane A) |

   The evidence references the PR head or an ancestor whose diff to the head is docs-only. Stories whose Gherkin needs Firefox or WebKit are accepted at wave end on the `wave` profile, not per PR.
3. code-reviewer APPROVED and security-analyst no Critical/High (D-004), and the CLAUDE.md §8 DoD items.
4. **Wave end:** a lane C `wave-end` run green on `main` after the wave's last merge, plus a lane B `wave` profile run on the same SHA. **G3 / G4:** a lane C `release-candidate` run green on the gate SHA and lane B `gate` evidence for the same SHA. `release.yml` step 1 now checks "a lane C run concluded `success` for the tagged SHA" instead of "`ci.yml` for that SHA concluded `success`".

**Degraded mode** (allowance exhausted before the monthly reset; GitHub blocks hosted runs without a payment method): test-runner executes lane A locally (`npm run quality:fastlane`, identical steps) and its `fastlane.json` is committed as evidence; the orchestrator logs each degraded merge in DECISIONS.md and dispatches lane C for them after the reset. Degraded mode never waives the code-reviewer or security-analyst verdicts.

### D. Monthly minutes against the free allowance (≈ 2,000 Linux 2-core minutes = $12 included compute; platform.md Appendix A)

| Hosted workload | Job-min per run | Runs per month (P5 estimate: 100 PRs, 100 merges, 5 wave ends, 2 gates) | Minutes |
|---|---|---|---|
| Lane A on PRs (incremental, single job; the local pre-flight makes most PRs pass first time) | ≈ 8 typical / 14 full-trigger → blended ≈ 9 | 100 × 1.3 | ≈ 1,170 |
| Lane A `iac` steps (infra PRs) | 3 | 10 | 30 |
| Lane C `wave-end` | ≈ 85 | 5 | ≈ 425 |
| Lane C `release-candidate` (pre-G3, pre-G4) | ≈ 85 | 2 | ≈ 170 |
| `release.yml` (`v0.1.0-m0`, `v0.1.0`: promote, rescan, SBOM, pull from GHCR + compose smoke) | ≈ 15 | 2 | 30 |
| `cd.yml` no-op notice | 0.2 | 2 | 1 |
| **Subtotal, default configuration** | | | **≈ 1,830 (≈ 92 %)** |
| Optional `push`-to-`main` fast lane (`CI_MAIN_FAST_LANE=true`) | ≈ 4.5 | 85 code merges | + ≈ 380 → ≈ 2,210 (over; hence off by default) |

**Guards.** The orchestrator checks usage weekly (GitHub → Settings → Billing → Usage; devops-engineer confirms the `gh api` usage endpoint in Wave 0 and adds `npm run ci:minutes` that prints it). At **≥ 70 %** before the 21st of the month: `CI_MAIN_FAST_LANE=false` (if on) and no further `wave-end` dispatches that month (lane B `wave` profile only). At **≥ 90 %**: lane C for gates only. At **100 %**: degraded mode (section C). Artifacts: 1-day retention, summaries only (500 MB storage pool). Caches (`node_modules`, `.tsbuildinfo`, ESLint) ≤ 1 GB of the 10 GB.

Assumptions (medium confidence; measured in P5 and re-estimated at the first wave end): 100 PRs/month; 1.3 lane-A runs per PR; 8 min per incremental run; 85 min per full run on 2 vCPU. If measurements exceed the estimate, the levers in order are: fewer `wave-end` dispatches (lane B covers the wave), making the repository public (option A), a self-hosted runner (option C, label switch), paid minutes (option B, needs a budget change).

### E. Consequences of the amendment

- Positive: $0, private repository, objective DoD (evidence files with SHA and hashes), Linux cross-check at wave ends.
- Negative: the heavy suites depend on one machine's availability; results are produced on Windows + Docker Desktop while production is Linux (R-ARCH-17; mitigated by lane C and `.gitattributes` `* text=auto eol=lf`); PR coverage is a diff gate until the next lane B/C run; evidence commits add `test(evidence)` noise to the log.
- **NFR-OPS-003:** the ≤ 20-minute wall-clock target applies to lane A (≈ 8–15 min) and, through per-browser sharding, to lane C (≈ 20–25 min, measured and reported). Every brief §10 stage exists in the workflows; some execute on dispatch only. The stage-presence test is unchanged.
- **NFR-PERF-001/007 reference host:** k6 gates run on the developer host (spec recorded in every `k6-*.summary.json`), the "developer machine ≥ 8 cores / 16 GB" branch of NFR.md's reference-host clause; the hosted 2-vCPU k6 smoke in lane C is reported, not gated. performance-engineer re-baselines A-029 in P4.
- Wave 0 tasks implied: `quality:heavy`, `quality:fastlane`, `quality:check-evidence`, `quality:prune`, `ci:minutes` scripts (Node/TypeScript), `docs/05-quality/README.md` and the JSON Schema; `ci.yml` with the lane conditions; `nightly.yml` without `schedule`; SPK-07.

## Amendments after the P3 security review (2026-11-12, `docs/05-quality/security/P3-architecture-security-review.md` SEC-P3-04, SEC-P3-07, SEC-P3-08 item 3; threat-model T-102, T-103, R-21; D-ARCH-020, D-ARCH-021, D-ARCH-022)

### F. Supply chain: no install scripts, release cooldown, lockfile provenance (SEC-P3-04, HIGH; amends §1 `ci.yml` "`npm ci`", §2 policies, §4 and amendment A; platform.md §3.2, §3.3, §7.1)

1. **`npm ci --ignore-scripts` everywhere** — Dockerfile stages `deps`, `prod-deps`, `build`; every workflow step; `quality:heavy`, `quality:fastlane`; the developer setup docs. A root **`.npmrc`** is committed with `ignore-scripts=true`, `engine-strict=true`, `save-exact=true`, `fund=false`, `update-notifier=false` (plus `min-release-age=7` as defence in depth once SPK-01 confirms the bundled npm supports it) and copied into the image stages with the manifests (*the full final text, including the `@platform` scope pin, is amendment J item 1, 2026-11-12, PR1-SEC-01*). Install-time work becomes the explicit allow-listed step **`npm run deps:rebuild`** = `npm rebuild bcrypt --ignore-scripts=false` (skipped when the pinned bcrypt loads its N-API prebuild without a build step; SPK-01 confirms), the `prisma-engines` pin-and-verify step (*added 2026-11-12, PR1-SEC-02, amendment J item 2*), `npx prisma generate` (before the build), and, for local e2e and lane C only, `npx playwright install --with-deps <browser>` (Chromium for the `pr` profile; all three engines for `wave`/`gate` and the lane C shards) (*both `npx` invocations superseded 2026-11-12 by `npm exec --no -- …`, amendment I item 3; SEC-P3-31*). Nothing else executes package lifecycle scripts; a repository test rejects lifecycle-style (`pre*`/`post*`) npm scripts in any workspace, because `ignore-scripts` would skip them silently. Lane A step `check-install-flags` (`tools/ci/check-install-flags.mjs`) fails on any `npm ci`/`npm install` in `.github/workflows/**`, `**/Dockerfile*`, `compose*.yaml` or `package.json` scripts that lacks `--ignore-scripts`, and on an `.npmrc` without `ignore-scripts=true`.
2. **Release cooldown.** The package-age script (§1 "licence + 18-month age check") gains `DEP_MIN_AGE_DAYS=7`: any direct or transitive version whose registry `time[version]` is fewer than 7 days before the lockfile commit timestamp fails lane A (lockfile diff on PRs; whole lockfile in lane C). A security-fix override is an entry in `tools/ci/dependency-overrides.json` (`pkg@version`, DECISIONS.md ID, expiry ≤ 30 days). Dependabot is configured with `cooldown: { default-days: 7 }` for `npm`, `github-actions`, `docker` and `terraform`.
3. **Lockfile integrity.** `tools/ci/check-lockfile.mjs` (lane A) requires every `packages[*].resolved` to start with `https://registry.npmjs.org/`, every non-link entry to carry `integrity: sha512-…`, and no `git+`/`http:` sources; `npm audit signatures` runs in lane A (registry signatures and provenance attestations).
4. **Image job isolation.** `images` is the only `ci.yml` job holding `packages: write` (the `release.yml` promote job also re-tags by digest and runs no npm at all); it `needs: build-and-scan`; none of its steps run package scripts (installs happen inside BuildKit with the flag). `check-workflow-policy` (amendment H) enforces both. §4 "Secrets in CI" is replaced by amendment H.
5. Verification: SEC-TC-32 (extended), SEC-TC-45 — a fixture package with a marker-writing `postinstall` leaves no marker after the CI, Dockerfile and `quality:heavy` installs, while `deps:rebuild` still yields a working `bcrypt`, Prisma client and Playwright. Enforced from the **first `npm ci` in Wave 0** (devops-engineer).

### G. Evidence integrity hardening and the hosted `security-integration` subset (SEC-P3-07, MEDIUM; amends sections B and C; risks.md R-ARCH-16)

1. **Verdict is recomputed.** `quality:check-evidence` derives the verdict from the attached JUnit/JSON reports (`failures + errors = 0` and the manifest below satisfied); the declared `verdict` field is informational and any mismatch fails.
2. **Required-suite manifest** `tools/quality/required-suites.json` (code-owned; qa-lead maintains the content): per profile (`pr|wave|gate`) and per changed-path rule of section C, the suites that must be present with `tests ≥ min_tests`; suites marked `security: true` must have `skipped = 0`: `rls-cross-tenant`, `rbac-matrix`, `audit-generator`, `audit-immutability`, `abuse`, `ssrf`, `csrf-cookie`, `idempotency`, `catalog-c1-c14` (*corrected 2026-11-12, SEC-P3-33 item 7: C13/C14 were added by SEC-P3-03*). JUnit counts must equal `summary.json`. The §9 security test cases of the review are tagged `@security` and listed here.
3. **Clean tree and environment.** The clean-tree check uses `git status --porcelain --untracked-files=all` over `apps/**`, `packages/**`, `prisma/**`, `tools/**`, `tests/**`, `*.config.*`, `.env*` (except `.env.example`), `compose*.yaml`, `package*.json`, `.npmrc`; any entry → `INVALID`. `summary.json` additionally records `lockfile_sha256`, `testcontainers_images[{image, digest}]` and `env_overrides[]` (the **names** of any `SKIP_*`/`TEST_*` variables set); any `SKIP_*` → `INVALID`.

### J. PR1-SEC rulings

1. **`@platform` is a third-party npm scope; the `.npmrc` pins it to an unresolvable registry (PR1-SEC-01, MEDIUM; D-ARCH-040; amends F item 1 and I item 1).** The public scope `@platform` on npmjs.com belongs to an unrelated organisation (131 packages on 2026-11-12; none of our 16 names is published). Every workspace package is `"private": true` and only ever linked (`link: true` in the lockfile), but any install that resolved a workspace name from a registry — a Docker stage copying only `apps/<app>/package.json`, an install outside the workspace graph (the F-SEC-1 mechanism), a lockfile with a broken link — would fetch that third party's code and run it inside the API or worker; `ignore-scripts` does not help because the payload is the module itself. The committed `.npmrc` is therefore, **in full** (replaces the I item 1 list): `ignore-scripts=true`, `engine-strict=true`, `save-exact=true`, `fund=false`, `audit=false`, `update-notifier=false`, `min-release-age=7`, `@platform:registry=https://registry.invalid/`. `.invalid` is reserved by RFC 6761 and never resolves, so a registry lookup of `@platform/*` fails closed with `ENOTFOUND` (security-analyst's scratch verification: `npm ci` 1,505 packages exit 0, `npm ls --all` exit 0, `npm audit` counts unchanged, out-of-graph install → `ENOTFOUND registry.invalid`). Guards: (a) `check-install-flags` fails if the root `.npmrc` or any `tools/isolated/*/.npmrc` copy lacks the exact line; (b) `check-lockfile` (F item 3) gains the rule: every lockfile key under `node_modules/@platform/` is `link: true` with no `resolved`/`integrity`, every `packages[*]` entry whose `name` is `@platform/*` is a workspace folder entry (`apps/*`, `packages/*`, `prisma`, `tests/*`, `tools`), and no `@platform/*` entry carries a `resolved` URL; (c) image installs run from the repository root with the root `package.json`, `package-lock.json` and `.npmrc` (`npm ci … --workspace=apps/<app>`, ADR-0022 am. 11/14) — `check-install-flags` fails any Dockerfile `npm ci`/`npm install` whose stage has not `COPY`-ed `package-lock.json` and `.npmrc`. Renaming the scope is not a control (we own no scope on npm and registering one is an external action outside the guardrails); the pin is. Verification: SEC-TC-45 gains `.npmrc pins the @platform scope to an unresolvable registry` and `lockfile workspace entries are links only`, plus the review's negative fixture (a temporary project depending on `@platform/shared@0.0.0`, installed with the committed `.npmrc`, fails with `ENOTFOUND registry.invalid`). The `.npmrc` line and the SEC-TC-45 assertion land in PR #1 (TASK-001); the lane A rules in TASK-007, before TASK-014 starts.

2. **The Prisma schema engine is pinned by an in-repo manifest and fetched only by `deps:rebuild`; Prisma's own downloader never runs (PR1-SEC-02, MEDIUM; D-ARCH-041; corrects I item 3 and extends the F item 1 allow-list).** Correction of fact: under `ignore-scripts` the `@prisma/engines` `postinstall` does not run, but the Prisma CLI compensates at run time — `ensureNeededBinariesExist()` downloads the native `schema-engine` (≈ 20 MB) from `binaries.prisma.sh` (or `PRISMA_ENGINES_MIRROR`) before `version`, `init`, `migrate`, `db`, `generate`, `validate`, `format` and `telemetry` whenever it is absent from `node_modules/@prisma/engines/` and from the per-user cache. Its only integrity check is a SHA-256 served by the **same origin**, skippable with `PRISMA_ENGINES_CHECKSUM_IGNORE_MISSING`; the lockfile, the cooldown, `npm audit signatures` and `check-lockfile` cover none of those bytes. SPK-01's "`prisma generate` works with no install script" held only because the host cache (created 2026-10-19 by another project) already held the engine; a clean runner or BuildKit stage downloads it. The engine executes DDL as the migrator role in `migrate`/`db` commands, so its **content** must be pinned like a lockfile entry (the version is already pinned indirectly through `@prisma/engines-version`):
   - (a) **Manifest** `tools/deps/prisma-engines.json` = `{ "enginesVersion": "d1b3f377ca835d73fd50954a5e22128b9ebdd6b8", "source": "https://binaries.prisma.sh/all_commits/", "schemaEngine": { "<binaryTarget>": { "sha256": "<hex of the gunzipped binary>" } } }` for exactly the targets the repository runs on: `debian-openssl-3.0.x` (the `node:24-*-slim` image stages and `ubuntu-latest` runners) and `windows` (developer host). Further targets (for example `darwin-arm64`) are added by a reviewed manifest change; an unknown target fails closed. `enginesVersion` must equal the `prisma.enginesVersion` of the installed `@prisma/engines-version` (today `8.1.0-1.d1b3f377…`, via `prisma` 7.10.1 → `@prisma/engines` 7.10.1); a Prisma bump that leaves the manifest unchanged fails (c).
   - (b) **Recording procedure — trust on first use with two independent fetches.** `node tools/deps/prisma-engines.mjs --record` fetches `schema-engine.gz` and `schema-engine.gz.sha256` from the fixed origin, checks the transport hash, gunzips and prints the binary's SHA-256. The manifest is accepted only when two independent environments (the developer host, and a clean `node:24-*-slim` container with an empty cache or a hosted runner) produce byte-identical hashes, and the PR that changes the manifest requires security-analyst review (CODEOWNERS on `tools/deps/prisma-engines.json`) with `enginesVersion` and every hash changed together.
   - (c) **Step `prisma-engines`** in `deps:rebuild`, ahead of `prisma generate`, in this order: **refuse to start** if the inherited environment sets any variable that redirects Prisma's engine source, version, checksum handling or binary path — at least `PRISMA_ENGINES_MIRROR`, `PRISMA_ENGINES_CHECKSUM_IGNORE_MISSING`, `PRISMA_SCHEMA_ENGINE_BINARY`, `PRISMA_QUERY_ENGINE_LIBRARY`, `PRISMA_QUERY_ENGINE_BINARY`, `PRISMA_FMT_BINARY`, `BINARY_DOWNLOAD_VERSION`, `PRISMA_CLI_BINARY_TARGETS` (TASK-003 completes the list from `@prisma/fetch-engine` at the locked version); check (a)'s version equality; resolve the binary target with `@prisma/get-platform` and require it to be in the manifest; if `node_modules/@prisma/engines/schema-engine-<target>[.exe]` exists and its SHA-256 equals the manifest, use it (**offline/cached mode**, no network); otherwise fetch from the origin constant (HTTPS, 60 s timeout, 3 retries with backoff and jitter, redirects only within the origin), verify the `.gz` against the upstream `.gz.sha256` (transport check), gunzip, verify the binary against the manifest (**the trust anchor**), write atomically with mode `0755`. Any mismatch deletes partial files, prints expected and actual hashes and exits 1 — **no `schema-engine*` is left behind**. The per-user Prisma cache (`%APPDATA%\Prisma`, `~/.cache/prisma`) is never read, written or trusted. The header of `tools/deps/rebuild.mjs` names this single network origin as the only one the script may contact.
   - (d) **Prisma children run with the verified path.** `deps:rebuild` exports `PRISMA_SCHEMA_ENGINE_BINARY=<absolute path of the verified file>` and `CHECKPOINT_DISABLE=1` to every Prisma process it spawns: an existing env-override path makes `ensureNeededBinariesExist()` skip both the download and the cache copy (which could otherwise overwrite a verified file from a poisoned cache), so Prisma's downloader is never reached. TASK-003 confirms this short-circuit against the `@prisma/fetch-engine` source at the locked version; if it does not hold, the step must also re-verify the file after every Prisma child. Every other Prisma CLI invocation in the repository (`db:migrate`, `db:migrate:deploy`, `db:reset`, the migration linter's `prisma validate`, TASK-003's harness, the `migrate` image entrypoint) goes through the same wrapper `node tools/deps/prisma-cli.mjs <args>` (steps (c)–(d), then `npm exec --no -- prisma <args>`); a lane A rule `check-no-raw-prisma` (inside `check-install-flags`) rejects a bare `prisma` in `package.json` scripts, workflows, Dockerfiles and compose files. `db:seed`/`db:seed:demo` (seed CLI, no engine) are unaffected.
   - (e) **CI and images.** Hosted lanes may cache `node_modules/@prisma/engines/schema-engine-*` keyed by `enginesVersion` + runner OS; the restore is still verified by (c), so a poisoned cache fails closed. `check-workflow-policy` (amendment H) rejects the variables of (c) and `npm_config_ignore_scripts=false` in any workflow. The `migrate` image fetches and verifies the engine in its **build** stage (via `deps:rebuild`), copies the verified file into the runtime stage, sets `ENV PRISMA_SCHEMA_ENGINE_BINARY=/app/node_modules/@prisma/engines/schema-engine-debian-openssl-3.0.x CHECKPOINT_DISABLE=1`, and its entrypoint runs the wrapper in `--verify-only` mode (hash compare, no network) before `migrate deploy`; `api`/`worker` contain no `node_modules/@prisma/engines` directory and no `schema-engine*` file (ADR-0022 am. 14). The origin is a constant in the tool and in the manifest's `source` field; the tool refuses a manifest whose `source` differs, and changing the origin requires an amendment of this item — never an environment variable or configuration key.
   - **Verification (SEC-TC-64 extended):** (i) one manifest hash altered → `deps:rebuild` exits 1 and leaves no `schema-engine*`; (ii) `PRISMA_ENGINES_MIRROR` set → refused before any network call; (iii) empty engine directory and unreachable origin → fails closed; (iv) a poisoned per-user cache entry (wrong binary plus a self-consistent `.sha256`) is ignored — the hash of the file in `node_modules/@prisma/engines` after `prisma generate` equals the manifest; (v) manifest `enginesVersion` ≠ installed `@prisma/engines-version` → exit 1; (vi) image tests: `docker run --network none <migrate> prisma --version` exits 0, and `api`/`worker` hold no engine. TASK-003's acceptance "`deps:rebuild` regenerates the Prisma client with scripts disabled" runs with an empty engine directory and no `PRISMA_*` variables. **Owners:** TASK-003 (manifest, step, wrapper, (i)–(v)), TASK-007 (`check-workflow-policy`, `check-no-raw-prisma`, cache key, workflow `env`), TASK-014 ((e) image rules, (vi)); security-analyst reviews the manifest and confirms the design (risks.md R-ARCH-23).

1. **Lane A is scoped by the push, with verified proof inheritance (D-ARCH-126; amends amendment A lane A row).** The fast lane classifies the **push range** (`github.event.before` → head on `synchronize`, when `before` is a known ancestor of the head; otherwise the PR range; an unknown range is code). A **docs-only push** — every changed path in `DOCS_ONLY_PATHS` = the amendment G item 4 staleness allow-list (`docs/**` minus `docs/03-architecture/api/**` minus the base-ref manifest's `tooling_inputs`) ∪ `.claude/**` minus `.claude/settings.json` ∪ `*.md` outside `apps/**`, `packages/**`, `prisma/**`, `tools/**`, `tests/**`, `infra/**`, `.github/**`, one constant in base-ref tooling (`tools/ci/lane-scope.mjs`) — runs lane A in **light mode**: the steps already gated by `if: env.CODE == 'true'` (lockfile, dependency age, licences, signatures, audit, lint, porcelain, format, type-check, unit tests, lint fixtures, build, porcelain, Semgrep self-test) are skipped; every other gate (workflow policy, install flags, migration immutability, lane B evidence verifier, commitlint, actionlint, gitleaks, Semgrep, openapi-breaking, security record) runs on the exact head as before. The skipped checks are **inherited** from a **code proof**: a `ci.yml` pull-request run on a commit of the head's *code-identical set* (first-parent commits of `<base>..<head>` plus the head whose **tree diff** to the head is docs-only — a tree comparison, so union merges are handled) whose `fast-lane` job concluded `success` **with every CODE-gated required step of CI_REQUIRED_GATES concluded `success`** (steps also gated by LINT_CONTROLS may be skipped) and whose `scans` gitleaks, Semgrep and openapi-breaking steps concluded `success`, read through the GitHub jobs API. A job conclusion alone is never a proof: a light `fast-lane` is green with its code steps `skipped`, so it cannot chain, and the first push of any code-identical range necessarily ran full (its `before` lies outside the range or does not exist). `ci-gate` recomputes the classification with base-ref tooling and is **red** when a code push ran light, when a docs push of a PR with code changes has no proof, or when any classification output is empty (fail closed); `fast-lane`'s own classification is an optimisation whose disagreement with the gate is red. Lookups use `actions: read` on jobs that run no head code (`scans`, `ci-gate`), with `GH_TOKEN` in the env of the lookup step only (policy tripwire). **Concurrency** becomes `cancel-in-progress: false` for pull requests: runs of one PR queue (GitHub keeps one pending run and supersedes it on the next push), so a full run is never cancelled by a docs push and the docs push finds a completed proof. A PR whose whole diff is docs-only keeps today's rule (no code checks, no proof needed: its code tree is the base's). Reading of amendment A's `≈ 8 job-min typical`: a code push ≈ 6.6 → ≈ 5.9 (item 3) → ≈ 4.7 (incremental, item 3 (b)); a docs push ≈ 3.7 (stage 1) → 2 (stage 2).
