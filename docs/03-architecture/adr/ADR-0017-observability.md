# ADR-0017: Observability — Pino structured logs, OpenTelemetry traces, RED metrics, correlation IDs

- **Status:** Accepted
- **Date:** 2026-11-12
- **Deciders:** principal-architect
- **Related:** brief §3.3 (Pino), §9 (observability row), §4.13; REQ-PLAT-011/012/018/019; NFR-OBS-001..004, NFR-PRIV-001, NFR-AVAIL-002; platform.md §8

## Decision

1. **Logs.** Pino 10 JSON to stdout, one line per event: `time` (ISO UTC), `level`, `msg`, `service`, `version`, `env`, `correlation_id`, `org_id` (`none` when absent), `actor_id` (`system`/`anonymous`), `trace_id`/`span_id` when tracing is on. `pino-http` request logs: method, route **template**, status, duration — never bodies. Redaction paths generated from the audit classification registry (ADR-0007) plus fixed keys: `password`, `*.token`, `authorization`, `cookie`, `set-cookie`, `secret`, `api_key`, `totp`, `recovery_code`, card/payment fields, carrier credentials; emails masked to `a***@domain` (REQ-PLAT-012). *Amended 2026-11-17 (ADR-0007 amendment 13 item 2, D-ARCH-150): redaction is the key matcher of `packages/shared/src/logging` (TASK-010), not a generated path list; a build-time coverage test ties it to the classification registry.* Local dev: `pino-pretty` only via the dev script (never in images). A JSON Schema validates every captured line in e2e (NFR-OBS-001).
2. **Correlation.** `X-Correlation-Id` per ADR-0016 #15, carried in `AsyncLocalStorage` request context, job payloads, outbox rows, audit entries and outbound headers (`X-Correlation-Id`, plus carrier-specific `transId`/`Message-Reference`).
3. **Metrics.** `prom-client` 15 (*superseded 2026-11-12 by `@prometheus-io/client` 0.16, same API — SPK-01 amendment 1 below*) `/metrics` on api and worker (internal network only; not under `/api/v1`; descriptor `NONE`): RED per route template (`http_requests_total{method,route,status_class}`, `http_request_duration_seconds` histogram), queue gauges (waiting/active/failed/dead per queue), outbox relay lag, carrier call histograms + breaker state per account, audit write duration, chain verification result, rate-limit hits, security events counters. Cardinality guard: route templates only (no IDs), test fails > 1 000 series per metric (NFR-OBS-002). In AWS the ADOT collector scrapes `/metrics` and exports to CloudWatch EMF (platform.md).
4. **Traces.** OpenTelemetry SDK for Node (`@opentelemetry/sdk-node` + auto-instrumentations for http/express/pg/ioredis/undici) enabled by `OTEL_ENABLED=true` (REQ-PLAT-019, Should); spans: inbound HTTP, Prisma/pg queries, BullMQ enqueue/process (manual spans with context propagated in job payload `trace_context`), outbound carrier/gateway calls, saga steps. Span attributes exclude personal data and secrets (allow-list of attributes). Exporter OTLP to a collector; Compose `observability` profile runs otel-collector + Jaeger + Prometheus + Grafana; CI uses the in-memory exporter to assert the parent–child chain for a Mock booking (NFR-OBS-003).
5. **Health.** `/health/live` (process up) and `/health/ready` (Postgres, Redis, object storage ≤ 2 s each; audit partition horizon and chain status as *degraded*; outbox relay lag > 60 s degraded; *2026-11-20, ADR-0004 amendment 2 item 11: relay lag is the gauge `platform_outbox_relay_oldest_pending_age_seconds`; ADR-0004 amendment 3 item 22: this one component is the worker's alone, because only a worker runs a relay*) on api and worker; no versions/hostnames in bodies (REQ-PLAT-018).
6. **SLIs/SLOs and alerts (design now, live at M5 — NFR-OBS-004 DEFERRED).** SLIs: availability = non-5xx / total (excluding health), latency = share of requests under budget per class, booking success, carrier availability per account. SLO 99.9 % monthly; multi-window burn-rate alerts (14.4× over 1 h, 6× over 6 h) defined as code (`infra/modules/cloudwatch/alarms.tf` + Prometheus rules for local); each alert maps to a runbook (platform.md §12). These alarms are the ROLLBACK_TRIGGERS of the CD pipeline (ADR-0023).
7. **Security events** (REQ-SEC-012): structured log lines `event_type: 'security'`, `event: <catalogue name>`, counters `security_events_total{event}`; catalogue in `api/README.md`.
8. **Audit vs logs.** Logs are operational and ephemeral (retention 30 d local / per CloudWatch group); the audit trail (ADR-0007) is the compliance record. Nothing in logs is needed to reconstruct audited actions.

## Alternatives considered

- **Winston.** Resolved by brief §3.3 in favour of Pino.
- **Vendor APM agents.** Not in the stack; OpenTelemetry keeps the exporter swappable (CloudWatch/X-Ray now, anything OTLP later).
- **Always-on tracing in local dev.** Off by default to keep `docker compose up` light; profile opt-in.

## Consequences

- Positive: one correlation ID end to end; metrics drive autoscaling and rollback; traces explain carrier latency.
- Negative: OTel SDK is still 0.x (API churn) — pinned; redaction lists must be maintained with the classification registry (test enforces).

## Reversibility

High.

## Amendment (2026-11-12, SPK-01): metrics client and instrumentation packaging (SPK-01 §3 F-03/F-09; D-ARCH-037)

1. **`@prometheus-io/client` 0.16.x replaces `prom-client` 15 (§3).** `prom-client` is deprecated on the registry ("replaced by `@prometheus-io/client`"; last code release 2024-06). The successor is published by the Prometheus organisation (`github.com/prometheus/client_js`), Apache-2.0, Node `^22 || ^24`, with two runtime dependencies and 0 advisories (registry check 2026-11-12, ADR-0025 SPK-01 table). It continues the same registry/`Counter`/`Gauge`/`Histogram`/`Summary` API, so every metric, label set and the cardinality guard in §3 are unchanged; the `/metrics` exposition and the ADOT scrape path (platform.md §5) are unchanged. Because the package is pre-1.0 it is pinned **exact** and all metric construction is confined to the `platform/metrics` module of api and worker (no direct imports elsewhere; `eslint-plugin-boundaries` rule), so a move to the OpenTelemetry Metrics SDK + Prometheus exporter — the recorded alternative — would be local. Risk R-ARCH-22.
2. **Explicit instrumentations instead of the `auto-instrumentations-node` meta-package (§4 traces).** The production closure's only advisories (5 moderate, `glob` 10) come from `@opentelemetry/auto-instrumentations-node` → GCP resource detector → `gcp-metadata` → `gaxios` → `rimraf`. The observability task (TASK-214) imports only the five instrumentations §4 already names (`@opentelemetry/instrumentation-{http,express,pg,ioredis,undici}`), plus `instrumentation-pino` for trace-id injection into log lines (§1), and the AWS resource detector (`@opentelemetry/resource-detector-aws`); no GCP/Azure/Alibaba detectors are installed. Smaller closure, no behaviour change (§4's span list is unchanged). security-analyst's triage of F-09 can then close on this basis.

## Amendment (2026-11-14, Wave-0 sheet-fold 7; `rulings/wave-0-task-014-rulings.md` §4.3 (e), D-ARCH-118, D-ARCH-125): explicit OpenTelemetry SDK assembly

1. **No `@opentelemetry/sdk-node` (§4 traces).** `apps/api` and `apps/worker` declare `@opentelemetry/sdk-node`, which pulls every exporter (OTLP/gRPC, OTLP/proto, Zipkin) and with them `@grpc/grpc-js` (≈ 4 MiB) and `protobufjs` (≈ 2 MiB) into images that export OTLP/HTTP only (≈ 8 MiB per image, measured in the PR #39 worker image; risks R-ARCH-31). TASK-214 replaces it with the explicit assembly `@opentelemetry/sdk-trace-node` (`NodeTracerProvider`, `BatchSpanProcessor`) + `@opentelemetry/exporter-trace-otlp-http` + `@opentelemetry/resources` + `@opentelemetry/semantic-conventions` + the five instrumentations of item 2 of the SPK-01 amendment, registered through `registerInstrumentations` of `@opentelemetry/instrumentation`; metrics stay with `@prometheus-io/client` (§3), so no OTel metrics SDK is installed; the CI in-memory exporter is `InMemorySpanExporter` of `@opentelemetry/sdk-trace-base`, already in that closure. The TASK-214 PR body shows `@grpc/grpc-js`, `protobufjs` and `@opentelemetry/exporter-trace-otlp-grpc` absent from both images and quotes the layer-sum delta against the `imgheadroom` baseline (TASK-283). The exporter stays swappable at the composition root: OTLP/gRPC later is one package and one line, not an architecture change.
