# ADR-0002: Monorepo, build and developer tooling

- **Status:** Accepted
- **Date:** 2026-11-12
- **Deciders:** principal-architect
- **Related:** ADR-0001, ADR-0003 (module boundaries), ADR-0024 (testing), ADR-0026 (frontend), REQ-PLAT-001..003, NFR-MAINT-001/002, NFR-WEB-004/005

## Context

Brief §4.1 fixes the repository layout (`apps/{web,admin,api,worker}`, `packages/{shared,ui,carriers,pricing,audit,authz,config}`, `prisma`, `infra`, `tests`, `docs`). CLAUDE.md §2 requires npm workspaces, TypeScript strict and Node/TypeScript tooling only (no Python on the Windows 11 host). §3.3 requires public pages to be pre-rendered (React Router framework mode). The build must give every workspace one set of root scripts (REQ-PLAT-003) and enforce layering by lint (REQ-PLAT-002).

## Decision

1. **Package manager and workspaces.** npm 10 workspaces (*superseded 2026-11-12: npm ≥ 11.10, SPK-01 amendment item 1*), one root `package.json`, `package-lock.json` committed, `.npmrc` with `engine-strict=true`, `save-exact=true` for toolchain pins, `fund=false`, `audit=false` (audit runs as an explicit CI step). Workspaces: `apps/*`, `packages/*`, `prisma`, `tests/*`. Internal packages are consumed as TypeScript sources via `exports` → `src/index.ts` in dev/test (no publish step) and compiled by each consuming app's build (*superseded 2026-11-12: the `@platform/source` export condition with `dist/` at runtime, SPK-01 amendment item 3*).
2. **TypeScript project layout.** Root `tsconfig.base.json` (strict family, `module: NodeNext`, `target: ES2023`, `moduleResolution: NodeNext` for Node packages; `bundler` for Vite apps), `tsconfig.json` per workspace extending it, root `tsconfig.json` with `references` for `tsc -b --noEmit` type-check of everything in one command (*superseded 2026-11-12: `tsc -b`, emitting; SPK-01 amendment item 2*). Path aliases are **not** used; imports go through package names (`@platform/shared`, `@platform/ui`, …) so boundaries are visible to ESLint. (*Noted 2026-11-12, PR1-SEC-01: the `@platform` scope on npmjs.com belongs to a third party; the `.npmrc` pins it to `https://registry.invalid/` so a workspace name can never be resolved from a registry — PR1-SEC amendment item 1.*)
3. **Backend build/run.** `apps/api` and `apps/worker` are compiled with `tsc -b` to `dist/` (plain ESM, no bundler → stack traces and Prisma generated client stay simple), run with `node dist/main.js`. Dev: `tsx watch src/main.ts`. Prisma client generated to `prisma/generated` and consumed by `apps/api`, `apps/worker`, `prisma/seed`.
4. **Frontend build.** Vite 8 with `@react-router/dev` (React Router 8 framework mode). `apps/web`: `react-router.config.ts` → `ssr: false`, `prerender: [...]` for public routes per locale (`/{en,es,fr}`, `/{lang}/track`, `/{lang}/tools/prohibited-items`, `/{lang}/legal/{terms,privacy}`, help placeholders — **not** `/`, which Nginx redirects to `/{lng}/`, ADR-0026 amendment 4) (D-026, NFR-WEB-005); output `build/client` served by Nginx with the SPA fallback `index.html`. `apps/admin`: `ssr: false`, no prerender (SPA). Route-level code splitting is native to framework mode; `size-limit` enforces NFR-WEB-004 budgets; `rollup-plugin-visualizer` reports are CI artifacts.
5. **Lint/format.** ESLint 10 flat config at the root with `typescript-eslint` (type-aware), `eslint-plugin-boundaries` (layering and package rules, ADR-0003), `eslint-plugin-import-x` (no cycles, no `apps/*` cross-imports), `eslint-plugin-i18next` (`no-literal-string` in JSX, NFR-I18N-001), `eslint-plugin-react-hooks`, `eslint-plugin-jsx-a11y` (*superseded 2026-11-12: `eslint-plugin-jsx-a11y-x`, SPK-01 amendment item 5*); custom local rules for: money arithmetic on `Money`, forbidden `toFixed/toLocaleString/parseFloat` outside helpers (NFR-I18N-004, NFR-DATA-001), outbound HTTP only via the SSRF-safe client (NFR-SEC-010), audit writer import allow-list (REQ-AUDIT-001), no `innerHTML`/`dangerouslySetInnerHTML` outside the sanitising component (REQ-SEC-016). Prettier 3 for formatting; Stylelint 18 (*superseded 2026-11-12: Stylelint 17.16.x until the plugin admits 18, SPK-01 amendment item 5*) with `stylelint-use-logical` (NFR-I18N-003) and a rule requiring hover styles inside `@media (hover: hover)` (NFR-A11Y-006). `--max-warnings 0`.
6. **Root scripts** (REQ-PLAT-003; these are the CLAUDE.md §2 commands):
   - `npm run lint` → `eslint . --max-warnings 0 && stylelint "apps/**/*.css" "packages/ui/**/*.css"`
   - `npm run format:check` / `npm run format` → `prettier --check .` / `prettier --write .`
   - `npm run typecheck` → `tsc -b --noEmit` (*superseded 2026-11-12: `tsc -b`, SPK-01 amendment item 2*)
   - `npm run test:unit` → `jest --selectProjects unit` (*all four Jest scripts run as `node --experimental-vm-modules --disable-warning=ExperimentalWarning node_modules/jest/bin/jest.js …` since 2026-11-12, SPK-01 amendment item 4*)
   - `npm run test:integration` → `jest --selectProjects integration` (Testcontainers; Docker required)
   - `npm run test:api` → `jest --selectProjects api` (Supertest + OpenAPI response validation)
   - `npm run test:e2e` → `playwright test -c tests/e2e/playwright.config.ts`
   - `npm run test:coverage` → `jest --coverage` (thresholds in `jest.config.ts`)
   - `npm run test:load` → `docker compose -f tests/load/compose.k6.yml run k6 ...`
   - `npm run build` → `npm run build --workspaces --if-present`
   - `npm run openapi:lint` / `openapi:types` → `redocly lint docs/03-architecture/api/openapi.yaml` / `openapi-typescript ... -o packages/shared/src/api/types.gen.ts`
   - `npm run db:migrate`, `db:migrate:deploy`, `db:seed`, `db:seed:demo`, `db:reset` (Prisma + seed CLI in `prisma/`)
   - `npm run dev` → `docker compose up` (full stack) ; `npm run dev:api|dev:worker|dev:web|dev:admin` for hot-reload against the compose data services.
7. **Git hygiene.** Conventional Commits enforced by `commitlint` in CI (not a local hook requirement); `lint-staged` optional locally; `.gitattributes` LF (already present); Gitleaks pre-commit documented.
8. **Tooling scripts** (migration linter, `.env.example` parity, repository-structure test, licence/age checks) are written in TypeScript and run with `tsx` (no Python).

## Alternatives considered

- **pnpm / Turborepo / Nx.** pnpm would be faster, but CLAUDE.md §2 fixes npm; Turborepo/Nx add a task-graph layer that npm workspaces + `tsc -b` references cover adequately at this size (4 apps, 7 packages). Revisit if CI time exceeds the 20-minute budget (NFR-OPS-003).
- **Bundling the API with esbuild.** Smaller image but complicates Prisma generated client loading and source maps; `tsc` output + `npm ci --omit=dev --ignore-scripts` (ADR-0023 amendment F; *since 2026-11-12 also `--omit=optional`, SPK-01 amendment item 8*) keeps images under 300 MB (NFR-OPS-002) since Prisma 7 ships no engine.
- **Next.js / Remix for the public site.** Not in the fixed stack; React Router framework mode provides pre-rendering natively (verified reactrouter.com/how-to/pre-rendering, 2026-11-12).
- **`ts-jest`.** Works with TS 6 but couples Jest to the compiler version; `@swc/jest` transpiles without type-checking (type-check is a separate CI step) and is 3–5× faster.

## Consequences

- One command per concern (REQ-PLAT-003); layering and package rules are lint-enforced with negative fixtures (NFR-MAINT-001).
- Framework-mode pre-rendering produces per-locale HTML with `<title>`, meta, `hreflang` and primary heading in the HTML (NFR-WEB-005); loaders on pre-rendered routes run at build time, so public pages read reference data from a build-time snapshot or client-side fetch (ADR-0026).
- Negative: developers must run Docker for integration tests; type errors are not reported by Jest (by design) — `npm run typecheck` is required in the DoD.

## Reversibility

High for tooling choices (lint plugins, Jest transform); medium for the framework-mode pre-rendering model (route structure depends on it).

## Amendment (2026-11-12, SPK-01): toolchain as proven by TASK-001 (`docs/04-plan/spikes/SPK-01.md` §2, §5 A-1..A-4; D-ARCH-035, D-ARCH-036, D-ARCH-037, D-ARCH-038)

No version pin of the ADR-0001 baseline changes. The items below replace the corresponding wording of §1, §2, §4, §5, §6 and "Alternatives considered"; where a sentence above contradicts an item here, the item wins.

1. **npm ≥ 11.10, not "npm 10" (§1; D-ARCH-035).** The package manager is the npm bundled with Node 24.22+ (11.19.1 on the host and in `node:24` images). Root `package.json` declares `"engines": { "node": ">=24 <25", "npm": ">=11.10" }`; with `engine-strict=true` the system Node 20 / npm 10.8 fails fast with `EBADENGINE` (verified; this is the intended guard of ADR-0001 amendment). The floor is 11.10 because that release introduced `min-release-age`. The committed `.npmrc` is, in full: `ignore-scripts=true`, `engine-strict=true`, `save-exact=true`, `fund=false`, `audit=false`, `update-notifier=false`, `min-release-age=7`. The "once SPK-01 confirms" clause of ADR-0023 amendment F item 1 is **confirmed**: `min-release-age=7` is active (0 of 1,597 lockfile entries were younger than 7 days at generation).
2. **`npm run typecheck` is `tsc -b`, not `tsc -b --noEmit` (§2, §6; D-ARCH-035).** TypeScript 6.0.3 rejects `--noEmit` in build mode whenever a referenced project emits (`TS6310`). `tsc -b` type-checks all 16 projects and emits incrementally into the git-ignored `dist/` and `*.tsbuildinfo`, so `typecheck` followed by `build` costs nothing extra and lane A caches `.tsbuildinfo`. `noEmit` stays only on leaf projects that nothing references (Vite apps, `prisma`, `tests/*`, `tools`). Empty workspaces use `"files": []` plus `include` so they type-check with no inputs and pick up files as tasks add them (no stub files). Consequences: (a) the clean-tree checks of ADR-0023 amendments B/G are unaffected because `dist/` and `*.tsbuildinfo` are git-ignored; (b) `dist/` also contains compiled `*.test.*` files (one tsconfig per workspace covers source and tests, which keeps tests under the same strict settings) — runtime images strip `**/*.test.*` and `**/__fixtures__/**` from the copied `dist/` (TASK-014; platform.md §3.2); (c) ad-hoc `tsc <file>` in a directory with a `tsconfig.json` needs `--ignoreConfig` under TypeScript 6 (`TS5112`); (d) NFR-MAINT-002's verification wording (`nfr-strategy.md`, `nfr-traceability.md`) reads `tsc -b`.
3. **Workspace packages resolve through the `@platform/source` export condition (§1 "consumed as TypeScript sources via `exports` → `src/index.ts`" is replaced; D-ARCH-036).** Every `packages/*/package.json` declares, in this order, `"exports": { ".": { "@platform/source": "./src/index.ts", "types": "./dist/index.d.ts", "default": "./dist/index.js" } }`. `tsconfig.base.json` sets `customConditions: ["@platform/source"]`; Jest sets `testEnvironmentOptions.customExportConditions` (ADR-0024 amendment); the dev runners pass the condition explicitly (`dev:api`/`dev:worker`: `node --conditions=@platform/source` in front of `tsx`, TASK-006; Vite `resolve.conditions`, TASK-004); ESLint's `import-x` resolver is configured with the same condition (TASK-002). **Production never sets the condition:** image `ENTRYPOINT`s and compose commands run `node --enable-source-maps dist/main.js` with no `--conditions`, so Node takes `default` → `dist/index.js`, built by the `tsc -b` project references before the app; no TypeScript is loaded from `node_modules` and runtime images copy `packages/*/dist` + `packages/*/package.json` only (no `src/`). Guards: a repository test asserts the exact `exports` shape and order in every package; a Dockerfile/compose/task-definition test rejects `--conditions` and `NODE_OPTIONS=--conditions`; the runtime preflight (item 8) imports every `@platform/*` package inside the image.
4. **Jest runs under `node --experimental-vm-modules` (§6 scripts; D-ARCH-036).** `test:unit`, `test:integration`, `test:api` and `test:coverage` are `node --experimental-vm-modules --disable-warning=ExperimentalWarning node_modules/jest/bin/jest.js --selectProjects <project>` (the flag is set in exactly these four scripts; workflows and `quality:*` call the npm scripts, never `jest` directly; incremental mode passes `-- --changedSince=<base>` through). Reason: `jose` 6, `uuid` 14, `canonicalize` 5, `otplib` 13, `cookie` 2 and `nock` 15 are ESM-only, and Jest 30's `require(esm)` inside its module sandbox needs `vm.SourceTextModule`, which Node 24 still gates behind that flag. The `@swc/jest` CommonJS transform and `jest.mock` hoisting are kept; full native-ESM Jest was rejected (it breaks `jest.mock` hoisting and was not needed). The flag is test-only and never appears in an image or compose command (same guard as item 3). Jest uses explicit `roots` with root-relative `testMatch` instead of `<rootDir>/{a,b}/**` brace globs, which matched nothing on Windows (R-ARCH-17). Until the first integration/API suites land (TASK-003, TASK-276), `test:integration`/`test:api` carry `--passWithNoTests`; the lane B required-suites manifest (`min_tests`, ADR-0023 amendment G) is the guard against an empty suite after that.
5. **Lint stack substitutions (§5; D-ARCH-037; registry evidence in ADR-0025).** `eslint-plugin-jsx-a11y` (last release 2024-10-26, > 18 months, peer range ends at ESLint 9) is replaced by **`eslint-plugin-jsx-a11y-x` 0.2.x** (MIT, es-tooling fork, peer `eslint ^9 || ^10`). **Stylelint 17.16.x** replaces "Stylelint 18" for now: `stylelint-use-logical` 2.1.3 (the NFR-I18N-003 rule) declares `stylelint >= 11 < 18`, and the alternative `stylelint-plugin-logical-css` 2.1.0 stops at `^17` too, so no logical-properties plugin supports 18 yet; a declared-compatible pair without a peer override beats a 9-day-old major with a forced peer. Upgrade trigger: the first `stylelint-use-logical` release whose peer admits 18 (Dependabot proposes it; the `lint` script is unchanged). The custom rules in §5 are unaffected.
6. **`size-limit` with `@size-limit/file` only (§4; D-ARCH-037).** NFR-WEB-004 budgets are byte budgets (gzip/brotli) on built files, which `@size-limit/file` measures with 5 packages and 0 advisories. `@size-limit/preset-app` (and `@size-limit/time`) pull a puppeteer/estimo chain with 14 High advisories and were not installed; runtime cost (TBT/INP) is Lighthouse CI's job (ADR-0024 amendment).
7. **`openapi-typescript` 7.13 peer override (§6 `openapi:types`).** Root `package.json` carries `"overrides": { "openapi-typescript": { "typescript": "$typescript" } }` because 7.13.0 declares `typescript ^5.x` while generation under 6.0.3 is verified (11,427 lines from `openapi.yaml`, type-checks under `--strict`). Remove the override when upstream widens the peer. This and the `@hookform/resolvers` 5.9.2 choice (ADR-0026 amendment 11) are the only version-selection deviations from "latest within the major".
8. **Runtime images install with `npm ci --ignore-scripts --omit=dev --omit=optional` ("Alternatives considered", esbuild bullet; D-ARCH-038).** `--omit=dev` alone leaves `devOptional` packages in place — the Prisma CLI, `@prisma/studio-core` (→ `elkjs`, `EPL-2.0` — *corrected 2026-11-12, PR1-SEC-05: the locked 0.11.1 declares `EPL-2.0` exactly, not "`OR GPL-3.0-or-later`"*), `@visx/*` alpha pre-releases and `typescript` are dev dependencies that are also reachable as optional peers of production packages (`@prisma/client` → `peerOptional prisma`; `react-router` → optional `typescript`), and npm drops them only when **both** `dev` and `optional` are omitted. bcrypt 6 ships its N-API prebuilds inside the package (not as optional dependencies), so `--omit=optional` does not affect it. A **preflight** step (`dist/preflight.js`, generated by TASK-014: imports every production module and every `@platform/*` package, then exits 0) runs as a `RUN` in the runtime stage and fails the image build if an omitted optional dependency was needed. Details, including the `migrate` image, are in ADR-0023 amendment I and platform.md §3.2.
9. **`deps:rebuild` uses `npm exec --no -- <bin>`**, never `npx`, so a missing local binary fails instead of being downloaded (SEC-P3-31, SEC-TC-64; D-ORCH-005 ruling 8). ADR-0023 amendment F item 1 and platform.md §3.2 are aligned by ADR-0023 amendment I.

Verification: TASK-001 clean-room run on the Windows host (`npm ci --ignore-scripts` 1,505 packages → `deps:rebuild` → `lint` → `format:check` → `typecheck` (16 projects) → `test:unit` 38/38 → `build` 9 workspaces → `npm audit --audit-level=high` 0/0 → `npm ls --all` valid), recorded in SPK-01 §1; the `ubuntu-latest` half closes with TASK-007's first lane A run (R-ARCH-01/17/20).

## Amendment (2026-11-12, PR1-SEC): `@platform` scope ownership and pin, Prisma CLI wrapper, `bcrypt` import confinement, exact `elkjs` SPDX (`docs/05-quality/security/PR-0001-TASK-001-security-review.md` PR1-SEC-01/02/05/06; D-ARCH-040, D-ARCH-041, D-ARCH-042, D-ARCH-003 rev 4; amends §1, §3, §5, §6 and SPK-01 amendment item 8)

1. **`@platform` is not ours (§1, §2).** The npm scope `@platform` belongs to an unrelated organisation on npmjs.com (131 public packages on 2026-11-12; none of our 16 names is published). The workspace names stay `@platform/*` — every workspace is `"private": true`, never published and only ever linked — and the committed `.npmrc` pins the scope to `https://registry.invalid/` (RFC 6761; ADR-0023 am. J item 1), so no install anywhere can resolve a workspace name from a registry; it fails closed with `ENOTFOUND`. Renaming would not change the exposure (we own no scope) and registering one is an external action outside the guardrails. Internal dependencies keep the `"@platform/<pkg>": "0.0.0"` form; `check-lockfile` asserts that every `@platform/*` lockfile entry is a workspace link, and `check-install-flags` asserts the `.npmrc` line (root and `tools/isolated/*` copies).
2. **The Prisma CLI runs through the repository wrapper (§3 "Prisma client generated", §6 `db:*` scripts).** `db:migrate`, `db:migrate:deploy`, `db:reset`, the migration linter's `prisma validate` and `deps:rebuild`'s `prisma generate` invoke `node tools/deps/prisma-cli.mjs <args>`, which verifies the pinned `schema-engine` against `tools/deps/prisma-engines.json` and then runs `npm exec --no -- prisma <args>` with `PRISMA_SCHEMA_ENGINE_BINARY` pointing at the verified file and `CHECKPOINT_DISABLE=1` (ADR-0023 am. J item 2). `db:seed`/`db:seed:demo` (the seed CLI; no engine) are unaffected. `check-no-raw-prisma` rejects a bare `prisma` in scripts, workflows, Dockerfiles and compose files.
3. **`bcrypt` is imported in one module only (§5 custom rules).** A `no-restricted-imports` rule (the mechanism of the audit-writer import allow-list) forbids `bcrypt` and `bcryptjs` outside the `PasswordHasher` implementation module (ADR-0006 am. 16), so the recorded exit from `bcrypt` 6.0.0 (ADR-0025 PR1-SEC amendment; D-ARCH-042) is a one-module change with no stored-hash migration.
4. **Correction to SPK-01 amendment item 8:** `elkjs@0.11.1` declares `EPL-2.0`, not `EPL-2.0 OR GPL-3.0-or-later` (D-ARCH-003 rev 4; ADR-0023 am. J item 3).
