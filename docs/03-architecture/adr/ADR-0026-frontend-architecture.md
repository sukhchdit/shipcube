# ADR-0026: Frontend architecture for `apps/web` and `apps/admin`

- **Status:** Accepted
- **Date:** 2026-11-12
- **Deciders:** principal-architect (ux-designer owns flows/wireframes/tokens content in P2)
- **Related:** brief §3.3 (pre-rendering), §4.2 (token in memory), §5, §6, §8; REQ-UI-*, REQ-I18N-*, REQ-RBAC-009/010, REQ-AUTH-010, REQ-ADMIN-001/005/006/009, REQ-SEC-002/016; D-008, D-023, D-026; NFR-WEB-*, NFR-A11Y-*, NFR-I18N-*, NFR-COMPAT-*; ADR-0002, ADR-0006, ADR-0016, ADR-0025

## Decision

1. **Two React Router 8 framework-mode apps**, both `ssr: false`. `apps/web`: `prerender` list = public routes × locales (home with quote widget, public tracking, prohibited-items lookup, legal/privacy, help placeholders) generated from `routes.ts` + the locale list; authenticated areas (results, wizard, checkout, account) are client-rendered via the SPA fallback. `apps/admin`: pure SPA (REQ-ADMIN-001), no prerender, all routes guarded. Hosted by Nginx (Compose) / CloudFront + S3 (AWS) with SPA fallback to `index.html` (`/` is not pre-rendered; Nginx redirects it — amendment 4) and immutable caching of hashed assets (NFR-WEB-005).
2. **Locale routing.** Public URLs carry the locale prefix `/{en|es|fr}/...` (pre-rendered per locale with `<html lang>`, `hreflang` alternates, canonical); `/` is answered by an Nginx 302 to `/{lng}/` honouring DR-A18 (cookie `lng` → `Accept-Language` → `en`), which works without JavaScript — amendment 4 (the earlier "server-less locale-detection page" is withdrawn). Authenticated routes keep the prefix for consistency. All strings via `react-i18next` keys; ICU plurals; `Intl` helpers in `packages/shared/format` for numbers, dates (viewer IANA zone shown, A-077), currencies and units (NFR-I18N-004); logical CSS properties only (NFR-I18N-003).
3. **Design system (`packages/ui`).** Tailwind 4 tokens (`@theme`), light/dark via `data-theme`, density (`comfortable|compact`) for admin tables, 14 px base, 4/8 px grid, 36 px pointer / 44 px touch targets, states (hover under `@media (hover: hover)`, focus-visible 2 px outline ≥ 3:1, active, disabled, loading), skeletons, toasts, confirmation-with-reason dialog, `PermissionGate`, `ScreenState` component implementing the six states (loading, empty with next step, error with retry, partial, permission-denied, offline) used by **every** screen (REQ-UI-007). Radix primitives wrapped once; no feature-level colours or spacing (lint).
4. **Data layer.** `packages/shared/api` generated types (`openapi-typescript`) + a thin typed client over Axios; TanStack Query for server state with query keys per resource; mutations send `Idempotency-Key` (UUIDv4 generated per user intent, persisted in the wizard draft to survive retries) and `If-Match` from the cached ETag; 412 → refetch and "merge or overwrite" prompt (REQ-API-013); problem+json `errors[].pointer` mapped to form fields (REQ-UI-010). Forms: React Hook Form + Zod schemas built from `packages/shared` constants (parity with Joi, NFR-MAINT-003).
5. **Auth in the browser** (REQ-AUTH-010, ADR-0006). Access token in a module-scoped variable only; silent refresh 60 s before expiry; single in-flight refresh per tab and cross-tab coordination (`navigator.locks` with `BroadcastChannel` fallback); on 401/`SESSION_REVOKED` → sign-in with a validated same-origin return URL (REQ-ADMIN-001). CSRF token fetched once per session for refresh/logout. `GET /me` provides permissions → `can()` helper hides controls from the accessibility tree (REQ-RBAC-009) and route guards render the permission-denied state without fetching (REQ-RBAC-010).
6. **Quote results streaming.** `fetch` + `ReadableStream` SSE parser (headers needed); progressive cards with reserved dimensions (CLS ≤ 0.1), per-carrier skeletons, notice per unavailable carrier (NFR-RES-006), badges computed client-side from the `complete` set using DR-B17.
7. **Booking wizard.** One step per screen on mobile; resumable, autosaved (`PATCH /shipments/{id}` per section with `If-Match`; autosave indicator; drafts expire 30 d); sticky price summary and sticky primary action on mobile; no redundant re-entry (WCAG 3.3.7); Stripe Payment Element on the checkout step with the visible test-mode indicator (REQ-PAY-016).
8. **Admin shell** (D-008): collapsible sidebar (only implemented modules: Audit, My sessions), breadcrumb, locale switch, command palette seam; audit viewer routes `/audit`, `/audit/entries/:id`, `/audit/entities/:entity/:id` with filters in the URL; staff MFA flows (enrolment, challenge, recovery codes shown once with acknowledgement).
9. **Security.** CSP hash-based for pre-rendered HTML (no inline scripts; React Router's hydration data is emitted as a hashed `<script>`), `connect-src` API + Stripe, `frame-src` Stripe; no `dangerouslySetInnerHTML` outside the single sanitising component (REQ-SEC-016); `rel="noopener"`; CSP violation listener in e2e (NFR-SEC-006).
10. **Performance budgets.** Initial JS of every public page (incl. the pre-rendered home) ≤ **170 kB** gzipped (D-035 d), authenticated routes ≤ 350 kB, CSS ≤ 50 kB, lazy chunks ≤ 150 kB; images AVIF/WebP with dimensions; **system font stack, no web fonts** (D-UX-001 — removes font download from LCP and avoids swap-induced CLS); `size-limit` in CI; Lighthouse CI thresholds (NFR-WEB-001/003/004/005).
11. **Browser matrix.** `browserslist` = current and previous majors of Chrome/Edge/Firefox/Safari + iOS Safari/Android Chrome; Playwright device descriptors for mobile (NFR-COMPAT-*).
12. **Analytics seam** (PRD §4.1, BACKLOG). `track(event, props)` abstraction emitting to a `POST /api/v1/events` endpoint in M2+; in M1 it is a no-op logger behind a feature flag with the event names (`auth.register_started`, `auth.verify_completed`, `quote.result_viewed`, `checkout.paid`) defined — explicitly documented, no silent stub.
13. **Map tiles decision (D-014, R-11).** Service points are delivered as a **list** (Should); the map view (Could) is **not built** this run because no zero-cost tile provider satisfies both its usage policy and the $0 budget without an API key (OSM tile policy forbids heavy app use; MapTiler/Stadia need keys). Seam: `<ServicePointMap provider={...}>` prop in `packages/ui` with a `NullMapProvider`.

## Alternatives considered

- **Server-side rendering (`ssr: true`).** Needs a Node SSR process for the frontends (a third runtime), contradicting "static frontends served by Nginx" (brief §10); pre-rendering satisfies SEO (D-026).
- **Single app for web + admin.** Rejected: separate cookies, CSP, bundles and permission surfaces (brief §4.1; NFR-WEB-004 forbids cross-bundle code).
- **Redux/Zustand for server state.** TanStack Query covers it; UI state stays local.

## Consequences

- Positive: SEO-ready public pages with no server; strict a11y/i18n by construction; typed contract end to end.
- Negative: locale-prefixed URLs double pre-rendered pages (×3 locales — cheap); hash-based CSP requires build-time extraction of inline hydration scripts (handled by the build step; verified in e2e).

## Amendments after the UX specification (2026-11-12, `docs/02-ux/README.md` §5 items 2, 4, 5, 6, 10, 11; D-UX-005, D-UX-011, D-UX-016, D-UX-018, D-UX-028, D-UX-029)

1. **Guest quote token persistence (UX §5 #2, D-UX-011).** The API contract is unchanged (`X-Quote-Token` header, api/README §8). The web app keeps tokens in `localStorage` under `qt:<quoteId>` → `{ token, expires_at }`: written once from `createQuote`'s response, read for `getQuote`, `streamQuoteResults` and `claimQuote`, and deleted on claim, on `expires_at`, on sign-out and on a 404 for that quote. The token never enters a URL, `history.state`, a query string or a log line. It survives reload, "open in new tab" and the register/sign-in detour (same origin). `sessionStorage` was rejected because it is lost when the tab closes or a link opens in a new tab within the 24 h validity. An HttpOnly cookie was rejected for this token: it would change the contract (`in: cookie` security scheme, CSRF handling on guest POSTs, one token per browser instead of one per quote) to protect a credential that only reads one unclaimed quote (postcodes and package data, no names) and dies on claim; the XSS control is the hash-based CSP with no third-party scripts (§9).
2. **TOTP QR rendering (UX §5 #4).** `uqr` 0.1.3 (MIT, zero dependencies; ADR-0025) encodes the `provisioning_uri` into a matrix that a `packages/ui` `<QrCode>` component renders as a React `<svg role="img" aria-label=…>` of `<rect>` elements (`shape-rendering="crispEdges"`, minimum 200 CSS px, fixed dark-on-light colours independent of the theme so scanners work in dark mode), with the manual key and a copy button beside it. No `dangerouslySetInnerHTML` (REQ-SEC-016), no data-URI image, no network request. Used by S-D03 (staff, Must) and S-C07 (customer MFA, Should). Server-rendered SVG was rejected: it would add an image endpoint carrying the secret or embed SVG text in JSON for no benefit (ADR-0006 amendment 11).
3. **ICU MessageFormat plugin (UX §5 #5, D-UX-028).** Both apps use `i18next-icu` 2.7 (MIT) with `intl-messageformat` 12 (BSD-3-Clause) and `@formatjs/icu-messageformat-parser` 3.5 (MIT) as the i18next message format: `{count, plural, one {…} many {…} other {…}}` and `{x, select, …}` per `content-and-i18n.md`; interpolation is ICU `{name}` (not `{{name}}`). Numbers, dates, money and units are **pre-formatted** by `packages/shared/format` and passed as strings, so ICU's own number/date formatting is unused and the es/fr grouping rule stays in our helpers (amendment 7). Messages compile at runtime without `eval` (CSP-safe) and are memoised. Budget: the ICU runtime is expected at ≈ 15–20 kB gzipped and is counted inside the 170 kB public-page budget (§10, `size-limit`); SPK-06 measures it in Wave 0. If the public budget is breached, the fallback is `Intl.PluralRules`-based i18next suffix plurals (`_one/_many/_other`, `context` for selects) for **all** strings — one format, not two — as D-UX-028 anticipates. The D-023 key check parses ICU to compare placeholder sets across en/es/fr.
4. **Root `/` locale redirect (UX §5 #6a, D-UX-005).** Decided mechanism: **Nginx in the `web` image** (the same image serves locally behind `edge` and in AWS behind CloudFront's default behaviour → ALB → Nginx, platform.md PD-01). `GET /` answers `302 Location: /{lng}/` with `lng` = cookie `lng` when it is `en|es|fr`, else the first supported language in `Accept-Language` order (regex `map`), else `en`; response headers `Cache-Control: no-store` and `Vary: Cookie, Accept-Language`. It works without JavaScript, so `/en/` is reachable with scripts disabled. Consequently **`/` is not in the `prerender` list**; React Router then emits `index.html` as the SPA fallback (not `__spa-fallback.html`) and Nginx uses `try_files $uri $uri/index.html /index.html` (platform.md §3.3 updated). The "tiny locale-detection page" of §2 is withdrawn. Locale cookie: `lng=<en|es|fr>; Path=/; Max-Age=31536000; SameSite=Lax; Secure` (readable by the SPA, which sets it on language switch; `Secure` relaxed only for plain-HTTP local use like REQ-SEC-003); the admin app uses the same cookie name on its own host.
5. **`noindex` (UX §5 #6b, D-UX-029).** Nginx adds `X-Robots-Tag: noindex` on `/{lng}/track` responses when `$arg_number` is non-empty, implemented with a `map` (not an `if` block, which would drop the inherited `add_header`s); the shell without `number` stays indexable. The admin Nginx sends `X-Robots-Tag: noindex, nofollow` on every response and serves `robots.txt` with `Disallow: /`. The API sends `X-Robots-Tag: noindex` on every response (ADR-0016 amendment 6). The header test suite (NFR-WEB-005, REQ-SEC-001) asserts all three.
6. **Carrier logo seam (UX §5 #10, D-UX-018).** `carriers.logo_asset_key` (data-model.md §3.8) names a brand asset. The frontends resolve it to the same-origin path `/brand/carriers/<key>.svg`, served by Nginx from an operator-mounted directory (Compose volume `brand-assets` → `/usr/share/nginx/html/brand`; AWS: `web-assets` bucket prefix `brand/` behind CloudFront) and render the monogram chip when the key is the reserved value `monogram` or the asset returns 404. CSP `img-src 'self' data:` is unchanged (no third-party hosts); the repository ships no logo files; the M1 seed sets `monogram` for every carrier. The same mechanism serves the `BRAND_*` logo.
7. **Number grouping (UX §5 #11, D-UX-028).** The number and money helpers in `packages/shared/format` call `Intl.NumberFormat(locale, { useGrouping: 'always', … })` on the frontends and in the worker (e-mails, PDFs), so es-ES renders "1.234,50" as US-116 expects. Supported by Node 24 and the §11 browser matrix (Chrome ≥ 106, Safari ≥ 15.4, Firefox ≥ 116). A shared unit test pins the US-116 examples per locale; qa-lead's test data uses the same helpers.

## Amendment after the P3 security review (2026-11-12, `docs/05-quality/security/P3-architecture-security-review.md` SEC-P3-11; D-ARCH-024)

8. **Admin idle timeout is driven by user input, not by the refresh timer (SEC-P3-11, MEDIUM; amends §5 "silent refresh 60 s before expiry" for `apps/admin`).** The admin app keeps an idle clock that is reset **only by user input** (`pointerdown`, `keydown`, `touchstart`, `wheel`; never by focus, visibility changes, timers or TanStack Query background refetches, which are paused while the warning shows). Silent refresh runs only while the idle clock is under 30 minutes (`AUTH_ADMIN_IDLE_TIMEOUT`, mirrored from the server's `AUTH_ADMIN_REFRESH_IDLE_TTL`). At 28 minutes a modal warning (`role="alertdialog"`, focus moved to it, announced) offers "Stay signed in" (which triggers an immediate refresh and resets the clock) and "Sign out"; it satisfies WCAG 2.2.1 Timing Adjustable (the user can extend before the limit, with at least 20 seconds' notice). At 30 minutes without input the app stops silent refresh, calls `logoutSession`, clears in-memory state and routes to `/sign-in?reason=idle` with a validated same-origin return URL (REQ-ADMIN-001). Server enforcement (the 30-minute sliding admin refresh token) is in ADR-0006 amendment 13, so a tab that is suspended or whose script is blocked still idles out. The web app is unchanged (its sliding refresh is the D-038 decision as amended). ux-designer supplies the dialog copy in en/es/fr; verification SEC-TC-39. *Added 2026-11-12 (SEC-P3-33 item 11, usability only):* the last-input timestamp is shared across the admin app's tabs through the same `BroadcastChannel` the single-flight refresh uses (§5), so activity in one tab keeps a second tab from idling out early and the warning appears in all tabs together; the server's 30-minute sliding refresh token remains the enforcement.
9. **Guest quote token in `localStorage` — accepted with conditions (SEC-P3-15, LOW; adjudication (b); completes amendment 1; D-052 d).** (1) Only `{token, expires_at}` is stored under `qt:<quoteId>`, never anything else. (2) On every app start the store sweeps expired entries and keeps at most the 20 newest. (3) Deletion on claim, sign-out, 404 and expiry as designed. (4) The token never enters URLs, `history.state`, `Referer` or logs; Pino redacts `x-quote-token`. (5) Server side, the token stops granting access **7 days after `expires_at`** even though the quote row is retained for 90 days (REQ-QUOTE-002, D-045). (6) Stripe.js is loaded lazily on the checkout route only; by then the quote is claimed and the token deleted, so the only third-party script never shares a page with a live guest token (also SEC-P3-24 item 3). Revisit trigger unchanged: an HttpOnly path-scoped cookie if a guest quote ever holds names, addresses or payment state. Verification: SEC-TC-54.

## Reversibility

Medium (routing and pre-render model shape the apps).
