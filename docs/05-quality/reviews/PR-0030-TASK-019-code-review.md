## 3. Deviation and decision rulings

- **D-TASK019-01 (GO, no fallback): accepted.** Every claim re-checked against the tests: 13 contract tests (put/head/get, 5 MiB, presigned GET, expiry, tamper, 301 s, versioning, putIfAbsent x2, missing, delete, checkBucket, wrong credentials) exercise the six capabilities; the digest pin is outside the cooldown (1.0.4 pushed 2026-10-25). The GO stands for RustFS; R1-m4 records what RustFS cannot show about AWS.
- **D-TASK019-02: accepted with R1-m4/m5/m7 wording.** (1) real `HeadBucket` check, stub and tripwire removed together (sheet: tripwire deleted in the same commit): met; the replacement test keeps a live positive control. (3) retry policy: the SDK retries every operation, which is correct for this port only because all writes overwrite by key (R1-n4 for versioned buckets).
- **Boundary test as the lint substitute (lint lock held by TASK-020): adequate for this PR**, not permanent as written (R1-m7).
- **`pendingCheck('object_storage')` removal (PR #9 m2, D-TASK006-02, D-ARCH-074): closed** for the storage half; the audit half stays with PR #24.
- **`putIfAbsent` retry semantics (the PR body note): correct and now proved** by my loopback probe (R1-m1 asks for it as a test). The documented caller rule (compare `head().sha256`) is the right one, but it needs an owner (R1-m6).
- **Credentials:** only via `STORAGE_*_REF` secret refs, revealed once in `storageOptionsFromConfig`, never logged; the adapter header and the error map never read `message`. The error codes carry no endpoint/bucket/key/credential (unit table of 13 shapes x 5 operations and the live composition body).
- **Presigner client:** a second `S3Client` only when `STORAGE_PUBLIC_ENDPOINT` differs; unit-proved (origin and credential scope) and destroyed on shutdown. Fine.

## 8. SECURITY-FLAGS (for security-analyst)

- Pre-signed URLs are bearer tokens: confirm the PR #20 redactor masks `X-Amz-Signature`, `X-Amz-Credential`, `X-Amz-Security-Token` in log lines and request logs before the first consumer (document download task).
- `contentDisposition` accepts any text without control characters: the caller must build the filename safely (quotes, `;`, non-ASCII); the port only blocks header splitting.
- Static credentials: `storageOptionsFromConfig` falls back to the SDK default chain when one of the two refs is missing (R1-m5): confirm that is acceptable in staging/production hardening (a half-configured pair should fail fast).
- `STORAGE_ENDPOINT`/`STORAGE_PUBLIC_ENDPOINT` are config-only (SSRF not reachable from user input); HTTPS is enforced by the config guard outside local/test.
- M5: Object Lock plus `s3:PutObject`-only worker role (ADR-0021 am. 1) interacts with `If-None-Match` and the CRC32 default; the 409 conflict shape (R1-m4) belongs in the anchor sink's threat notes.
- `apps/api/src/platform/**` is a security-owned path: record naming the final head required.
