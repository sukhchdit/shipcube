## Scope notes (lead)

- **Runtime (packages/ui/src/i18n).** One factory, `createI18n`, builds an i18next instance per app with the ICU format plug-in. Resources are static imports, so `initAsync: false`, prerender and hydration stay synchronous. Fallback is `en`. Namespaces: the app's `common` plus the shared ui namespaces. Values are passed as `replace`, so no placeholder name can collide with an i18next option. Translators come from `getFixedT(locale)`: the locale is an argument, never global instance state, so the existing hydration snapshots stay valid.
- **Shared `errors` namespace.** The 80 error-code messages are identical in both apps today. They move to `packages/ui/src/locales/{lng}/errors.json`, keyed `errors:<CODE>` (UX §2.1). The completeness check against the shared `ERROR_CATALOGUE` moves with them.
- **Runtime missing key (AT-07).** A post-processor compares the language that resolved the key with the requested one. It warns once per locale and key, naming the key only. It never logs values.
- **Checker (tools/i18n).** One pure core with a thin CLI (`npm run i18n:check`, also the last step of `npm run lint`), plus the Jest suite `tools/i18n/parity.test.ts`. The checks:
  - key parity per namespace and locale;
  - ICU syntax;
  - placeholder parity;
  - plural categories per locale (CLDR through `Intl.PluralRules`);
  - unused keys (literal keys and template prefixes in the non-test sources of the consuming apps);
  - cross-namespace collisions with different parameters;
  - concatenation of translated text (`t()` with `+`, or inside a template literal);
  - the linguistic-review register (every es and fr namespace listed; the pending count is printed).
- **Hydration (R3-n1).** The web `useLocale` server snapshot uses a served locale captured once, at module evaluation. It is `DEFAULT_LOCALE` when React Router reports SPA mode, otherwise the `<html lang>` of the served file. The test isolates the module. The admin `meta()` cookie read stays.
- **Not in this task:** `react-i18next` (it arrives with the first `<Trans>` consumer), e-mail template sets (notifications), the pseudo-locale (TASK-110), lazy routes and the m6 size-limit split, and activating the `i18n-parity` suite in `tools/quality/required-suites.json` (a manifest-only follow-up: a PR cannot activate a suite and carry its evidence).
