## Scope notes (lead)

- **Compile without a new dependency.** A small Node/TypeScript compiler in the repo that reads `packages/ui/tokens/tokens.json` and writes or verifies the theme CSS is enough. A token build library would change `package-lock.json`, which TASK-041 also changes (working rule 8). If you generate the CSS, commit the output and add a test that fails when the committed CSS and the JSON drift apart. A build-time generator that lane A does not run is not enough.
- **Token lint.** It rejects `#hex`, `rgb()`/`hsl()` colours and off-grid spacing in CSS, and an unknown token. The card names `tools/ui/token-lint.ts`. A Stylelint rule under `tools/stylelint-rules/`, registered in `stylelint.config.mjs`, matches the house pattern and runs inside `npm run lint` already. If you keep a standalone script instead, wire it into the root `lint` script. Both `stylelint.config.mjs` and the root `package.json` are CODEOWNERS paths and need a security record. Raw values stay allowed only in the theme source file. Do not edit `eslint.config.mjs`: it holds the `lint` lock. Arbitrary Tailwind values in JSX class names (`p-[13px]`) are out of scope unless the card AC needs them; if they need an ESLint rule, ask the orchestrator for the lock.
- **Negative fixtures.** One fixture per refused shape under `tests/fixtures/lint/` (CODEOWNERS), linted by the existing negative-fixture test, so that a weakened rule is a no-weakening finding in lane A.
- **Tenant override** (AT-US-101-04): a brand or tenant layer overrides semantic tokens through CSS variables only, never by changing primitives, as `tokens.md` describes.
- **Contrast** (NFR-A11Y-005): if `tokens.md` lists contrast pairs, add a unit test that computes them from the JSON.
- The DoD lines about screens (en/es/fr, six states, axe, Playwright) are the generic frontend template. This task ships no screen. The Playwright and axe runs of the existing scaffold pages must stay green on the new theme (lane B `e2e` on Chromium).
