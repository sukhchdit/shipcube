## Scope notes (lead)

- **Tables.** Create `outbox_events`, and also `processed_events`, which data-model §3 puts beside the outbox as the consumer-dedupe table and which the PURGE line names. Both are SYSTEM tables in `tools/db/table-classes/platform.json`: no RLS, reached only through the platform/outbox port via `systemDelegates(tx)` (PR19-SEC-01). The hard-delete allow-list entries and the `grants.manifest` lines come with them. If you decide not to create `processed_events` here, record it as `D-TASK043-nn`, keep its purge out, and say so in the report.
- **`job_executions` DELETE.** Per the PURGE line, the migration grants DELETE on `job_executions` to `platform_app`, `worker.json` gains `hardDelete`, and `grants.manifest` gains the line. Extend `tools/db/grants-manifest.test.ts` too.
- **Relay.** The worker relay reads due rows with `FOR UPDATE SKIP LOCKED` in batches through the worker runtime runner under the SYSTEM actor (bound parameters, no second pool). It enqueues a payload v2 job whose deterministic job ID is derived from the event ID, then marks the row published. A crash between enqueue and mark redelivers, and BullMQ deduplication by job ID or consumer idempotency absorbs the duplicate (AT-US-011-04). Order is per aggregate (AT-US-011-03). If the queue is unavailable, rows stay pending (AT-US-011-05). Export the relay latency metric (AT-US-011-06).
- **Purge schedule.** Add one schedule name (at most 47 characters) to the closed `SCHEDULE_NAMES`. The handler applies its own age predicate in its own SQL, works in batches of 5,000, and runs through `idempotentProcessor`, keyed by the occurrence ID, if it writes. A row published or processed 29 days ago stays.
- **Configuration.** If you add relay tunables, add them with defaults to `packages/config/src/schema.ts`. Suggested names: `OUTBOX_RELAY_POLL_INTERVAL_MS` (default 500, ADR-0004) and `OUTBOX_RELAY_BATCH_SIZE`. List the `.env.example` lines in the report (working rule 6). `OUTBOX_PAYLOAD_KEY` already exists in the schema and the key register: do not re-add it.
- **No `platform.job_context` work.** That is TASK-047. The relay runs as SYSTEM and enqueues identifiers only.
