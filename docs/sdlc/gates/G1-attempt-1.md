## Findings
- **F1 (minor, contradiction):** Configuration defaults differ between REQUIREMENTS.md and NFR.md: (a) guest-quote limit 20/min + 100/h per IP (`REQUIREMENTS.md:445` REQ-QUOTE-002, US-155) vs 60/min (`NFR.md:112` NFR-SEC-005); (b) verification-resend / reset-request limit 3 per hour per account (`REQUIREMENTS.md:105,112` REQ-AUTH-004/011) vs 5 per hour per email (`NFR.md:112`); (c) compose all-healthy 180 s (`REQUIREMENTS.md:77` REQ-PLAT-005) vs ≤ 10 min (`NFR.md:203` NFR-OPS-001); (d) home-page initial JS 170 KB (`REQUIREMENTS.md:283` REQ-UI-018) vs 200 kB public JS (`NFR.md:90` NFR-WEB-004); (e) DR-A22 (`REQUIREMENTS.md:694`) adds a 5/min/account auth limit absent from NFR-SEC-005. All are ASSUMED/default values, so the risk is a design that satisfies one document and fails the other's test.
- **F2 (minor, tagging):** Three M0 REQs are delivered only by M1 stories: REQ-UI-014 (M0 Must) → US-109 (M1 Must) — PRD §6.1:134 itself says the widget UI is M1, so the REQ tag is wrong; REQ-AUTH-020 (M0 Should) → US-026 (M1 Should); REQ-UI-018 (M0 Should) → US-111 (M1 Should). Conversely REQ-DATA-014, REQ-SEC-008, REQ-QUOTE-004 (M1 Must) are delivered by M0 Must stories (US-052, US-046, US-156) — harmless but the matrix should say so. US-239 is a Must story bundling REQ-PICK-010 (Should, D-014 drop-off list) with REQ-PICK-013 (Must) although PICK-013 is unreachable without PICK-010; D-014 says drop-off is Should, so REQ-PICK-013 should be Should or the drop-off confirmation split from pickup confirmation.
- **F3 (minor, hygiene):** GAP-B-27 has no ASSUMPTIONS row; 13 REQ rows say ASSUMED without a GAP id (listed above); 6 assumptions have no validation method; 6 Must stories lack the `Permission path: not applicable` marker although an equivalent scenario exists.
- **F4 (trivial, rendering):** `NFR.md:214` NFR-MAINT-002 contains unescaped pipes inside a code span (`packages/pricing|audit|authz|carriers`), which breaks the Markdown table row and drops its Status cell when rendered or parsed.
- **F5 (risk, buildability):** 290 stories (215 Must), 109 S + 181 M, 2 007 Gherkin scenarios, 430 REQs, 90 NFRs. Using the README sizing (S ≤ 2, M ≤ 4 dev-days) the upper bound is ~940 dev-day-equivalents for one run with MAX_PARALLEL_DEVELOPERS = 4. The Must share (74%) is justified by the per-feature RBAC/audit/RLS/i18n/a11y obligations, but the plan has no per-epic "demo-critical" subset below Must to fall back on when the escalation ladder (CLAUDE.md §7 step 3) needs to re-scope. STATUS.md risk 1 already names this.
- **F6 (gap, traceability of NFRs):** 88 of 90 NFRs are not referenced by any story (only 2 "Linked NFRs" lines exist) and `traceability.md` has no NFR section. Acceptable at G1 (NFRs carry their own verification method and phase), but G2 requires a mechanism per NFR and G3 requires evidence per NFR, so the matrix must gain NFR rows.
- **Not a G1 concern (recorded):** the M1 "real sandbox label" demo is deferred by human decision D-003 as COND-SANDBOX-DEMO; the PRD §6.2 scenario is tagged accordingly and G3/G4 judge on Mock + fixtures.
