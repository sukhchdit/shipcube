## Conventions

- **ID scheme:** `REQ-<AREA>-NNN`, three digits, starting at 001 within each area. IDs are never reused; a withdrawn requirement keeps its ID and is marked `WITHDRAWN`. Domain rules are `DR-Axx` (Part A, Appendix A) and `DR-Bxx` (Part B, Appendix C); edge cases are `EC-Axx` (Appendix B) and `EC-Bxx` (Appendix D). All are cross-referenced from requirements by ID.
- **Exactly one milestone and one MoSCoW value per requirement.** Every REQ in this file is tagged with exactly one of M0/M1 and exactly one of Must/Should/Could.
- **Milestones:** M0 = Foundation (release slice R0, `v0.1.0-m0`: M0 Must and Should). M1 = Customer MVP (release slice R1, `v0.1.0`). A requirement is tagged with the first milestone in which it must be demonstrable.
- **MoSCoW (D-029):**
  - **Must** = on the critical path of the M0 or M1 exit demo, or a non-negotiable cross-cutting obligation (RBAC on every route, audit on every route, tenant isolation, i18n en/es/fr, WCAG 2.2 AA, responsive layouts). A Must that fails blocks the gate.
  - **Should** = brief-listed M0/M1 functionality that the exit demos do not need. Delivered unless capacity forces a defer; a deferred Should becomes a tracked backlog item.
  - **Could** = conveniences and items whose full version arrives in M2–M5. Built only if everything else is done.
- **Standing obligations applied to every area:** every route declares a permission, an audit descriptor and a validation schema in route metadata (REQ-RBAC-005); every tenant-owned table carries `org_id` with RLS (REQ-RLS); every user-visible string is an i18n key with en/es/fr values (REQ-I18N); every screen implements the six screen states (REQ-UI). Area sections below do not repeat these unless the area adds a specific behaviour.
- **Error codes** quoted in Notes (for example `AUTHZ_DENIED`) are the stable `code` member of an RFC 9457 problem+json body (REQ-API-005).
- **Seams** (brief "LATER" or later-milestone hooks) are marked "seam" and must exist as data model or interface only, with no user-facing behaviour.
