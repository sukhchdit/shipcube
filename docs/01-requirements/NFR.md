## How to read this document

- Each category is a section `## NFR-<CAT>` with one table. Each row is one measurable requirement with the ID `NFR-<CAT>-NNN`.
- **Target.** A number or a boolean. A target taken from the brief is kept verbatim. A target I added is marked **(default)**, which means "industry-standard default proposed by the requirements analyst; the product-manager may change it". Every invented number is logged in the handback gap list as `GAP-N-nn`.
- **Measurement method.** Names the tool, where it runs, and the pass condition. "CI" means the GitHub Actions pipeline on `sukhchdit/shipcube`. "Compose" means the local `docker compose` stack (staging for this run, D-002).
- **CI evidence model (D-ORCH-001, D-044).** The repository is private on the GitHub free tier, so "in CI" is satisfied in one of two ways: (a) the hosted **PR fast lane** (install, lint/format, typecheck, unit + coverage, contract, build, Gitleaks, dependency audit, Semgrep) on every PR; or (b) the **heavy suites** (integration with Testcontainers, generated RBAC/audit/RLS suites, Playwright e2e, k6, ZAP, Trivy image scans, compose smoke, restore rehearsal) run in the full `ci.yml` on `main`/`workflow_dispatch` at wave ends and before G3/G4, and otherwise locally via test-runner on Docker Desktop with the summary and JUnit/coverage reports committed under `docs/05-quality/`. Either form is acceptable evidence for the gate; the verification report states which was used per NFR. Node 24 LTS is the runtime everywhere (D-ARCH-001).
- **Verified in phase.** The earliest phase that must produce the evidence. `P5` = Build (per-task or per-PR CI), `P6` = Verification (gate G3), `P7` = Release (gate G4), `M5` = Production readiness milestone (outside this run).
- **Reference host (default).** Performance numbers are measured on a developer machine with at least 8 cores and 16 GB running the full compose stack (the primary host under D-ORCH-001), or on a GitHub-hosted `ubuntu-latest` runner when the full workflow runs on `main` (private-repo runners are 2 vCPU / 7 GB; results from them are reported, not gated). The host spec and CPU utilisation are recorded with every result.
- **Mock latency profiles (default)**, used wherever a test needs carrier behaviour:
  - `fast`: per-call latency p50 300 ms, p95 900 ms.
  - `slow`: p50 2.5 s, p95 3.8 s.
  - `hung`: never responds.
  - `error`: always returns HTTP 500.
  - `flaky`: 30% of calls return HTTP 500.
- The brief's rule "No silent stubs" (§13.5) applies to NFRs. A target that this run cannot reach is marked PARTIAL or DEFERRED with the evidence it does produce. It is never silently dropped.

- No AWS account and a $0 budget (D-002), so RDS, ALB, WAF and CloudWatch cannot be exercised.
- No carrier sandbox credentials (D-003), so the Mock carrier plus recorded or synthesised `nock` fixtures drive all automated tests. Live sandbox runs are opt-in.
- Stripe runs fixture-backed in test mode when no key is present (D-011, D-003).
