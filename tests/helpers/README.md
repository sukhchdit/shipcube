# Test harness (TASK-276, T-QA-03)

Shared support for the Jest projects. Everything here is deterministic: fixed clock, seeded RNG, derived sentinels.

| Piece                                              | Use                                                                                                                                                                                      |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tests/factories` (`createFactories({ seed })`)    | Typed records for user, organisation, membership, quote, shipment, order, payment, document. E-mails end in `@<run>.test.invalid`; `<run>` differs per seed, Jest worker, `TEST_RUN_ID` and test file (lane B runs database suites in band, so the file keeps two suites with one seed apart). Related ids (`membership.orgId`, `quote.orgId`, `shipment.quoteId` ...) are independent placeholders: pass overrides when a test needs a coherent graph. |
| `tests/helpers/fake-clock.ts`                      | `createManualClock()` for injected clocks. For Jest modern fake timers pinned to a fixed instant use `useFakeClock()` at describe level (installs before and always restores after each test, also when it throws) or `withFakeClock(fn)`; `installFakeClock()` is the manual primitive.                                                  |
| `tests/helpers/sentinels.ts`                       | Fixed sentinel PII and secret values (name, e-mail, tax id, token, secret, Luhn-valid `4242` PAN), derived at load time, never written out as literals.                                     |
| `tests/helpers/leakage-scanner.ts` | `scanForLeaks`, `expectNoLeaks`, `createLogCapture`, `useLeakageGuard(options, register = afterEach)` (a hook that fails a test whose captured logs, including a trailing line with no newline, contain a sentinel, then clears the capture). Finds the value in any letter case, percent-encoded, JSON-escaped, hex, and base64/base64url at every byte alignment (inside JWT segments, `Basic` headers, base64 JSON); a PAN grouped by up to two spaces, NBSP, dots or dashes. Walks own, non-enumerable and symbol properties (Error `cause`, AggregateError `errors`), Map, Set, Headers, URLSearchParams, typed arrays and ArrayBuffer, and `toJSON()` (URL, Date); going deeper than `maxDepth` is a `DEPTH_LIMIT` finding. Findings carry ids and paths, never the value, not even a sentinel used as a key (`<key N>`). |
| `tests/helpers/mock-scenario.ts`                   | `mockScenario({ latencyMs, fail, error, ratesEmpty, track })` builds the `X-Mock-Scenario` header and the `MOCK:` customer reference; `parseMockScenario` mirrors the API rules.          |
| `apps/api/src/platform/db/query-counter.ts`        | Prisma query counter: `withQueryCounter(client, counter)` plus `counter.middleware()`; read `counter.requests()` and call `assertQueryBudget(report, 12)` (NFR-PERF-006).                  |

## Running suites

- `npm run test:unit`, `test:integration`, `test:api` and `test:generated` select one Jest project each (`unit` and `unit-dom`, `integration`, `api`, `generated`).
- The `generated` project takes the `*.api.test.ts` / `*.int.test.ts` suites under `tests/generated/`; `integration` and `api` ignore that folder, so a generated suite never runs twice. A plain `*.test.ts(x)` there (route registry, contract drift) is a lane A unit test. `tools/repo/jest-projects.test.ts` pins the mapping.
- The query counter is a test seam: only test files and `prisma/tests` may import it (the `db-test-seam` boundaries policy and `tools/repo/test-seams.test.ts`).
- **Put the test path BEFORE `--selectProjects`.** The flag is variadic: `jest.js --selectProjects integration <path>` treats the path as a second project name and runs every integration suite. Use `jest.js <path> --selectProjects integration`; `npm run test:integration -- <path>` has the same problem because the script ends in `--selectProjects integration` (SPK-03 F-12).
- Tests that need a directory create it with `mkdtemp` and delete only that directory (D-ORCH-038).
