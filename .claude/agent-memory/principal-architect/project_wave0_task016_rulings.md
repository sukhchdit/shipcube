TASK-016 (PR #11 @557aada, RLS foundations) rulings on 2026-11-13: `docs/03-architecture/rulings/wave-0-task-016-rulings.md`; D-ARCH-071..074; data-model §4.1/§4.2/§4.3/§4.4/§4.6/§8.3/§8.4/§12 A19; ADR-0005 am. 10 item 9 + "Round-3 corrections" bullet; platform.md RDS paragraph; risks.md v1.6 R-ARCH-26; 12 `plan-data.mjs` blocks.

**Non-obvious outcomes to defend in conformance reviews:**
- **Migration files are not atomic.** Prisma 7.10.1 `migrate deploy` runs a file's statements one at a time, outside any transaction block (PR #11 `prisma/README.md` "Rule 5"). Consequences: rule 11 = session-form `SET lock_timeout` only (`SET LOCAL` is a warning-only no-op outside a tx block; `RESET` at EOF when raised above the migrator role default 3 s); rule 9 b = `GRANT … TO platform_app` after `ENABLE`+`FORCE` (+policies); rule 15 = `SET ROLE platform_definer … RESET ROLE` is the **only** definer form (the "grants before `OWNER TO`" alternative of ADR-0005 am. 10 item 9 is withdrawn; `OWNER TO platform_definer` in migrations fails; unreset role at EOF fails; `handedOver` branch removed; fixture `definer-grants-before-owner-to` flips to failing); new rule 17 = `down.sql` `IF EXISTS` forms; §8.4 prefix-reversibility check in `up-down-up.ts` (TASK-024). `migrate resolve --rolled-back` IS legitimate for a genuinely FAILED prefix (the P3012 restriction concerns successful migrations). Principle: "every prefix of a file leaves the schema safe".
- **DR-A14 special policies = named renderer templates**, never an exemption file: manifest field `policySet: dr-a14-users | dr-a14-memberships | dr-a14-organisations` (accepted only on the same-named table; users USER_OWNED, memberships/organisations TENANT); the set replaces `user-owned` (users) / `tenant` (organisations) and adds `own_read` to memberships; exact atoms `id = platform.app_actor_id()` / `id = platform.app_org_id()` and two exact `EXISTS` strings; **positive status lists** — `p_users__org_member_read` uses `m.status IN ('INVITED','ACTIVE','SUSPENDED')` (was `<> 'REMOVED'`, fail-open on enum growth), organisations keeps `('ACTIVE','SUSPENDED')`. Rule 9 a: every `CREATE POLICY` must equal the renderer output. C3 derives the expected set from manifests + renderer (rendered on a rolled-back probe, deparsed), asserts a keyed helper atom in every `TO platform_app` predicate, and the recursion invariants (memberships: no subquery; users/organisations: `public.memberships` only). Tooling owner **TASK-024** (gained locks `prisma-rls`, `prisma-core`); TASK-037 (memberships, organisations, `app_is_operator` template) now depends on TASK-024; TASK-049 creates `users` and ships its set. Security-analyst sign-off on rendered policies = merge condition of both. Open: `memberships.user_id → users(id)` FK ordering (users lands 3 batches later) — flagged on TASK-037 dod for senior-developer.
- **`GRANT EXECUTE ON platform.app_actor_id() TO platform_definer`** accepted (definer body calls the helper; PUBLIC has no EXECUTE): issued by the migrator BEFORE `SET ROLE` in the `app_is_operator` migration; C11 helper expectation gains `platform_definer` when TASK-037 applies the template.
- **Helper bodies qualified** (`pg_catalog.current_setting`, `OPERATOR(pg_catalog.~*)`, `pg_catalog.decode`, `::pg_catalog.uuid`) — inlined SQL resolves through the caller's path; adopt in the UNMERGED helpers migration (afterwards = immutable → CREATE OR REPLACE migration).
- **`lc_messages = 'C'` role backstop** for `platform_app` in `02-role-backstops.sql` (unmerged in PR #11; fallback `03-role-locale.sql` by TASK-021): `mapDbError`'s 403-vs-500 split reads the English RLS prefix; C13 = five `platform_app` rows; SPK-08 checks RDS (`lc_messages` is SUSET).
- **statement_timeout layering** (platform.md): role backstop 30 s (non-pool sessions only), pool startup `DB_STATEMENT_TIMEOUT_MS` 25 s (PR #9), per-tx `DB_TX_STATEMENT_TIMEOUT_MS` 5 s — nothing is "set by migration".
- **Routing:** T-83 lint `platform/no-external-calls-in-tenant-tx` → TASK-020 (lock `lint` free in batch 0.6; TASK-113 extends the list); C6/C7/C14 → TASK-021 (C7 via new manifest flag `immutable`), C8/C9 → PR #11 else TASK-024, C10 → TASK-028; PR11-SEC-09 wiring items 1–6 + D-ORCH-014 (a)–(f) on TASK-016 as merge conditions, verified by TASK-020 at the `tx` slot; TASK-025/043 SYSTEM writers take `TenantDb` only; TASK-019/021 replace readiness stubs (`part: US-012`); TASK-015 carries C-1 (`SPK03_BENCH=1`, delete spike file + its `TENANT_CONTEXT_EXEMPTIONS` entry in one commit).
- **Deliberately NOT created:** a new `late` task for RLS tooling (gen.mjs supports `late:true` without renumbering, but it would disturb the orchestrator's dispatch state); TASK-024 was the right specialist/batch instead.

**Process lessons:** (1) PR #11 code is read from the main checkout with `git show 557aada:<path>` after `git fetch` — never touch the worktree. (2) Validate the generator by parsing the JSON (`errors`, `warnings`) and prove ID stability with `diff <(cut -d, -f1,5-9 HEAD) <(cut … working)` — only the intended dependency line should differ; a full-row diff shows exactly the edited tasks. (3) Adding `part:` stories to tasks is safe when another task fully owns the story (no generator warning). (4) `ALTER ROLE … SET` of a SUSET parameter needs superuser — fine locally, verify on RDS via SPK-08 before relying on it. (5) The scratchpad persists across sessions with stale `decisions-append-*.md` files — always use a fresh, specific name and guard the append with a `grep -q` for the first new decision ID.
