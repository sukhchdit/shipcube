Wave-0 batch-3 rulings (2026-11-12; `docs/03-architecture/rulings/wave-0-batch-3-rulings.md`; D-ARCH-057..061 + D-ARCH-062 revision; ADR-0010 am. 11, ADR-0005 am. 10, ADR-0008 am. 2, ADR-0018 am. 8; data-model §1.7/§3.3/§4.3/§4.5/§7.3/§8.3 r10/§9.2/§12 A17; risks.md v1.4 R-ARCH-25).

**Non-obvious outcomes to defend in conformance reviews:**
- **UPS PDF labels come from Label Recovery, not conversion.** Official pinned spec `UPS-API/api-documentation@fd57ca9` `Shipping.yaml`: Ship `LabelImageFormat.Code` = GIF|ZPL|EPL|SPL (:11251-11263); Label Recovery = GIF|**PDF**|ZPL|EPL|SPL (:13479-13496). `CarrierAdapter` gained optional `recoverLabel(ref, formats, ctx)` (idempotent, retryable, transactional pool; UPS/Mock true, FedEx/DHL false). UPS declares `labelFormats = [PDF_4X6, ZPL]`; `createShipment` returns `labels: []` for PDF; the saga's step 4 (ADR-0014) calls `recoverLabel`. **No pdfkit / raster decoding in `packages/carriers`** — pdfkit belongs to the documents module (ADR-0003/0019). My first draft (in-house GIF decoder in carriers) was overturned by the PR #6 code review M1; the contingency (R-ARCH-25) is a converter in the documents module. No npm GIF decoder passes the 18-month rule (`omggif`/`gifwrap` 2022-06, `@jimp/gif` 2024-02, `gifuct-js` 2025-01; `jimp` drags them; `sharp` = optionalDependencies binaries dropped by `--omit=optional`).
- **DHL `cancelShipment` → `CAPABILITY_NOT_SUPPORTED`** (`capabilities().operations.cancelShipment = false`): shipment CANCELLED, pickup cancelled, `carrier_void = UNSUPPORTED`, label VOIDED Platform-side, refund proceeds. No DC story affected (US-196/216/229/261 Should non-DC; US-237 works). PM to reword REQ-BOOK-029/REQ-DOC-013/REQ-CARR-003/REQ-CARR-019/REQ-CARR-016.
- **Egress allow-list is derived, never env-configured:** adapters export `EGRESS: { sandbox, production }` of `EgressRule { origin, pathPrefixes, tier }`; exact origins, no wildcards (FedEx ETD sandbox host contains "prod"); DHL sandbox/production differ by path (`/mydhlapi/test/`); production rules only under `APP_ENV=production`; carrier-supplied URLs never dereferenced.
- **Token lifetimes:** `ttl = clamp(Number(expires_in) − CARRIER_TOKEN_REFRESH_SKEW_S, 0, CARRIER_TOKEN_TTL_MAX_S)`; missing → uncacheable, never a default. Token-endpoint failures: negative cache 60 s, per-carrier token bucket, FedEx 403 → carrier-wide 600 s cool-down (SEC-TC-68).
- **ADR-0005 am. 10 (SPK-03 GO):** cost = one extra round trip + ~0.1 ms server-side (W-1); nested `tx.$transaction` = SAVEPOINT keeps context, hazard = root client or nested `withTenantTx` (W-2). Binding on TASK-016: run-time `TenantDb` Proxy omitting `$transaction`/`$queryRawUnsafe`/`$executeRawUnsafe`; AsyncLocalStorage `NESTED_TENANT_TX` guard; `set_config(name,$1,true)` only with literal true + validated strings; `mapDbError` keyed on `driverAdapterError.cause.originalCode` (42501 WITH CHECK → 403 AUTHZ_DENIED + `rls_write_rejected`, never echo; P2028/55P03/40001/40P01/57014 → retryable 503); `''` ≡ NULL only for equality predicates → renderer predicate allow-list + C3 scan; definer functions under `SET ROLE platform_definer` (grants before OWNER TO otherwise — migrator's INHERIT FALSE membership); linter rule 15 mandatory; GUEST_CAPABLE no-de-claim trigger (data-model §4.3); per-tx timeouts vs role-setting drift. **C-1** (end-to-end delta on ubuntu-latest) owner TASK-016 via the hosted `security-integration` job + `SPK03_REPORT` artifact (benchmark behind `SPK03_BENCH=1`); performance-engineer verifies at P6.
- **ADR-0008 am. 2:** Super Admin = every role-assignable permission (webhook `signatureOnly` perms held by no role); `selfService` set (`session:manage`, `notification_pref:manage`, `notification:read`) held by all 17 roles and carved out of the Viewer/Auditor invariants (mirrors PM's D-058); `isAuditPermission` keyed on the key's resource segment, `category === resource` except an explicit map; reserved `:any_org` seams; dead-permission rule; file names = `permissions/<ctx>.ts`, `roles.ts`, `generated/role-permission-matrix.md`. Seeding = generated versioned migration pinned by SHA-256 (`SEED_MIGRATIONS`), `ON CONFLICT ("id")`, `artefacts()` throws for version > 1 until a delta renderer exists; REQ-RBAC-013 `CONFIG_CHANGE` = post-migrate **reconciler** (`SYSTEM_JOB`, digest vs `reference_dataset_versions('authz_matrix')`, baseline back-fill) in TASK-221 (now depends on TASK-023). Rule 10: insert-only seed = `data-changing: no`; DELETE/UPDATE/upsert/MERGE = yes. `privacy:export` scoping confirmed by RLS inside `withTenantTx`.
- **ADR-0018 am. 8:** every refusal keys on `APP_ENV` (Mock refused at `APP_ENV=production`, allowed in staging behind HMAC); `NODE_ENV=production` is a staging/production deployment requirement enforced by images + TASK-014 preflight (NODE_OPTIONS/PG*/NODE_ENV refusals, exit 78); ECS second signal (`ECS_CONTAINER_METADATA_URI[_V4]` present → `APP_ENV` local/test refused); `APP_ENV` has no `benchmark` value (bench image refuses unless local/test).

**Process lessons (important):** (1) Code and security reviews of the same PRs were published *while* I was ruling (D-058, D-SEC-PR8-01, D-ORCH-011, PR #6/#7/#8 reviews) — before finishing a rulings batch, re-grep `docs/05-quality/{reviews,security}` and the DECISIONS.md tail for the PR numbers, and read any "§4a / for principal-architect" sections; the orchestrator's D-ORCH-011 explicitly routed review deltas to my ADR amendments. (2) DECISIONS.md is append-only: a superseded decision gets a new entry (D-ARCH-062 "supersedes D-ARCH-057 item 3"), never an edit. (3) Verify vendor API facts against the *pinned* official spec file (curl raw GitHub at a commit SHA into the scratchpad, grep) rather than a README summary — the "no PDF" claim was true for Ship only. (4) `pdfkit` embeds JPEG/PNG only; it lives in the documents module — do not move document generation into `packages/carriers`. (5) `npm view <pkg> time.modified license --json` is the quick 18-month-rule check; `WebFetch` on a 600 kB YAML truncates at 100 k chars — download and grep instead.
