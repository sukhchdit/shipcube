**Non-obvious outcomes to defend in conformance reviews:**
- **The audit stream lock is the head row's `SELECT … FOR UPDATE`, not `pg_advisory_xact_lock`** (D-ARCH-085). Lock + head read + `clock_timestamp()` = one round trip; design rule "≤ 2 round trips from lock grant to COMMIT (CTE append-and-advance, COMMIT); nothing else under the lock; no lock after the head lock". Consequences: `platform_app`'s UPDATE grant on `audit_stream_heads` is load-bearing; **no FK may reference `audit_stream_heads`**; OI-21 (hashtext slot sharing) is closed. Reviewers must reject any audit writer that issues a statement between the lock and the CTE, or uses `RETURNING` on the CTE insert.
- **Short audit `lock_timeout` is set inside the lock statement** via `WITH lt AS MATERIALIZED (SELECT set_config('lock_timeout', $2, true)) … FOR UPDATE OF h` (`DB_AUDIT_LOCK_TIMEOUT_MS` default 250); TASK-030 must PROVE it with a held-row test — fallback is a separate `SET LOCAL` round trip. 55P03 → **503 `AUDIT_LOCK_TIMEOUT` retryable** (new code) vs 500 `AUDIT_WRITE_FAILED`; both roll back the business tx (O4 argument: nothing exists without its entry; clients retry via Idempotency-Key).
- **Vault = two statements before the lock** (multi-row `INSERT … SELECT FROM unnest(...) ON CONFLICT DO NOTHING`, then a separate lateral token lookup): `DO UPDATE … RETURNING` is impossible because the vault's BEFORE UPDATE guard raises; the lookup needs a fresh snapshot. The token-lookup plan must be EXPLAIN-asserted against ≥ 100k vault rows (spike saw PG CPU 95–114 % unattributed).
- **Two grammar-level qualification exceptions** recorded in data-model §8.3: multi-arg `unnest(a,b)` (`pg_catalog.unnest(a,b)` = 42883) and `extract(epoch FROM x)` (`pg_catalog.extract(epoch FROM …)` = syntax error; `pg_catalog.extract('epoch', x)` is fine). No linter/C-series rule may flag them.
- **Pool protection is admission control, not a second pool** (D-ARCH-086): `withTenantTx` admits ≤ `DB_TENANT_MAX_CONCURRENT_TX` (default `max(2, floor(DB_POOL_MAX/2))`) per orgId (`anonymous`/`operator` keys) BEFORE checkout, FIFO wait `DB_TENANT_ADMISSION_WAIT_MS` 250 ms, depth 2×cap, overflow 503 `SERVICE_UNAVAILABLE` reason `TENANT_CONCURRENCY_LIMIT`. Owner TASK-025 (files under `apps/api/src/platform/db/`, config keys without the `pkg-config` lock — D-ORCH-020 precedent); worker twin TASK-047 (not yet on its sheet — add at next fold). Rationale to repeat: a lock_timeout alone bounds wait time per connection, not the number of connections a hot tenant holds (60 rps × 250 ms ≈ 15).
- **Hot-tenant sub-streams (lever b) deferred with a trigger**: adopt only if TASK-280's clean 300 rps Linux run still shows hot-stream lock-wait p95 > 5 ms or Δp95 over budget; needs a superseding amendment (changes `stream_id ≠ org_id`, verifier, checkpoint heads, viewer).
- **Zero hash**: `decode(repeat('00', 32), 'hex')`; `'\x' || repeat('00', 32)` is text (42804). PR #24's bootstrap was already correct — checked via `git show origin/<branch>:prisma/bootstrap/10-audit.sql`; D-ORCH-031 (3) closable as clean.

TEST-STRATEGY §7.10 `audit-ab` row still says "`APP_ENV=benchmark` build" — routed to qa-lead, not edited.

**Process lessons:** (1) Delegating requirement wording to product-manager in the background with the exact proposed text works well — it returns final cell text plus inconsistencies it deliberately left (route those). (2) Read PR-branch files with `git show origin/<branch>:<path>` after `git fetch`; verify a suspected defect in a sibling PR the same way before flagging it. (3) The Write tool refused a brand-new scratch file once with "File has not been read yet" — retry under a different filename. (4) Column-level task-map.csv diff script (split respecting quotes) is the quickest proof that only refs/title/nfr changed. (5) Other agents' review records (e.g. `PR-0027-...-security-review.md`) appear in `git status` mid-task — never list them as mine.
