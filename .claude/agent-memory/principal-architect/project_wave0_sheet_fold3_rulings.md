- The guard exposed two incomplete data-model sketches (§6.4 `number_sequences` allocation, §6.2 `idempotency_keys` takeover/complete: no `version`/`updated_by`); the §4.4 column grant for number_sequences already listed the stamps. Fixed; any future raw statement on an STD table must stamp (§7.6 item 4). Outbox relay `updated_by = $system` only passes if its tx context carries SYSTEM_ACTOR_ID.

No new security event (api/README §13 + SECURITY_EVENTS must change together, PR #20 SEC-TC-63).
- **§7.6 as implemented:** relation fields refused incl. `connect`/`disconnect` (PR26-SEC-01, PR #26 fix cycle), equal-orgId tolerance on create/upsert.create only, `updated_at` app clock vs `created_at` DB clock (skew; order by `version`), extension innermost.
- **§5.2 (PR #24 R2-n1):** drop-the-squat works only for type/domain/composite/sequence/procedure/aggregate; table/view/matview/index/function squats need a superuser to disable `platform_audit_ddl_guard_drop`, drop, `ENABLE ALWAYS` in one tx. - **Anchor sink (D-ARCH-094, ADR-0021 am. 2):** "worker PutObject only" never held (the hourly verifier reads the sink) → PutObject + GetObject + ListBucket on `anchors/`; sink = `Pick<ObjectStorage, putIfAbsent|head|get>` with its own credential/bucket as worker-only `anchorSink` (never documents `storage`); TASK-116 owns the lost-response→412→`created:false`→compare `head().sha256` rule (mismatch = ANCHOR_SINK_MISMATCH, never overwrite); AWS 409 ConditionalRequestConflict retryable.
