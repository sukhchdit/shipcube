Ruling (2026-11-13, docs/plan only, nothing committed by me): ADR-0005 am. 11 (items 17-21), ADR-0003 and ADR-0008 am. 4 appended, api/README 8/10/15 (row 12), ARCHITECTURE 7.1-7.3 notes, data-model 7.7 + A26, nfr-strategy PERF-001, risks.md v1.10 (R-ARCH-29), plan-data.mjs (19 sheets, 281 tasks, 0 errors), DECISIONS D-ARCH-106 (T-83), D-ARCH-107 (auth), D-ARCH-108 (owners).

**Non-obvious outcomes to defend in conformance reviews:**
- **`prepare(ctx)` without DB access was rejected.** Every synchronous external call needs a tenant-scoped read first (RLS 404 before any carrier/gateway call, price snapshots, attempt counter). Replacement: descriptor phases `load` (short READ ONLY tx) -> `call` (no tx, no handle, AbortSignal, deterministic idempotency keys derived from `loaded`) -> `handler` (the only write tx + audit) -> `afterCommit` (best-effort, drained at shutdown). Outbox stays the default home. Implementation = TASK-020 part 020-C (third PR, no new ID), due before batch 1.3, hard stop before TASK-044; NOT in PR #32 (round 1 already large, needs the 020-B runner for the read-only proof).
- **T-83 lint roots:** R1 withTenantTx callbacks; R2 `handler` of the defineRoute literal unless `transaction: 'none'` literal (spread/non-literal = tenant; fixtureRoute defaults none); R3 same-file named handler; R4 `load` (with 020-C); R5 whole-file `txFiles` (platform/audit, outbox/writer.ts, packages/audit/src/store); **R6 any function whose parameter type annotation names TenantDb/AppDb/AppTransactionClient** — needed because routes get an INJECTED controller from the module index (`handler: controller.cancel` is unresolvable); type-name based on purpose (a `db: DatabaseRuntime` readiness param or `ctx: CarrierContext` must not be a root; `RouteContext` deliberately not in the default list because transaction-none health handlers are typed with it). I first wrote "report unanalysable handlers" and dropped it after reading the layering rule (routes -> controller -> service -> repository, ADR-0003 / eslint.config.mjs lines ~264-291).
- **Hatch + ratchets:** only `transaction: none` (public tenancy, audit NONE); route-metadata pins the set of none operationIds; unit test greps eslint-disable naming the rule; runtime twin = API lanes with `DB_TX_IDLE_IN_TRANSACTION_TIMEOUT_MS=1000` (key exists, min 1000, prod stays 15000) + Mock `latency` scenario.
- **Route auth = closed set of credential kinds** `anonymous|session|refresh-cookie|quote-token|signature`; six allowed sets; scalar sugar kept (no fixture churn); `permissionAuthenticated` required exactly on dual-mode routes; `refresh-cookie` is a separate kind because refresh/logout/csrf are called with an expired/absent access token (a generic bearer authenticator would break refresh); `Principal.credential` added, `Principal.authenticated` keeps meaning "user actor" (guest/provider principals have authenticated false -> tenantContextOf unchanged, closes code-review n3). C2 implemented as a CREDENTIAL GATE (`route.auth` contains `principal.credential`, `public` included), not the review's literal `principal.authenticated` (that would reject every guest and signature route). Missing quote token => 404 (A-078), not 401. Verified against openapi.yaml: 133 ops = 29 anonymous, 95 session, 3 refresh-cookie, 3 signature, 1 anonymous+session, 2 session+quote-token, zero rule violations.

**Process lessons:** (1) `security: []` in OpenAPI means anonymous — my first verification script reported 29 false AUTH_SET hits until I mapped an empty list to `anonymous`; always run a "does the closed list fit the real contract" script before ruling. (2) HEAD moved while I worked (PR #20 merged, orchestrator appended DECISIONS entries): append with `cat >>` after a grep guard and re-run `git log`/`git diff --stat` before reporting. (3) The session scratchpad is shared with earlier sessions (stale scripts) — put new work in its own subdirectory (t83/). (4) Content with backticks goes in separate files read by the edit script; plan-data strings must have no apostrophes or backslashes (write `transaction: none`). (5) `gen.mjs --stats` writes stats.json only on the `--write` path, so key-to-ID lookups come from task-map.csv titles instead.
