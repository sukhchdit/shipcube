**Non-obvious outcomes to defend in conformance reviews:**
- **Declared-kinds rule (D-ARCH-109).** The contradiction was inside my own ADR-0008 am. 4 item 4: its first sentence ("only the kinds the route declares are considered") is the design; the stub clause and (e) ("any request that presented a credential") over-reached because a stub that verifies nothing cannot tell stale from current. Cookie `Path` stays `/` (`__Host-` requires it, T-17). Refresh cookie = three routes (`refreshSession`, `logoutSession`, `getCsrfToken`; ADR-0006 am. 1 had omitted csrf); `Authorization` on `[anonymous]`/`[refresh-cookie]`/`[signature]` is ignored, valid or not ("a present bearer must be valid" only for the three sets containing `session`); a `[session]` route never accepts the cookie (CSRF reach = 3 routes). **I deliberately did NOT adopt the security owner note "cookie still makes the response private, no-store"**: reference lists are `public, max-age=3600` and every signed-in browser carries the cookie, so marking on presence kills HTTP caching for all signed-in users. Generic any-credential test stays only for pre-route problems and errors before the authn slot. Both cookies on one request (Compose shares `localhost` across ports): read the one matching the request app, ignore the other unevaluated.
