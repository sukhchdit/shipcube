**Non-obvious outcomes to defend in conformance reviews:**
- **Admission classes (D-ARCH-120):** `auth` is DERIVED from `route.rateLimit ∈ {auth, email-send}` in the pipeline tx slot (not declared twice); `guest:<hash>` per guest session; `public` otherwise. Ceiling `DB_ANON_MAX_CONCURRENT_TX` = tenant cap (so ADR-0007 am. 10's pool argument stands). Reserves via `inflight(k) < C − Σ_{j≠k} max(inflight(j), reserve(j))` — defaults auth `max(1, floor(C/2))`, guest 1 if C ≥ 4 else 0, `auth + guest ≤ C − 1` so public always runs. Fixed partitions and cap-without-ceiling were rejected. Owner TASK-284 `admitcls`, a DAG dependency of TASK-052 (not an honour-system due date). Per-client public sub-key = recorded lever, not scheduled.
