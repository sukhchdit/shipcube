**Non-obvious outcomes to defend in conformance reviews:**
- **Companion carve-out (D-ARCH-113 (1)).** ADR-0008 am. 5 table already calls `X-Quote-Token` on claimQuote/saveQuote/createShipment "a declared companion header the handler checks", and openapi declares it there as the `QuoteToken` header PARAMETER (not the `quoteToken` scheme). So the PR38-SEC-03 rule refuses credential header names in `schema.headers` everywhere EXCEPT `x-quote-token` on routes whose auth is exactly `[session]`; route-metadata gets companion parity instead of the blanket `PIPELINE_HEADERS` entry. Refusing it everywhere would have broken the existing design.
- **Header list lives in `@platform/shared` credentials.ts (`CREDENTIAL_HEADER_NAMES`), pinned by a parity test against `securitySchemes`** — not a hard-coded constant in define-route.ts as the analyst proposed (drifts when a provider is added; the shared file is CODEOWNED since PR #38 and feeds `presentedKinds`). Includes `x-csrf-token` and `x-reauth-proof` (proof headers, header parameters not schemes, listed by hand).
- **Signature authenticators cannot use `presentedKinds` for their own header** (`signature` is not a presentable kind): the contract says they read their signature header themselves only on `[signature]` routes and never consult authorization/cookie/x-quote-token; `markCredentialsRead` still called with the decision.

**Process lessons:** (1) The plan-data "no apostrophes" convention has one exception: the route block has an existing string with an escaped `\'` (`["\']`), so a quote-aware scanner must skip the char after a backslash or it inserts inside the string (my first run did). (2) Applier pattern that worked: lines.mjs (texts) + apply.mjs (block range by next `\n{k:'`, field scan outside strings, append before `]`, import both modules and deep-compare all fields except a/x prefix; `--commit` only after 0 problems), then `gen.mjs .` and `gen.mjs . --write`, then a column-level CSV diff via a small node CSV parser (not line diff). (3) `git show origin/<branch>:path` with a `;` right after the branch name breaks the revision parse — put the path in a variable or quote. (4) Check openapi before ruling on a header: a `QuoteToken` header PARAMETER and a `quoteToken` SECURITY SCHEME coexist and mean different things.
