**Non-obvious outcomes to defend in conformance reviews:**
- **Blocker was TS layout, not lint.** `apps/api` has `rootDir: src` (TS6059/TS6307) and `tools/tsconfig.json` lists platform/db files one by one (`files`), so any new platform/db module (`generated.ts`) must also be added there. A bare workspace specifier that resolves to `prisma/generated/**` is classified by the resolved FILE (category `prisma-generated`); existing policies already refuse services/other packages and allow `platform/db`. A `module: { source }` selector matches NOTHING for workspace specifiers.
- **Shape:** `prisma/client/tsconfig.json` (composite, rootDir `../generated/prisma`, outDir `../dist/client`, maps off) referenced by apps/api and tools, NOT in root tsconfig (root-scripts.test AT-US-001-04 pins the list: workspaces + tools + tests/api + tests/contract-stubs). `@platform/prisma` exports only `./client`. Generator options pinned because the CLI infers `moduleFormat`/`importFileExtension` from the nearest tsconfig. `@ts-nocheck` always written (tsNoCheckPreamble hard-coded on in 7.10.1) but declaration emit still runs: TS2883 for non-async functions returning PrismaPromise.
- **Value vs type:** value import only in `apps/*/src/platform/db/**` (+ prisma/**, tools/db, tests); repositories and the two PLANNED_PRISMA_FILES type-only; `generated.ts` joins category `db-root-client`; `AppDb`/`AppTransactionClient`/`Prisma` leave platform/db and `@platform/api/runtime` as types only (so `Prisma.sql/raw/Decimal` have no value path; subsumes data-model 7.5 "Decimal only in FX repo").
- **Runner activation = TASK-020 part 020-B** (second PR, no new ID; branch `feat/TASK-020-b-prisma-client-package`, after PR #20 then PR #32; locks + `prisma-core`; merged before batch 0.7 dispatch, hard stop before TASK-024 merge and TASK-025/026/040 start). `databaseRuntimeFromConfig` takes no Client; one composition for api and worker.
- **Rejected:** staleness auto-regeneration in `typegen` (nothing runs the Prisma CLI implicitly; check-only), chaining `generate` after `db:migrate` (npm appends `--create-only` to the LAST command), adding prisma/client to the root solution.
- **Costs:** 4 models cold tsc 1.9 s; synthetic 100 models 8.4 MB/213k lines: generate 5 s, cold compile 9.3 s/390 MB, up to date 0.27 s, dist 9.2 MB. Downstream type-load and SWC transform at 100 models unmeasured (R-ARCH-28 triggers).
- **Still open (not mine to close):** PR32-SEC-01 (MEDIUM) asks the architect to rule on a pre-transaction phase for handlers needing external I/O (T-83); CLAUDE.md section 2 should list `npm run db:generate` (orchestrator); STATUS D-TASK020-05 closes with 020-B.

**Process lessons:** (1) Scratch extract of a PR head: `git archive <branch> | tar -x --exclude=docs --exclude=.claude --exclude=infra`, junction every top-level main `node_modules` entry (script mknm.mjs, `@platform/*` pointing at the extract), copy main's git-ignored `prisma/generated`. Build the junctions from LONG paths: when the scratch dir was reached through the Windows 8.3 short path (`MADELI~1`), eslint-plugin-boundaries silently classified resolved files as unknown (root-path spelling mismatch) and nothing was flagged — `cd` with the long path and verify with a positive control. (2) The Bash tool here cannot parse quoted heredocs containing quotes reliably: write scripts with the Write tool. (3) Jest 30: `--selectProjects unit <paths>` swallows the paths as project names (ran everything); use `--testPathPatterns`. (4) For a "does the lint rule fire" claim, run one probe file per arm including positive controls before writing the ruling. (5) Synthetic-scale check: generate N models with a node script, `prisma generate --schema <dir>` (no config needed), `tsc -b --extendedDiagnostics`.
