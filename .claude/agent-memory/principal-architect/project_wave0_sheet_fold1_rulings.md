- **`reference_dataset_versions` has ONE writer (the seed as migrator) and `platform_app` SELECT only.** TASK-221's reconciler writes no digest row: it reads the last audited digest from `audit_entries` (latest CONFIG_CHANGE for `authz_matrix`) — this also kills the "second baseline after down.sql" problem. The reconciler is generalised to every audited dataset because the seed path is the migrator connection and the **migrator never gets a privilege on audit tables** (TASK-025's `ConfigChangeSink` stays a port; drift restores recorded in two expand columns and audited by the reconciler). If a runtime writer is ever needed: §4.5 definer function; never a table grant, never RLS on a SYSTEM table.
- **PR12-SEC-02 squat fix is three layers**: guard matches the object's OWN name for every pg_class/pg_type kind; `ensure_audit_partitions` identity test raises `AUDIT_PARTITION_NAME_TAKEN` (never a silent skip); readiness = contiguity from the catalogue (current..+2) + `audit_partition_squatted` event for any foreign object under a partition name (because `audit_partitions` rows are writable by platform_app and a count can be satisfied with one missing month). `ENABLE ALWAYS` adopted for event + audit triggers with stated limits (does not close `event_triggers=off`, `ALTER EVENT TRIGGER DISABLE`, RDS master SET ROLE path → TASK-116 tripwire + M5 pgaudit misc_set).

**Process lessons:** (1) For >10 sheet edits, write a patch file with `@@@OLD/@@@NEW/@@@END` blocks and a tiny Node applier that asserts each anchor occurs exactly once — 47 replacements in one run, no escaping headaches (write `\\d` in the patch for a literal `\d` in the .mjs string; avoid apostrophes; backticks are fine). Trailing anchors = the last ~150 chars of each block (print them first). (2) Review-extraction fan-out: four Explore subagents (one per PR group) returning verbatim finding text keeps the main context workable; large reports persist to `tool-results/*.txt` — read in pages. (3) Never `cat > file` without a heredoc in Bash (hangs on stdin). (4) Check `git status` before finishing: other agents' memory files and new review records may be modified concurrently — leave them alone and do not list them as mine. (5) Owner statements shift between review rounds and between the code and security records of the same PR — quote the latest round and record the chosen owner explicitly.
