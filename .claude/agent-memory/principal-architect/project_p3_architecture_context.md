Several ADRs carry dated "Amendment" sections (threat-model P1 items in ADR-0005/0006/0007/0014/0016/0022; D-ORCH-001 in ADR-0023/0024/0001; UX §5 items in ADR-0006/0016/0026/0025) — judge conformance against the amendments, not just the original Decision sections.

**Why the non-obvious choices:**
- Node 24 (not the host's Node 20): Node 20 went EOL 2026-04-30; `opossum` 10 needs Node ≥ 22. Host now has Node 24.22.3 via fnm but NOT on PATH: every Bash command running node/npm/npx must start with `export PATH="$APPDATA/fnm/aliases/default:$PATH";` (CLAUDE.md §2, D-ORCH-002). A missing prefix hits Node 20 and fails on engine-strict — intended.
- TypeScript ~6.0.3 (not 7.x native): ts-jest/typescript-eslint peers declared `<7` on 2026-11-12. Jest uses @swc/jest to decouple.
- Valkey 8 instead of `redis:7` image: redis 7.4/8 licences (RSALv2/SSPL/AGPL) are off the allow-list.
- RustFS instead of MinIO/LocalStack: MinIO community archived; LocalStack requires an account since 2026.03.
- Audit erasure = tokenised PII vault (not key shredding) because closed partitions go to S3 Object Lock and must hold no PII.
- Carrier portals (DHL WAF, UPS 403) block automated fetches; UPS specs are on github.com/UPS-API/api-documentation; DHL MyDHL API is at spec 3.3.x.
- **CI (D-ORCH-001, human):** private repo ≈ 2,000 free min/month vs ≈ 22,000 needed all-hosted. Result: hosted PR fast lane (single incremental job, diff-coverage gate) + heavy suites run LOCALLY by test-runner with machine-generated evidence under `docs/05-quality/{tests,security,performance}/runs/<stamp>_<sha7>/` + hosted full lane on `workflow_dispatch` only (wave ends, G3, G4). No self-hosted runner (kept as `HEAVY_RUNNER_LABELS` switch), no merge queue, `nightly.yml` has no schedule, post-merge fast lane off by default (`CI_MAIN_FAST_LANE`). "Passing CI" in the DoD = lane A green + lane B evidence PASS for changed paths + reviews. Estimate ≈ 1,830 min/month; guards at 70/90/100 %.
- WebFetch cannot reach registry.npmjs.org from this environment; use `npm view <pkg> ... --json` under the PATH prefix to verify licences/dates.

**P3 security remediation (2026-11-12, pre-G2, review `docs/05-quality/security/P3-architecture-security-review.md`):** SEC-P3-01..04 (HIGH) and 07/08/10/11/12/13/14 resolved as dated "Amendment (2026-11-12, SEC-P3-xx)" sections; decisions D-ARCH-003 rev 2 and D-ARCH-017..028; a "Remediation status" table closes the review doc. PM owns configuration defaults (D-046/D-048: `CARRIER_ANON_CALLS_PER_MIN=120`, bulkheads 6/4, reserve 40 %) — ADR values must follow DECISIONS, not the review's suggestions. Wave-0 follow-ups: `x-origin-check` on login-class routes (SEC-P3-18), Nginx strip of `X-Mock-Scenario`, SPK-08 (audit owner + anchors on PG 18), SPK-01 extended for `--ignore-scripts`.

**SPK-01 amendments (2026-11-12, P5 Wave 0, D-ARCH-035..039 + D-ARCH-003 rev 3; "Amendment (2026-11-12, SPK-01)" sections in ADR-0002/0017/0022/0023 (am. I)/0024/0025/0026):** the spike (TASK-001, PR #1) was GO with no pin changes. Non-obvious choices to defend: (a) `typecheck` = `tsc -b` *emitting* (TS 6 rejects `-b --noEmit`, TS6310) → `dist/` holds compiled tests, stripped at image assembly, not via per-workspace `tsconfig.build.json`; (b) Jest runs under `node --experimental-vm-modules` for `require(esm)` (jose/uuid/cookie/canonicalize/otplib/nock are ESM-only), CJS transform + `jest.mock` kept; (c) `@platform/source` export condition (first in `exports`), production never passes `--conditions` and resolves `dist/`; (d) Stylelint **17.16**, not 18 — no logical-CSS plugin supports 18 yet, no peer override; (e) `prom-client` is deprecated → `@prometheus-io/client` 0.16 (Prometheus org, pre-1.0, pinned exact, confined to `platform/metrics`); (f) `eslint-plugin-jsx-a11y-x` (es-tooling fork) replaces the stale upstream; (g) LHCI = repository-built tool container (`tools/isolated/lhci/Dockerfile`) because `@lhci/cli` has 9 High advisories; Stryker = isolated install `tools/isolated/stryker` (Babel 8 hoist); `size-limit` with `@size-limit/file` only; `@hookform/resolvers` 5.9.2 (7.x wants `effect ^4`, Prisma has `effect` 3); (h) runtime images `npm ci --omit=dev --omit=optional` (devOptional leakage: Prisma CLI, Studio → `elkjs` EPL-2.0, `@visx` alpha, `typescript`); `prisma` 7.10.1 hard-depends on `@prisma/studio-core`, so the migrate image prunes it with an allow-listed script; (i) D-ARCH-003 rev 3 admits EPL-2.0 in the **dev** closure only for unmodified transitives (`elkjs` via Prisma), never in images — security-analyst to confirm; (j) F-SEC-1: `@react-router/dev` auto-runs `npm install isbot` without a custom `entry.server.tsx` → entry mandatory in both apps, `isbot` not declared, lane A fails if `git status --porcelain` is non-empty after build; (k) `npx` → `npm exec --no --` everywhere (SEC-P3-31). Registry facts are verified with `npm view` + `npm audit` on lockfile-only scratch installs (`npm install --package-lock-only --ignore-scripts` in the scratchpad) — that technique works offline from the repo and is the way to check advisories for a candidate. CLAUDE.md §2 build/lint lines (npm ≥ 11.10, `tsc -b`, jsx-a11y-x, Stylelint 17) were handed to the orchestrator, not edited by me.

**PR #1 security-review rulings (2026-11-12, P5 Wave 0, review `docs/05-quality/security/PR-0001-TASK-001-security-review.md`; D-ARCH-040..044 + D-ARCH-003 rev 4; "Amendment (2026-11-12, PR1-SEC)" sections in ADR-0023 (am. J), ADR-0002, ADR-0025, ADR-0006 (am. 16), ADR-0013 (am. 6), ADR-0022 (am. 14); platform.md §2.1/§3.2/§7.1; risks.md R-ARCH-23/24):** (a) `@platform` on npmjs.com is a third-party org → `.npmrc` line `@platform:registry=https://registry.invalid/` (fails closed); names NOT renamed — we own no scope, the pin is the control. (b) `prisma generate` needs no lifecycle script but the CLI downloads `schema-engine` at run time (SPK-01 passed on a warm cache) → in-repo manifest `tools/deps/prisma-engines.json` (enginesVersion `d1b3f377…` = `@prisma/engines-version` 8.1.0-1.d1b3f377, per-target sha256, two-environment recording), `deps:rebuild` step `prisma-engines` is the only fetcher, children and all CLI calls go through `tools/deps/prisma-cli.mjs` with `PRISMA_SCHEMA_ENGINE_BINARY=<verified file>` (the env override is the one Prisma short-circuit that skips BOTH download and cache copy — verify-after alone is unsafe); origin change = ADR amendment. (c) **Lesson:** licence facts must be read from the *locked* version (`npm view pkg@locked license`) — I read `latest` (`elkjs` 0.12.1 `EPL-2.0 OR GPL-3.0-or-later`) while the locked 0.11.1 is plain `EPL-2.0`; rev 4 also turned the EPL admission into a named exception (`tools/ci/licence-exceptions.json`) and clarified deprecated transitives = gating in production closure, report-only in dev-only. (d) `bcrypt` 6.0.0 (18 months on 2026-11-11, brief-fixed) kept under a time-boxed exception in `tools/ci/maintenance-exceptions.json` (expires 2027-05-11, monthly review, 4 exit criteria), exit = `bcryptjs` in a `worker_threads` pool behind a `PasswordHasher` port with ESLint import confinement; `@node-rs/bcrypt` rejected because napi-rs binaries are `optionalDependencies` (dropped by `--omit=optional`). (e) `node-abort-controller` via BullMQ accepted — BullMQ's wrapper prefers `globalThis.AbortController`, so the polyfill is loaded-but-dead on Node 24 (read from the `npm pack` tarball); `@opentelemetry/auto-instrumentations-node` dropped from `apps/api` before TASK-007's gate. Technique: `npm pack <pkg>@<ver> --ignore-scripts` into an isolated scratch dir + `tar -xzf` is the way to read a dependency's shipped code without installing it.

**Batch-0.2 implementation rulings (2026-11-12, P5 Wave 0; `docs/03-architecture/rulings/batch-0.2-rulings.md`; D-ARCH-045..051; data-model §4.4/§4.6/§7.3/§8.1/§8.3/§8.4/§8.6/§12 A16, ADR-0005 am. 9, ADR-0002 batch-0.2 am., ADR-0026 am. 13, ADR-0018 am. 5, platform.md §4.3, SPK-01 §2.5):** all eight deviations by TASK-003 (PR #5) / TASK-004 (PR #4) / TASK-005 (PR #3) were ACCEPTED — the code was right, the docs were wrong. Non-obvious outcomes to defend: (a) **`platform_migrator` does NOT own the database** (SEC-P3-34 item 5 adopted at the first bootstrap file because bootstrap files are immutable by ledger hash); extensions are installed by the bootstrap role in `01-schemas.sql`; the shadow-DB `initShadowDb` rendering keeps `CREATE EXTENSION` (migrator owns the shadow DB). PostgreSQL checks `CREATE` on the database BEFORE the `IF NOT EXISTS` short-circuit of `CREATE SCHEMA` (schemacmds.c) but AFTER it for `CREATE EXTENSION` (extension.c) — so a generated `CREATE SCHEMA IF NOT EXISTS "public"` now fails for the migrator; linter rule 14 rejects schema/extension/database/role DDL in `prisma/migrations/**`. (b) **`ALTER DEFAULT PRIVILEGES … IN SCHEMA … REVOKE … FROM PUBLIC` is a PostgreSQL no-op** (per-schema defaults only ADD to global ones; verified in the PG 18 reference) — the global `FOR ROLE <creator> REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC` form is used for migrator/definer/audit owner, and the `TABLES` line is dropped because PUBLIC gets nothing on tables by default; C5/C11 assert `pg_default_acl` (exactly 3 rows, `defaclnamespace = 0`, objtype `f`). (c) `prisma migrate resolve --rolled-back` is only for FAILED migrations (P3012 on a successful one) — the up→down→up driver writes `_prisma_migrations.rolled_back_at` directly, test/dev only, and additionally proves `S_down = S0`. (d) Bootstrap files are `00-roles.sql`/`01-schemas.sql` (`NN-name`), never one combined file, because the restore rehearsal runs only `00-roles.sql` before `pg_restore`. (e) Linter rules 3–9, 11, 14 → TASK-016 (closes US-074, which activates the `migration-lint` required suite; claims `[SEC-TC-33]` = rules 7/8/9/12/14 and `[NT-AVAIL-003-a]` = rules 2/3/4/5/6/11); TASK-016 got lock `prisma-core` added. (f) `typecheck` = `npm run typegen && tsc -b` (React Router `+types` are generated into git-ignored `.react-router/`). (g) ADR-0018 register = 25 rows; the security review's "24 entries" is stale. Process lessons: plan-sheet edits go through `plan-data.mjs` + `node docs/04-plan/generator/gen.mjs . --write` (then validate without `--write`; expect `errors: []`); the generator forbids two tasks in one batch sharing a lock and requires deps in earlier batches; PR #5 also edits `plan-data.mjs`, so after it merges the orchestrator must regenerate once. Rulings files live in `docs/03-architecture/rulings/` (new directory created in this batch) — one file per batch, verdict per item, "required code changes per PR" table at the end.
