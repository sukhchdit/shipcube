Findings use the CLAUDE.md §11 scale with CWE and OWASP Top 10:2021 codes (threat-model.md uses 2021 codes, e.g. A10 = SSRF; keep consistent). Severity matrix from threat-model.md §1: Impact×Likelihood, C×H=CRITICAL, C×L/M or H×M/H=HIGH, H×L or M×M/H=MEDIUM, else LOW. Security-analyst never edits ADRs/requirements: findings go to principal-architect (technical) or product-manager (functional), and proposed decision text is handed to them to log in DECISIONS.md.

**Why:** Orchestrator instructions for P3 (read-only scope, no commits, no human questions); consistency with threat-model.md lets quality-gatekeeper trace IDs.

**How to apply:** Registry checks (`npm view <pkg> license version time.modified --json`) work from the Windows host when prefixed with `export PATH="$APPDATA/fnm/aliases/default:$PATH";` (D-ORCH-002) — no need to spawn dependency-auditor for spot checks before a lockfile exists. Notable licence facts found 2026-11-12: caniuse-lite is CC-BY-4.0, spdx-exceptions CC-BY-3.0 (stale), argparse 3.x is PSF-2.0, nodemailer MIT-0, tslib 0BSD, lru-cache BlueOak-1.0.0.

**dependency-auditor hits its 30-turn limit.** A 4-task dispatch on 2026-11-12 (age sweep, provenance, maintenance, gitleaks) stopped before it reported. Its scratchpad outputs (`sweep-stdout.json`, `packuments-condensed.json`, `gitleaks-out/`) were still usable.
- Give it at most 2 tasks per dispatch.
- Or run the licence, audit and maintenance checks yourself with Node scripts; this is fast.
- gitleaks works via the Docker image with `--redact`. In Git Bash, prefix it with `MSYS_NO_PATHCONV=1`, otherwise `/repo` is rewritten to `C:/Program Files/Git/repo`. For worktree commits, mount the main repo, which holds the shared object store, and use `--log-opts=<base>..<head>`.
- **gitleaks `dir` mode** (scanning a `git archive` tree) reports paths as `/scan/...`.
  - The path-anchored allowlists in `.gitleaks.toml` (`^docs/...`) therefore do not match in that mode.
  - So the 17 PR1-SEC-11 hits (`openapi.yaml`, the agent docs) always show up there. Triage them as allow-listed; lane A's git mode reports repo-relative paths.
  - Lane A scans `base.sha..head.sha` with `--diff-merges=first-parent`. Any text on main that a branch has not yet merged arrives as *added lines* in that branch's next main-merge.
  - Therefore never quote a flagged value in docs, records or memory (PR13-SEC-11).
- Semgrep is not installed on the host.
- **Probing lint configs without running the suite.** A single-process `ESLint#lintText` against the worktree's real `eslint.config.mjs` stays light enough for the memory-constrained host. Load ESLint from the worktree with `createRequire(<worktree>/package.json)`, and add the `tseslint.configs.disableTypeChecked` + `projectService: false` overrides, because the probe files are not on disk. `isPathIgnored` / `calculateConfigForFile` show coverage holes. Write the probe file with a heredoc, not a `node -e` string, because quoting breaks in Git Bash.
- **Probe scripts with regex escapes.** A Bash-tool heredoc (even `<<'EOF'`) turned `\\b` into `\b` in one case (PR-0005, 2026-11-12). The probe then silently matched nothing. Write such probes with the Write tool, and include a positive control line in every probe. **But the Write tool decodes ` `-style escapes into raw characters** (PR-0020, 2026-11-13: a raw U+2028 inside a regex literal gave a SyntaxError; `sed` repair with `\\u` failed too, GNU `\u` = uppercase). For control and line-separator characters, build them with `String.fromCharCode` and test by code point, never with escapes in the source.
- **Lock-only fix-cycle deltas.** A generic deep JSON diff of the base and head `package-lock.json` (every differing path, with a positive control) proves "only X changed" faster and more strictly than the tuple diff. Used for PR-0002 R2, 2026-11-12.
- **Merge-only rounds: "the lockfile delta is unchanged" (PR-0004 R3).** Compare the leaf-level `delta(old base → old head)` with `delta(new main parent → new head)` as (path, before, after) sets. Use `delta(old base → main)` as the positive control. Script: `scratchpad/review/PR-4-sec-r3/scripts/lockdelta-eq.mjs` (session-scoped). Then a clean `git merge-tree` equal to the merge tree, plus the three-way tree compare, settles every other path.
- **Pre-lint head code in lane A's fast-lane:**
  - `deps:rebuild` → `prisma generate` loads the unowned `prisma.config.ts`;
  - since PR #4, `npm run lint`/`typecheck` start with `typegen`, which runs workspace scripts, `vite.config.ts`, `react-router.config.ts` and `routes.ts` (PR4-SEC-13).

  The fast-lane gates can therefore be tampered with by unowned files. When a PR adds a new pre-gate execution point, check it against this class.
- **Boundaries head-vs-main probe (PR-0019).**
  - `git archive <sha> eslint.config.mjs tools/eslint-rules tools/lint` into `cfg-head` / `cfg-main`, and junction each `node_modules` to the MAIN checkout's.
  - Write a scratch mini-repo, then run `new ESLint({cwd, overrideConfigFile, overrideConfig:[disableTypeChecked, projectService:false, no-unresolved off, {settings:{'boundaries/root-path': root}}]})`.
  - File descriptors accumulate categories, so a new category never removes an old one.
  - **Gotchas (PR-0020 R2, 2026-11-13):**
    - The mini-repo needs a root `package.json`, otherwise `import-x/no-relative-packages` crashes with "path … null".
    - Turn `import-x/no-cycle` off (it crashes the same way).
    - To test the *resolved-file* arm, junction `root/node_modules/@platform/<pkg>` → `root/packages/<pkg>`, and build every junction target from the **long** path (`/c/Users/<long user dir>/AppData/...`), never the 8.3 short form (`<FIRST6>~1`). An 8.3 short-path target puts the resolved file outside `boundaries/root-path`, and the arm silently misses. That produced a false "`?worker` bypass" until re-run.
    - A junctioned root dir has the same problem. Copy the root instead.
    - `unrs-resolver` strips `?query` suffixes, so the resolved arm catches `x?worker`/`x?raw`.
- **Probing a git-object-reading verifier (PR-0023).** Build scenario commits with plumbing in a scratch repo and never check them out:
  - a temporary `GIT_INDEX_FILE`, `read-tree <parent>`, `update-index -z --index-info` (mode `0` deletes), `write-tree`, `commit-tree`;
  - `-c core.protectNTFS=false` lets the Windows host commit LF/CR/colon path names;
  - the work tree stays at the base, so `git status` stays clean.
  Run the PR's script from outside the repo with `--manifest`, which simulates the base copy. Copy `node_modules` packages instead of using junctions when the probe swaps them. Script: `scratchpad/review/PR-23-sec/scripts/probe.mjs` (session-scoped).
- **Probing a PR head without touching its worktree** (PR-0005 R2):
  - `git show <sha>:<file>` the `.ts` sources into scratch.
  - Rewrite the `./x.js` imports to `./x.ts`, and bare `pg`-style imports to file URLs into the main checkout's `node_modules/<pkg>/esm/index.mjs`.
  - Run them with plain `node` (Node 24 strips types).
  - For URL guards, diff the guard's result against `new pg.Client({connectionString})`'s `host`/`port`/`database`, which needs no connection.
- **Type-stripping PR sources (PR-0008).**
  - Use `stripTypeScriptTypes(code, { mode: 'transform' })`. The default strip mode rejects constructor parameter properties (`constructor(readonly x: string)`), which the authz package uses.
  - In probe scripts, build file URLs with `pathToFileURL`. Hand-built `replaceAll('\\', '/')` broke again in a Bash heredoc.
- **Probing Prisma runtime behaviour without a database (PR-0011).**
  - Strip the PR's sources and the worktree's `prisma/generated/prisma` into scratch.
  - Build `new PrismaClient({ adapter: fakeFactory })`. `fakeFactory` is `{provider:'postgres', adapterName, connect()}`, and the adapter returns `{queryRaw, executeRaw, executeScript, startTransaction, dispose}`. The transaction has `options:{usePhantomQuery:false}` and savepoint methods.
  - Log each SQL with a `ROOT`/`TXn` tag. Result sets are `{columnNames, columnTypes (7 = Text), rows}`.
  - Throw `new DriverAdapterError({kind:'postgres', originalCode, originalMessage, …})` from `@prisma/driver-adapter-utils` to drive P2010/P2039.
  - This proves transaction-binding and escapes cheaply.
  - The scratch `node_modules` junction vanished once mid-session, so re-check it before re-running.
- **Probing a Prisma extension or any model-level code against a schema that does not exist yet (PR-0026).** `prisma generate --schema=<abs path>` from a scratch cwd works offline with no DB (Prisma 7 `prisma-client` generator emits `.ts`; import `client.ts` directly with Node 24 via a scratch `node_modules` junction). Write a tenant-like schema (org/shipment/parcel, standard columns, `org_id`, `on_behalf_of_org_id`, relations) and drive the PR's real sources over the recording fake adapter. Answer SELECT/RETURNING with one plausible row when Prisma needs follow-up statements (`connect` pre-checks). Details in [[project-p5-pr26-standard-columns]].
- **Probing a capability guard (Proxy / wrapper).** Also probe what the allowed members RETURN, and use that value after the guard is revoked. In PR-0011 R2, a "deep, deny-by-default" `TenantDb` still returned Prisma's raw `PrismaPromise`, and its `requestTransaction(null)` reached the root pool. For a lint or run-time check on a tagged template, also probe the interpolated values (`Sql` objects splice raw text). **Also probe check-versus-use of the ARGUMENT (TASK-075):** a guard that validates `ctx` and then forwards the caller's object is split by a getter, a Proxy, or a mutation after the callee's first `await`; record what the callee sees before and after an `await`. Fix: snapshot into a frozen copy and pass the copy. **And probe whether the error CLASS encodes the side-effect stage (TASK-075 r2):** when a downstream classifier keys on class ("contract error = local, non-ambiguous"), throw that class from inside the callee after the external call; if it leaves the wrapper unchanged, the classifier cannot be right.
- **Validating a record when the PR branch is not merged with main.** Use `checkSecurityOwnedPaths` with base `origin/main` and the PR head. Older head rows in the same record only produce notes, and the run still passes on the newest head (PR-0011 R2).
- **"No commands in worktree X" includes read-only git.** On 2026-11-13 (PR-0009 R2) I slipped and ran `git status` there; disclose any such slip in the record.
  - Check the worktree's state from the main checkout instead (`git worktree list`, `git show <sha>:<path>`).
  - Junctions into its `node_modules` are fine.
- **ReDoS-probe every regex that a fix adds over request input.** The PR-0009 HIGH (PR9-SEC-14) came from a charset fix.
  - Measure in a child-process server; same-process timings hide event-loop blocking.
  - Fuzz the proposed grammar for language equivalence.
- **Hand-scan loops: probe the "closer at the end" family** (PR-0020 R3, PR20-SEC-18). A regex-driven loop can scan a value by hand (`valueEnd`) and then `continue` without setting `lastIndex = end`. Feed it N units whose scanned value closes only at the very end of the string (`"pin",\'` × N, then `\':`). Every unit then re-scans to the end: O(N²).
  - Linear regexes do not prove a linear pass.
  - Absolute-threshold tests (< 50 ms at 8 KiB) miss it. Assert a scaling ratio instead (time(8k)/time(1k) < 16), and measure uncapped functions at 8k/32k/128k by appending `export { internalFn }` to a stripped copy of the module.
- **Redaction walkers: also probe `{ name|key, value }` records** (HAR header arrays, parsed cookie records, SDK `{Name, Value}`). These are distinct from `[name, value]` tuples, and keyed classification misses them. Also probe the logger's *event/message* argument, which may be escaped but not redacted.
- **Never let a Bash redirect depend on a `cd`.** A failed `cd` in one call left an empty `> file` in the main checkout root (PR-0020 R3; removed). Always write outputs to absolute scratch paths.
- **Git attribute experiments: confirm them in a Linux container, not with host git** (PR-0010 R2, 2026-11-13). With an empty work tree, Git for Windows 2.52's `git log -p` still treated `package-lock.json` as binary. The attribute source is unexplained, and `-c attr.tree=<empty tree>` cleared it. Treat host results as hints only.
- **Probing PR code that imports `@platform/*` workspace packages (PR-0011 R3).**
  - The main checkout's `node_modules/@platform/*` resolve to main's TS sources (exports `default` → `dist`).
  - Use a `module.registerHooks` resolve hook (`probes/hooks.mjs`) mapping `@platform/<pkg>` → `<build>/packages/<pkg>/src/index.js`.
  - In Git Bash, pass `--import ./hooks.mjs` from the probes dir, or a `file:///$(cygpath -m …)` URL; a `/c/...` path fails with `ERR_UNSUPPORTED_ESM_URL_SCHEME`.
  - Remove scratch junctions with `cmd //c "rmdir <dir>\\node_modules"`, never `rm -rf`, which would follow the junction.
  - **Full-app variant (PR-0021 R2).** This runs the real `createApp` with no build:
    - `git archive <sha> apps/api/src packages/*/src` into scratch;
    - a `registerHooks` resolve hook mapping `@platform/<pkg>` → `src/index.ts`, and relative `./x.js` → `./x.ts` when only the `.ts` exists;
    - a load hook with `stripTypeScriptTypes(src, {mode:'transform'})`;
    - a `node_modules` junction to the main checkout.
    Script: `scratchpad/review/PR-21-sec-r2/probes/hooks.mjs`.
- **Duplicate dispatch (PR-0061, D-ORCH-COORD-01).** Two orchestrator sessions on one tree dispatched the same r1 twice. Before writing, `git fetch` and check the PR branch and the latest main DECISIONS for an existing record of the same round. If one exists, keep its finding IDs, and deliver it verbatim plus an appended round section (its own Head row, new IDs only, and a final Verdict row). Never deliver a competing whole file.
- **Overlapping reviews.** The code reviewer often probes the same lint or walker items in parallel. Read their record on main (`docs/05-quality/reviews/`) and the latest D-ORCH rulings before finalising, so owners and fix forms align. main moves during a review, so re-fetch before writing "state of main".
- **Raw-socket HTTP probes (PR-0004 R2).** Send the request with `socket.write`, never `socket.end`. On a half-close (FIN), Node's http server drops responses that are written asynchronously, such as piped file streams; only synchronous 4xx responses come back, so every 200 reads as "no response". Use `Connection: close` and wait for `close`.
- **Signature and advisory spot checks without an installed tree.** `npm audit signatures` needs `node_modules`. Instead, verify each tuple's `dist.signatures` (ECDSA over `name@version:integrity`) against `-/npm/v1/keys` with `node:crypto`, add a tampered-integrity control, and POST to `-/npm/v1/security/advisories/bulk` with a known-vulnerable version as a positive control. Script: `scratchpad/review/PR-4-sec-r2/scripts/sigcheck.mjs` (session-scoped).
- **Gitleaks without Docker (PR-0021).** Emulate the default ruleset in Node.
  - Download `config/gitleaks.toml` for the pinned tag. Parse it with a minimal TOML reader: `[[rules]]`, `[[rules.allowlists]]`, `[allowlist]`, `'''` literals, arrays.
  - Convert RE2 to JS: strip `(?i)` into the `i` flag (over-approximates the mid-pattern ones), map `[:alnum:]`-style classes, `\z` → `$`. All 221 v8.30.1 rules compiled.
  - Apply the keyword prefilter, `secretGroup` (else the first non-empty group), entropy `<=` threshold, the generic-rule digit check, and the global and rule allowlists including lower-cased stopwords.
  - Run it per line, with runtime-generated positive controls.
  - Script: `scratchpad/review/PR-21-sec/scripts/gl-emul.mjs` (session-scoped). Treat the results as hints; devops confirms with the real image.
  - Also run it over your own record before hand-off.
- **Effective-config diff for an `eslint.config.mjs` block (PR-0027).**
  - Run `ESLint#calculateConfigForFile` over ~50 representative plus near-miss paths on two `git archive` extracts (head and base), scrub the root path, and diff every leaf. Add a mutation control (a widened glob and a rule turned off) to prove the probe can see them.
  - The extract needs `tools/eslint-rules`, `tools/lint` and the workspace `package.json` files, because the config reads the disk.
  - `tseslint.configs.disableTypeChecked` is one object, not an array.
  - Scripts: `scratchpad/review/PR-27-sec/effcfg.mjs`, `lintprobe.mjs`, `lintts.mjs`.
- **The scratchpad is shared and can be wiped mid-run (2026-11-13).** Earlier `review/PR-NN-*` folders usually persist (`record-sim.sh` variants, Gitleaks emulators), but during PR-0026 round 2 the whole `scratchpad/review/*` (including my active extract, junction dirs and probes) vanished between two tool calls, with other agents creating dirs alongside. So: look first, but never rely on it; write each probe in a single go, keep results in the record as you go, and rebuild from `git archive` when needed. Junction clean-up is safe: `fs.rmdirSync(link)` removes only the link (main's `node_modules` stayed at 740 entries); never `rm -rf` a tree that may hold junctions without unlinking them first (lstat walk, `rmdirSync` each symlink, then `rmSync`). A `gl-emul` that prints the matched line shows a runtime positive control in tool output: print counts and rule ids only.
- **Scratch jest/tsc on a `git archive` extract (PR-0026 r2).** Extract the whole tree minus `docs`/`.claude`/`infra`/`tests` (add an empty `tests/` dir: jest `roots` demand it). Build `<tree>/node_modules` as a real directory of junctions to every top-level entry of main's `node_modules`, but `@platform/*` pointing at the extract's `packages/*`, `apps/*`, `prisma` (so the PR's sources win; script `mknm.mjs`). `prisma generate` (no env needed) into `prisma/generated` makes the real-client unit tests run. Then `node --experimental-vm-modules --disable-warning=ExperimentalWarning node_modules/jest/bin/jest.js --selectProjects unit --runInBand <paths>` and `node node_modules/typescript/bin/tsc -b apps/api tools` (31 s; clean = no output). Mutants by `sed`/`node` on the extract, restore from the pristine `git archive` copy. This stands in for lane A's typecheck and unit when the lane-B evidence step aborts the job, but never for lint or build.
- **Gitleaks emulation, minimal form.** `curl` the pinned tag's `config/gitleaks.toml` (222 rules), minimal TOML reader, keyword prefilter, `secretGroup`, entropy, stopwords, global regex allowlist; runtime-generated positive controls (github PAT, AWS id, generic key) must fire; 0 hits over the appended record lines.
- **Pinned-image checks need no Docker.** Anonymous GETs to `auth.docker.io` and `registry-1.docker.io` give the manifest, config blob (user, created, entrypoint) and a body-hash check. Compare per-platform manifest digests with the moved tag, because only the attestations may differ. Script: `PR-27-sec/k6digest.mjs`.
- **Lockfile delta script.** Reusable at `scratchpad/review/PR-2-sec/scripts/lockdiff.mjs`, but scratch is session-scoped, so re-create it if it is gone. It reports new and removed tuples, integrity changes, flag moves, hosts, install scripts and licences.

- **Host quirks for scratch probes (PR-0028).**
  - With `MSYS_NO_PATHCONV=1`, Windows `git -C` and `node` need mixed paths (`cygpath -m`); `/c/...` fails ("cannot change to"). `cmd //c` then starts an interactive shell, so make a junction with `fs.symlinkSync(target, link, 'junction')` and remove it with `fs.rmdirSync(link)`.
  - A `git archive` extract of `tools/quality` (base and head) plus a shared clone with a `node_modules` junction runs the verifier's real CLI (`--root <clone> --base --head --json`). Scenario commits come from plumbing (`scratchpad/review/PR-28-sec/probes/scenarios.mjs`: `mk(parent, {path: content|null|{mode,content}})`), and a patched scratch copy of `lib/manifest.mjs` tests a candidate pattern. The record simulation is `probes/record-sim.sh`.
  - **Record Head rows:** the checker binds SHAs from ANY table row whose first cell starts with `Head` (word boundary), in any table. Keep exactly one such row, and never a first cell starting with `Verdict` before the final one. `Head-code …` and `Head bootstrap …` also count. I wrote both into a residuals table in PR-0046 R2, and one of them carried a short SHA; a sim row-count check (`/^\|\s*Head\b/`) caught it. Always count those rows in the candidate before appending.
  - **Sim helper gotcha (PR-0046 R2):** a `git()` wrapper that `.trim()`s stdout turns `blob + '\n'` back into the original content, so a "union-like edit" scenario silently passes. Append `'\n\n'` or a marker line instead. Sims with about 18 plumbing scenarios exceed the 120 s Bash limit, so run them with `run_in_background`.
  - **GitHub run `pull_requests` is best-effort:** it is empty for fork PRs and can list a PR other than the triggering one. Never treat it as proof of which PR or base a run belonged to.
  - `os.tmpdir()` on this host is the 8.3 form (`<FIRST6>~1`), so `homedir()`-based scrubbing misses it; never quote that fragment in a record.

- **SDK/library option claims need a behaviour probe (PR-0030).** A "10 s request timeout" set via an option literal was warn-only in `@smithy/node-http-handler` 4.14.2 (`throwOnRequestTimeout`); no test observed it. Probe with a loopback TCP server that accepts and stays silent, no caller signal, 50 s watchdog, and a scratch copy with the fix to measure the corrected bound.
- **Targeted RustFS/Docker probe recipe (PR-0030).** Acquire the `docker.lock` directory by `mkdir` (retry loop), `docker run -d -p 127.0.0.1::9000` with the image by digest and random per-run credentials passed through the environment (never printed), poll `/health`, run the probe with `PROBE_ENDPOINT/AK/SK`, `trap` removes the container and the lock. Scripts: `scratchpad/review/PR-30-sec/probe/p20-run.sh`, `p20-rustfs.mjs` (method/tamper/Host/path/checksum/concurrency matrix), `p21-host.mjs` (raw-socket Host shapes). Use raw `node:http` with the signed path string (no URL normalisation) and `socket.write` for request lines.
- **Windows junction from Git Bash.** `cmd //c mklink //J "<long target path>" '<source path>' < /dev/null` with path conversion ON (do NOT export `MSYS_NO_PATHCONV` in that call: `//c` then stays literal and cmd opens an interactive console). Remove with `cmd //c rmdir "<long path>"`. `node` needs `cygpath -m` paths.
- **A hung store without a custom server (PR-0030 R2).** `docker pause <container>` on a published-port container (Docker Desktop) gives a store that accepts TCP and never answers; unpause afterwards and confirm a new client works. Also: a probe's own `ExperimentalWarning` (`stripTypeScriptTypes`) lands in a `console.error` spy: filter it before concluding "the adapter logged something". For a composition probe, a second `registerHooks` resolve hook can stub heavy siblings (`../db/runtime.js`, `../valkey/client.js`) with counter modules to prove ordering ("storage refused before any pool/client"). Scripts: `scratchpad/review/PR-30-sec-r2/probe/` (`hooks.mjs`, `hooks2.mjs`, `p7-silent.mjs` .. `p13-rustfs.mjs`, `p13-run.sh`, `record-sim.mjs`), session-scoped.
- **A long record section via Bash heredoc failed** with `unexpected EOF while looking for matching '` (PR-0030 R2) even with a quoted delimiter: write the section with the Write tool into scratch, then `cat scratch >> record`, and validate with the simulator before appending.
- **Record-sim wrinkle:** when an earlier round's record is already on main, the "no record" control is really "round-1 record only" (its message names the old head); label controls accordingly.
- **Type-stripped adapter probes.** `stripTypeScriptTypes(code, {mode:'transform'})` to `.mjs` (rewrite `./x.js` imports), `node_modules` junction to the main checkout, real SDK clients with a stub `requestHandler` returning `HttpResponse` from `@smithy/core/protocols`. Script: `PR-30-sec/probe/p1-adapter.mjs`.

- **Probing a PR's tools from `git archive` extracts (PR-0031).** Junctions to `node_modules` vanished mid-run again (same cause as the shared-scratchpad wipe above); copy the needed dependency closure (`ajv`: `require-from-string`, `json-schema-traverse`, `fast-uri`, `fast-deep-equal`) as real directories instead. Kit that worked: plumbing scenario commits (`probes/scen.mjs`), head and base-ref copies of `check-evidence.mjs` side by side (the base copy is the positive control for "can the probe see staleness"), `--manifest` variants for manifest rules, `record-sim.mjs` (20+ negative controls) with main's `tools/ci` copy.
- **`git diff` hides submodule changes** when a worktree `.gitmodules` says `ignore = all` (or `diff.ignoreSubmodules=all`), for `--raw` and `--name-only` alike, unless `--ignore-submodules=none` is passed (PR31-SEC-01). Check any verifier that reads paths or modes from `git diff`; plumbing `ls-tree` cannot be filtered.
- **Count-only host-fragment scan with a positive control (PR-0031).** Compute the needles at run time (OS user name, its 8.3 stem plus `~`, home, tmpdir, host name, git e-mail), scan `git show` blobs of the run directory, print counts per label, and validate the scanner on an older run known to carry the fragment. A tree-wide `git grep -F -l` per needle at head and main gives file counts. Bash-tool gotcha: an unbalanced parenthesis inside an `echo "..."` label broke the whole command with an `eval` syntax error.

- **Bash-tool heredocs can drop a backslash (PR-0027 R2).** A quoted-delimiter heredoc turned a regex lookbehind with an escaped backslash into an unterminated group; write scripts that contain backslash regexes with the Write tool (a NEW file name if the failed heredoc already created one), or build the character with String.fromCharCode(92).
- **Remove scratch junctions before rm -rf (PR-0027 R2).** `cmd //c rmdir "$(cygpath -w <path>/node_modules)"` for each junction, then rm -rf the scratch dir; confirm the main checkout node_modules entry count is unchanged.

- **Cite line numbers only from a single-file read (PR-0032).** `cat -n a.ts b.ts` numbers continuously across files, so a line number read from a multi-file dump is offset; re-check with `grep -n` on the one file before writing it into a record.

  - **Protecting the rule is not enough; check which rules hold its inputs (TASK-080 r2, PR080-SEC-06).** An import-confinement rule that skips non-static specifiers or `import x = require('…')` is only as strong as the rule that forces the static ESM form. Here that was `static-module-specifier` and `no-require-imports`, both unprotected.
    - TS 6 under `nodenext`/ESM ACCEPTS `import x = require()` and emits a `createRequire` load. Prove such acceptance with `ts.createProgram` before rating.
    - Probe each residual form with an inline disable of the holding rule, under the whole config and through the suppression checker.
- **Scope-shadow probes (typescript-eslint scope manager versus TypeScript).** Each of these binds a watched global for the scope manager, while TypeScript resolves the value to the global and the emitted code calls the real one:
  - `import type { X as Date }`;
  - a type-only `namespace Date {}`;
  - `declare const { Date }: …`.

  Interfaces, type aliases and type parameters do NOT capture value references. Prove TypeScript's acceptance and the emitted JS with `ts.createProgram` under the package's parsed tsconfig. The robust fix refuses any binding of the watched name.
- **Catalog literals beyond the brief's list (TASK-080).** C9 (`c01-c12.int.test.ts`, `ENUM_CHECKS`) selects every `public` CHECK whose definition deparses to `= ANY (`, that is, any IN list with 2 or more values (a 1-value list deparses to `=`). A new enum-like CHECK needs an entry, or lane B goes red. **PGlite** (`@electric-sql/pglite` 0.4.3 in main's `node_modules`, PostgreSQL 17.5) runs migrations with `CREATE ROLE` and `SET ROLE`. It needs a `public.uuidv7()` stub, its process exits with code 99 or 100 harmlessly, and it dumps the whole query text on an error, so redirect its output to a file.

- **Request-value kinds versus column types (TASK-045).** For any new generic parameter kind (filters, search keys), probe values the Joi schema accepts but PostgreSQL refuses: U+0000 in strings (22021), integers outside `int4` (22003), year 0000 and negative years (22008/22007; adapter-pg formats years without a sign). Every unmapped SQLSTATE is a 500 `DB_ERROR`. End-to-end kit: the PR's module through main's generated client, `PrismaPg` and the PGlite socket server (fresh client per case, retry once on P1017). See [[project-p5-task045]].

- **New dependencies: also query REPOSITORY advisories (TASK-042).** npm audit, the npm bulk feed, OSV and the global GitHub database all said 0 for i18next 27.1.1, yet `GET https://api.github.com/repos/<owner>/<repo>/security-advisories` (anonymous) listed a published High for `< 27.1.3`, not yet reviewed into the global DB. Read the upstream CHANGELOG between the pinned and the newest release for "security" lines too. Such an advisory turns lane A red for every PR once GitHub reviews it.

- **Catalog gates that join identifiers into text and split them later (TASK-051 r2, PR051-SEC-06).** A query that returns `child=parent,…` text, and code that later splits it on `=`/`,`, fails open on quoted identifiers that contain the separator. Probe with a quoted `"a=x"` column plus a constraint on a real column `a`, and add a behaviour row: the gate must report the key, and the database must refuse the row. Recommend structured arrays (`jsonb_agg(jsonb_build_array(…))`).
- **Classify against behaviour, not only against the planted list (TASK-051 r2).** For every shape, record both what the rule reports and whether the database actually leaks: X versus Y answers for another owner's value. Then check that no passed shape leaks, and run the previous rule on the same rows as the positive control. A wrapped DDL that fails (for example a unique index over the seed rows) aborts the transaction, so put it in a savepoint.
- **Titles-only commits after a Prettier re-wrap.** Remove the tags, all white space and the `,` before `)`, then compare the old and new text. Two controls: the same compare without removing the tags must differ, and so must a one-token body mutant. The TypeScript scanner is no use here: it loses sync on template literals.
- **`git show ref:path` in Git Bash without `MSYS_NO_PATHCONV=1`** fails ("ambiguous argument 'origin\main;…'"), and a redirect still leaves an EMPTY file. The gitleaks emulator then silently ran with an empty repo config. Always check the output size, or `cmp` it against a known copy.

- **Read-then-spend gates with an in-flight hold (TASK-041B).** Probe the client that ABORTS after admission, not only the parallel burst. A release on `res 'close'` frees the unit while the slot still runs, because Express keeps running a request whose client has gone. Kit: raw sockets with `socket.resetAndDestroy()` a few ms after sending, staggered sends, a slot delay of 20 or 200 ms; count authenticator entries against `limit`. Also probe a hold by unfinished bodies. body-parser 2.4.0 reads off the whole request before it passes a 400 or 413 on, so a declared oversize `Content-Length` with no bytes also holds the request until Node's `requestTimeout` (300 s by default).
  - **When a fix makes "release only by the outcome" (TASK-041B r2), probe a slot that never reports one.** A slot that writes the answer itself (`res.status(401).json()` and no `next`) or swallows an error keeps its unit for good. The close no longer frees it. Also probe the window between admission and the slot with a `gzip` JSON body (body-parser inflates asynchronously): a reset 10 ms after sending a ~1 KB body that inflates to 900 kB reaches it reliably, while a body-less GET reaches the slot in the same tick. Prove "no leak" with `FinalizationRegistry` on each `res` (`server.on('request')`), `--expose-gc` and `server.getConnections`.
- **Timer-based store bounds and event-loop stalls.** After a synchronous stall the timers phase runs before the poll phase. A 250 ms `setTimeout` race therefore fires even when the reply is already waiting, and opens a breaker. Probe: a loopback server that answers at once, then a busy loop of 300 ms right after the call.
- **Stacked branches and squash merges (TASK-041B).** The repository squash-merges PRs. Merging main into a branch stacked on a squashed predecessor therefore conflicts: add/add for every file the predecessor created and the stacked part changed. The record checker passes resolutions that silently drop a change; only `git diff --raw <main> <merge>` equal to `git diff --raw <pred head> <head>` (old AND new blob) catches them. Simulate the squash with `commit-tree $(merge-tree --write-tree main pred) -p main`. Probe a full app with no junctions: a resolve hook that maps `@platform/<pkg>` through the extract's `@platform/source` export and resolves bare packages with `parentURL` = the main checkout's `apps/api/package.json`.
