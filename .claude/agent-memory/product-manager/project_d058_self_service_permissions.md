D-058 (2026-11-12, P5 Wave 0, PR #8 head efe23df): product-manager ruled on TASK-013's least-privilege defaults (D-T013-05). Requirement side became REQUIREMENTS 1.5 / PRD 1.5; NFR.md and traceability.md untouched (no ID or count changes; 434/91/293/134 baselines hold).

**Ruling:** `session:manage`, `notification_pref:manage`, `notification:read` form a catalogue-flagged `selfService` set held by **all 17 seeded roles** (they guard only `user`-tenancy `/me/*` routes, so "manage" is own rows only). REQ-RBAC-004 / DR-A07 / US-066 invariants carve the set out of "Viewer no manage" and "Compliance Auditor read+audit only" and assert it positively. Grant changes TASK-013 must apply: CUSTOMER_VIEWER + session:manage + notification_pref:manage; CUSTOMER_FINANCE + notification_pref:manage + order:read; CUSTOMER_ADMIN + privacy:delete (the REQ-ACCT "Admin all except privacy:delete" line was withdrawn as inconsistent with Shipper holding it); OPERATOR_COMPLIANCE_AUDITOR + session:manage + notification_pref:manage. Confirmed: Viewer no payment:read / document:download / document:email / privacy:export / privacy:delete; Shipper no org:update / org:member:invite / org:member:manage / payment_method:manage / payment:read; Super Admin = every *role-assignable* permission (signature-only webhooks held by no role, D-T013-02 accepted on the REQ side); partner roles org:* + self-service only.

**Why:** Permissions resolve from the *active* membership (REQ-RBAC-008), so a role without the set strips its holder of the Must session list/remote sign-out (REQ-AUTH-021/022, ASVS 3.3.4) and the admin "My sessions" page whenever that membership is active. Renaming to `:self` qualifiers was rejected as churn with no behavioural gain. `payment:read` for Viewer is telemetry-gated (A-104: >1 denial per 100 Viewer sessions re-opens it as a Should).

**How to apply:** Pairs that move together from now on: self-service set → REQ-RBAC-004 + REQ-RBAC-014 note + REQ-ACCT scope note + DR-A07 + US-066 notes/AC + A-103 + ADR-0008 §3 (architect's side). Any future "role X lacks permission Y" question from a developer: first check whether the route tenancy is `user` (then it is self-service and every role gets it) before applying least privilege. Open follow-ups handed to others: architect to mirror the carve-out in ADR-0008 §3 and confirm `privacy:export` scopes shipments/quotes to the active org (personal-org switch could otherwise bypass the Viewer exclusion); security-analyst to re-check Viewer/Compliance Auditor rows in the PR #8 review. The generated matrix lives at `docs/03-architecture/generated/role-permission-matrix.md` on the PR branch (not `rbac-matrix.md` as ADR-0008 says).
